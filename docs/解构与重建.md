# 解构与重建

状态：设计草案（2026-10-27）。不是决策记录，也没有改代码。与现行
[`事件状态与读取.md`](事件状态与读取.md) 冲突的地方，本文是候选方向；哪些采纳、哪些否掉，
另记 [`决策记录.md`](决策记录.md)。文献依据见 [`研究/原子化与重建-调研.md`](研究/原子化与重建-调研.md)。

---

## 0 一句话

原文保存不动；把它切成可计算的段/原子，抽出最小关系（出处、覆盖）和特征（段矩阵）；
回忆时按当前线索做条件组装，组装由结构完成，主模型只负责把结果说成人话。

---

## 1 从“结构-激活”到“解构-重构”

现行路径：

```
事件图（本体） → 线索激活 → 竞争选一件 → 编写模型写成回忆
```

它解决了“记得住、想得起来”，但留下四个硬问题：

1. **一次只能重建一件事。** 跨事件的“上回说到一半”“去年今日”在结构上做不出来。
2. **改口被压平。** “以时间较晚者为准”只留最新值；旧说法在 note 层被覆盖，回忆看不到它。
3. **编写模型是第二个作者。** 它同时做选择、排序和措辞；既不可审计，也是一次有损生成。
4. **图是本体。** 图一丢就像记忆丢了；但图其实只是这一版的理解，不是记忆本身。

新路径：

```
原文（trace） → 切段/原子 + 最小关系 → 特征矩阵
                                      ↓
线索 → 条件组装（激活/扩散/筛选/填槽） → 记忆对象 → 主模型润色
```

关键不是“把原文打碎”，而是**把 schema 打碎，trace 不动**。

---

## 2 本体论：trace / schema / recollection

三层，不能互相还原：

| 层 | 是什么 | 可变性 | 权威 |
|---|---|---|---|
| trace（痕迹） | 原文、note、可引用的 span | 不可变 | “当时确实这么说过” |
| schema（图式） | 段、原子、特征、关系、解释 | 可弃、可重建、多版本 | “这一版怎么理解” |
| recollection（回忆） | 此刻组装出来的一段记忆 | 一次性的行为 | “现在对她说什么” |

三条原则：

- **trace 不可变**：原文不重写；note 只增版本，不覆盖。
- **schema 可弃**：段/原子/图都可以从 trace 重建；丢了不算事故。
- **recollection 可问责**：每个事实性分句都要能指回 trace；说不清出处的，不许说。

由此，事件图从“记忆本体”降为“schema 的视图/缓存”；事件是段矩阵里的**软簇**，
不是硬边界。遗忘也不再是“剪连接”，而是**当前 schema 里没有通向那段 trace 的路径**——
原文还在，只是这一版的理解够不到它。

这也回答“原文到底值什么价格”：

- 原文不是“一手资料”（说话者当时已经在选择、编码、掩饰），也不是“确定事实”
  （它包含错误、误解和当时的自欺）；
- 它是**事件的痕迹**：权威不在“内容为真”，而在“当时确实这么说过”；
- 所以记忆要保的不是 truth，而是 **fidelity to the saying**。

## 3 原文的价格

“原文信息熵很低”这句话，要分两种熵：

- **语义密度**低：口语、重复、口水话；
- **残差熵**高：措辞、停顿、时机、那句本可以不这么说的话。

原子提高语义密度，丢掉残差；而“她”恰恰长在残差里。所以原文的价格不是一种：

| 价格 | 说明 |
|---|---|
| 存储价 | 几乎为零 |
| 检索价 | 很高；原文是糟糕的索引 |
| 保真价 | 零；它就是基准 |
| 解释价 | 很高；原文不告诉你什么重要 |
| **期权价** | 最高；未来在全新语境下重读它的可能性 |
| **他者价** | 唯一能反驳她的东西；没有它，记忆变成自我确认 |

原子化只降低了检索价，却可能把期权价和他者价一起卖掉。所以“原文信息熵低”不是丢弃的理由；
它是“需要更好的解码器”的理由。

一句话：**原文不是记忆，但它是记忆的抵押品。**

## 4 拆解：结构抽取 + 非均匀切分

讨论里提出的三步：

- A. 从原文中提取一些结构；
- B. 原子化处理，这一步不一定均匀；
- C. 用提取的结构重新生长出记忆。

本文把它落成：

### 4.1 结构抽取

不是通用信息抽取，而是**记忆 schema**：

- `claim`：主张 / 事实 / 决定；
- `stance`：立场 / 偏好 / 情绪，带时间；
- `thread`：未完成的事；
- `scene`：场景 / 气氛，不拆；
- `revision`：改口——一个原子覆盖另一个。

抽的是“是什么 + 变过什么”，不只是“是什么”。**改口是结构，不是噪声。**

### 4.2 非均匀

粒度由**转折密度**和**语义类型**决定：

| 内容 | 粒度 | 理由 |
|---|---|---|
| 事实、决定、承诺 | 细（claim 级） | 要比较、要版本 |
| 立场、偏好、情绪 | 中（stance 级） | 两个都真，按时间并存 |
| 场景、气氛、一次争吵 | 粗（scene / 段级） | 意义在整体 |
| 反讽、含糊、“你懂的” | 不拆 | 拆了就错 |
| 前后矛盾 | 不裁决 | 存成 revision 对 |

“不裁决”很重要：写入时不解决冲突，只记录“这是后来那句”；什么时候把旧说法说出来，
由回忆时的线索决定。

### 4.3 最小结构

段/原子只留这些字段：

```json
{
  "id": "s-...",
  "text": "预算改成二十四万",
  "type": "claim",          // claim | stance | thread | scene | fact
  "segment": "seg-...",     // 所属段；段是默认单位
  "ts": "2026-04-03",
  "source": "e-.../span",   // 指回原文
  "supersedes": "s-..."     // 可选；改口
}
```

持久关系只有三样：

- `source`：纵向，指回原文；
- `supersedes`：时序，改口；
- embedding 近邻：横向，联想；可现算，不必存。

**改口 = 一个原子指向被它覆盖的原子。** 但覆盖不能删旧原子：删了就再也说不出
“你以前不是这么说的”。旧原子保留，链头是当前状态，链身是历史。

事件不需要离散 `event_key`。事件是段矩阵里的软簇，不是硬边界；两件事共享一段，就共享。

### 4.4 专用模型

通用抽取有现成的：GLiNER（零样本片段）、NuExtract（schema 驱动 JSON）、
OpenIE / REBEL（关系）、事件抽取（EE）。但**没有现成的**
“claim / stance / thread / scene + supersedes”中文亲密对话抽取器。

建议顺序：

1. 定 schema，人工/强模型标 200–500 条银标；
2. 规则 + 嵌入做 baseline；
3. 差得多，再蒸馏到 1.5B–3B 的单任务 seq2seq（约束 JSON 解码），或做 span + 分类头。

先训模型容易掩盖 schema 的问题；schema 没定好，训出来也是错的。

## 5 特征：f(text) → 矩阵，不是单向量

一个关键批评：`event_key + centroid` 还是索引，不是特征；新表述要能算出相近的特征值；
复合回忆需求要把每个关键词提成向量，整段排成矩阵。

同意。特征应该是：

```
f(text) = [emb(unit_1), emb(unit_2), ..., emb(unit_n)] + 每行的元数据
```

- 记忆侧：`M` 的行是段（默认）或原子（需要时更细）；
- 线索侧：`Q` 的行是关键词 / 短语 / 小句；
- 两边同一个 `f`，不需要离散事件标签。

匹配是矩阵对矩阵：

```
score(Q, M) = mean_{q∈Q} max_{m∈M} [ cos(q, m) × gate(q, m) ]
             − λ × uncovered(Q, M)
```

- `max`：每个线索词找最像的段；
- `mean`：所有线索都要有落点，不能只命中一个；
- `gate`：时间 / 类型 / 角色（“后来”偏新，“以前”偏旧）；
- `uncovered`：没着落的线索要罚——缺一块就不该假装全记得。

这类做法在检索里叫 late interaction / multi-vector：不是把整段压成一个向量，
而是保留多行，用逐行对齐来匹配。

为什么这比 centroid 强：单向量把“预算”和“吵架”平均掉；矩阵保留每一行，
paraphrase 的鲁棒性来自多行对齐，而不是句子结构相同。

原子化不是必需，而是**段不够用时的细化**：一段多事、改口要指到子句、需要跨段比较时，
再切细。默认单位是段。

## 6 组装：结构自己组装，模型只润色

前提：组装完可以润色，但组装本身不靠模型。

流程：

1. **特征匹配**：cue 矩阵 vs 段矩阵，取前几个候选；
2. **激活**：按行匹配分数点亮段/原子；沿 embedding 近邻扩散一跳；沿 `supersedes` 补版本链；
3. **比较筛选**：分数 + 类型/slot 匹配 + 时间去重；同一 slot 只留链头 + 必要历史；
   保证每个槽位至少一个；
4. **填槽**：`现在 / 变更 / 未完成 / 场景 / 人`；
5. **输出对象**（不是散文）：

```
[现在] 预算 24 万（2026-04-03，s-12）
[变更] 28 万（s-03）→ 24 万（s-12）
[未完成] 等装修公司报价（s-07）
[场景] 咖啡馆，纸巾上写数字（s-09）
```

6. **主模型润色**：只决定怎么说，不决定记忆里有什么。

分工的理由：选择/排序是组合问题，结构比模型更可靠、更便宜、更可审计；
措辞是语言问题，主模型更擅长。编写模型这个“第二作者”可以整条去掉。

## 7 改口

改口是这条路径的试金石，也是关系事件，不只是数据更新。

| 类型 | 例子 | 记忆该做什么 |
|---|---|---|
| 事实更正 | “周三” → “记错了，周四” | 更新当前值，保留旧值与更正时间 |
| 偏好变化 | “我不喜欢惊喜” → “上次那个其实挺好” | 两个都真，按时间并存 |
| 决定反转 | “我要辞职” → “先不辞了” | 记录决定链与理由，当前状态取最新 |
| 态度变化 | “当时很气” → “现在不气了” | 情绪属于时间点，不更新 |
| 否认 / 假前提 | “我没说过” | 用 trace 核对，不顺着编 |
| 策略性改口 | 说对方想听的 | 不建模，或标“不确定” |

现行实现的三处硬伤：

1. `remember` 覆盖旧 note（`notes[0]["text"] = note`），旧说法只剩一个 `edited` 时间戳；
2. `write-memory.txt` 的“以时间较晚者为准”把更正、变化、否认压成同一个动作；
3. `recollect` 一次只取一个 event，跨事件的改口连不起来。

目标行为：不只回答“预算是二十四万”，而是“你三月说二十八万，四月改成二十四万——
是那时候家里出了什么事吗？”前者是数据库，后者才是记忆。

`supersedes` 链的用法：

- 线索问“现在 / 后来” → 取链头；
- 线索问“以前 / 一开始” → 取链身；
- 线索问“怎么变的” → 整条链 + 时间 + 理由（理由只有 trace 里有才写）。

## 8 扩散模型的启发：从“去噪”到“条件采样”

讨论里提出：原子汤像噪声，回忆是从噪声中重建需要的记忆。

这个类比方向对，但要拆成两步：

- **字面**：不要训一个扩散模型。文本/结构扩散还重，而且先验会编造。
- **概念**：回忆是**条件采样**，不是 argmax 检索。

```
z = 一次组装（选哪些段/原子、怎么排）
o = 当前线索 + 当下语境
p(z | o) ∝ p(o | z) · p(z)
```

- `p(z)`：这段组装像不像一段记忆（连贯、有事件、不打架）；
- `p(o | z)`：和线索、和 trace 对不对得上；
- 采样而非 argmax：每次回忆可以略有不同，这才叫重建。

三个可直接用的推论：

1. **温度 = 清晰度 / 年龄。** 老记忆、没复述过的记忆从更高的噪声起步，重建更模糊；
   “我记得不太清”在计算上有对应物，不是话术。
2. **多次采样 = 不确定性。** 同一线索采 2–3 个版本；事实层要低方差，语气层允许高方差。
3. **guidance = 保真与在场的旋钮。** 强 trace guidance → 事实清楚、语气克制；
   强 context guidance → 更贴当下、更活。事实层调高 trace，语气层调高 context。

工程上先做**离散退火**，不做扩散网络：

```
z0 = 段矩阵的 gist（粗）
repeat T 次，温度下降：
  候选 = 加一个段 / 删一个段 / 换顺序 / 展开一条 supersedes
  按能量 E(z) 接受/拒绝
return z_T（或 top-k 样本）
```

能量先用启发式：

```
E = -线索覆盖
    + 冗余
    + 不连贯（时间 / 人物 / 类型打架）
    + 缺槽（该有变更 / 未完成却没有）
    + 版本冲突（同时用了互相覆盖的两段，却没标链）
    + 无出处（不在 trace 里的内容，直接无穷大）
```

这是“去噪”的工程版：没有高斯噪声，只有结构丢失；没有生成模型，只有约束优化。
跑通后再考虑学 score model。

风险：先验编造（必须只允许选/排，不允许造）、计算成本、收敛判据、
“噪声”隐喻误导（原子不是 i.i.d.，出处和覆盖是结构，不是噪声）。

## 9 和现有 palimpsest 的接口

保留：

- trace（原文 / entries）、persona、主模型、单写者、SQLite、嵌入器；
- 上下文时间线（sink + 四档 + 两块）不变；
- “材料只读、原文不删”的原则不变。

改变：

| 现在 | 候选 |
|---|---|
| 事件图是本体 | 事件图降为视图 / 缓存；段矩阵是检索面 |
| `recollect` 单事件 + 编写模型 | `assemble` 多段 + 结构填槽；主模型润色 |
| `remember` 覆盖 note | 新版本不覆盖；`supersedes` 指针 |
| “以时间较晚者为准” | 当前状态取最新；变化要能被说出来 |
| 遗忘 = 剪边 | 遗忘 = 当前 schema 没有路径；温度随年龄升高 |

迁移：从现有 graph / notes 派生段与关系，非破坏性；事件名保留为标签；
旧图可随时重建。**不删 trace，不重写 note。**

## 10 风险与未决

风险：

- **编造**：先验 + 退火最容易补“合理但没发生”的细节；trace 硬约束 + 负样本测试。
- **特征塌缩**：段矩阵对话题相同、情绪不同的事件可能不够敏感；加 stance / 时间列，
  或保留段原文。
- **切段质量**：段切错，后面全错；需要人工抽检。
- **改口识别**：`supersedes` 什么时候建、什么时候只标冲突，未定。
- **成本**：矩阵匹配 O(m·n)，退火多次采样；段数少时可接受，规模大要近似。
- **评估**：事实保真、索引保真、关系保真、编造率、人读“像她”；不能只看 LoCoMo。
- **身份**：图降级后，连续性靠 trace + persona + 回忆史；这需要单独论证。

未定问题：

1. 最小单位是段还是原子？默认段，什么时候必须原子？
2. 哪些记忆不许打碎？
3. 温度 / 清晰度怎么定？年龄、复述、重要性各占多少？
4. 能量函数是手写还是学？先手写。
5. 抽取器：规则、蒸馏、还是专用模型？
6. 多采样给主模型几个版本？怎么合并？

## 附：术语

- **trace**：原文 / note，不可变。
- **schema**：段 / 原子 / 关系 / 特征，可弃。
- **recollection**：此刻组装出来的记忆。
- **段（segment）**：默认单位，一句 / 一个小句。
- **原子（atom）**：段不够用时的细化，带类型 / 时间 / 出处 / 覆盖。
- **signature**：段矩阵的聚合（centroid + 时间 + 参与者），用于粗筛。
- **supersedes**：改口指针，B 覆盖 A。
- **gate**：时间 / 类型 / 角色兼容性。
- **coverage**：线索每一行都要有落点。
- **temperature**：清晰度；越高越模糊。
- **energy**：组装好坏的启发式分数。
