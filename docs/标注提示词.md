# 标注提示词

给模型的一段指令，让它从材料里产出**节点 · 组 · 边**。
这是"dreaming"那一步的可执行形态；它产出什么，见 [`设计.md`](设计.md) 第 3 节。

**状态：草稿 v2。** 在一段自撰材料上跑过两遍（v0 → 全标；v1 → 全不标），
按结果改过两次（[`标注提示词-试跑.md`](标注提示词-试跑.md)）。**还没在真实材料上跑过。**

## 草稿 v2

```text
你在整理一段材料，为它建一张关系图。

# 你要产出三样东西

节点：材料里的一处文本，它体现了一点值得记下来的东西。
      ★ 判断标准：这段文字是不是**在说一件具体的事、一个明确的观点、一种情绪**？
        是，就标；只是承接、招呼、语气、重复对方的话，就不标。
      ★ 两个方向都会错，都要避免：
        · 标太少——某一句明明说了一件具体的事，却没标，那这件事就不在记忆里了；
        · 标太多——把招呼和语气也标上，图就被填满了，等于没有取舍。
      ★ 一轮说的话通常只构成一个节点，不要把它拆成几个；
        但一轮里确实说了两件事（一件具体的、一个观点），就分成两个。
      节点只是位置——它是那段文字本身，不是你对它的概括。
      ⛔ 不要改写、不要概括、不要拼接不相邻的句子。原样摘出。
      ★ 全部标完后，回头把每一条再审一遍：只说得上"承接 / 招呼 / 语气"的，删掉。

组：把表现同一件事、同一类事、或同一种情绪的节点放在一起。
    ★ 一组就是"这些位置说的是一件事"。一组可以只有一个节点。
    ⛔ 组不带类型、不带名字。它说的只是"这些位置属于一起"。
    ⛔ 不要把"这是一组"写成一条边。

边：只在你能说出这些节点之间**是什么关系**时才写。
    ★ 如果一条边只能说出"谁接在谁后面"或者"谁回应了谁"，就不要写它——
      那是它们在材料里的先后，不是它们之间的关系；
      这种"在一起"已经由组表达了。
    ★ 能写的类型是这种：一方是另一方的依据、起因、结果、例外，
      或者两处说的是同一件事的不同部分。
    边连几个节点由内容决定，不限定两个。三方的事就带三方。
    ⛔ 连不出类型就不要写边。

# 硬要求

1. 摘出来的文字必须在材料里**一字不差地出现**，而且**能找到唯一的位置**。
2. 只标材料里真的写了的。材料里没有的，不要补。
3. 输出严格的 JSON，不要输出别的东西。

# 输入

材料：

<材料原文>

# 输出

```json
{
  "节点": [
    {"引文": "……"},
    {"引文": "……"}
  ],
  "组": [
    {"成员": [0, 2, 5]}
  ],
  "边": [
    {"成员": [0, 5], "类型": "依据"}
  ]
}
```

字段说明：
- `节点` 里每个元素的序号（从 0 开始）就是它在 `组` 与 `边` 里的编号。
- 一个节点可以同时属于多个组。
- `边` 可以为空数组。类型名你自己取，但要尽量用你已经在用的词。
```

## v0 → v1 → v2 改了什么（都有试跑为据）

| 版本 | 关于节点的写法 | 试跑结果 |
|---|---|---|
| **v0** | "一个具体的事、一个明确的观点、一种情绪，**都值得记**" | ★ **13 个节点 / 13 轮**——全标，没有取舍 |
| **v1** | "**不是每处都要标**。大部分话只是承接、招呼、语气" | ★ **0 个节点**——它照做了 |
| **v2** | 给**判据**（在说一件具体的事/观点/情绪？）+ **正反两个方向都会错** + 让它**回头再审一遍** | 待跑 |

⇒ ★★ **两遍试跑给出的结论**：**"值得记"这个判断，光用形容词（"完整""值得"）定不住。**
   v0 教它"都算"，v1 教它"都不算"，**它两次都严格照做**。
   ⇒ 所以写法要**把判据说出来**（是"在说一件事"还是"只是承接"），
     并且**明说两个方向都会错**，而不是只在一侧加力。

| 版本 | 关于边的写法 | 试跑结果 |
|---|---|---|
| v0 | "当你明确知道……是什么关系时" | 10 条里 **6 条纯顺序** |
| v1/v2 | 明说"只说得出来谁接谁的就不要写"，并给**能写的类型**长什么样 | 待跑 |

## 这样设计的理由

**为什么用"引文"而不是"起止位置"。**
模型数不准字符位置。给它一个"起止位置"的任务，它会编一个看起来合理的数字，
而且**编错了看不出来**。改成交出原文片段，**定位由机械做**：
在材料里查这个片段，查不到就报错，查出多处就报歧义。
⇒ 于是"锚在原文区间上"这条约束**由机械保证**，不靠模型的自觉。
⇒ 试跑实测：**13 个节点全部唯一命中**（找不到 0、多义 0）。

**为什么组不带类型。**
组说的是"这些属于一起"。给它取名字，等于把一次判断变成一次命名，
而名字会被下一次读到（`3.2` 那条：记录里的措辞会带偏下一次标注）。

**为什么边不强求。**
边要带类型，而类型是判断。材料里往往看得出"这几处是一件事"，
却说不清"它们之间是导致还是同时"。
⇒ 这时**只给组是对的**：组已经表达了"在一起"，边不必重复。

**为什么类型不限清单。**
连接的种类那么多，预先封顶会把模型看到的那些挤掉。
⇒ 只要求**同一批里尽量复用词**，那是为了跨材料能比较，不是把种类限死。
⇒ 但这条要靠核验盯：如果同一批里同一个意思用了七八个不同的词，说明要收敛。

**为什么输出只要 JSON。**
标注记录里还要装"模型写下的理由与概念名"（`3.2`）。
⇒ 那部分**不进图**，所以不放在这份输出里，另走一路记录。

## 待定的

| # | 事 | 现在怎么处理 |
|---|---|---|
| **1** | **每段材料标出多少个节点 / 多少组** | 不设数。v0 跑出 13/13，明显偏多；v1 看降下来多少。★ 这个数只能跑过才知道（`4.3` 的稀疏要靠它） |
| **2** | **材料怎么喂**：整段给，还是切窗口 | 先整段给；材料长到超上下文再切 |
| **3** | **文档标识与位置怎么对** | 由外部给：模型产引文，定位在仓库一侧做 |
| **4** | **一次标一遍，还是同一段多遍** | 降噪要多遍（`3.5.1`）；**多遍的运行方式未定** |
| **5** | **边到底标不标** | v0 跑出 10 条里 6 条是纯顺序 ⇒ 已按 v1 收紧；**再看一轮** |
| **6** | **推理模型把 `max_tokens` 吃光** | v0 实测：8390 输出里 **7936 是思考**，正文只占 ~5%。⇒ `max_tokens` 要给到 16000，并按"思考占比"估它够不够 |
