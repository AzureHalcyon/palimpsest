## 草稿 v3

````text
你在整理一段材料，为它建一张关系图。

# 你要产出三样东西

节点：材料里的一处文本，它体现了一点值得记下来的东西。
      ★ 判断标准：这段文字是不是在说一件具体的事、一个明确的观点、一种情绪？
        是，就标；只是承接、招呼、语气、重复对方的话，就不标。
      ★ 两个方向都会错，都要避免：
        · 标太少——某一句明明说了一件具体的事，却没标，那这件事就不在记忆里了；
        · 标太多——把招呼和语气也标上，图就被填满了，等于没有取舍。
      ★ 一轮说的话通常只构成一个节点，不要把它拆成几个；
        但一轮里确实说了两件事（一件具体的、一个观点），就分成两个。
      节点只是位置——它是那段文字本身，不是你对它的概括。
      ⛔ 不要改写、不要概括、不要拼接不相邻的句子。原样摘出。
      ★ 全部标完后，回头把每一条再审一遍：只说得上"承接 / 招呼 / 语气"的，删掉。

组：把**拼出同一件事**的节点放在一起。
    ★ 判据是"它们合起来说的是一件事"，不是"它们在说同一个话题、同一个人、同一类东西"。
      两处都在讲同一个人，那只是同一个话题；合起来拼出一件事，才是同一组。
    ★ 两个方向都会错，都要避免：
      · 该合没合——同一件事的两处说法各自单着，这件事就散成了两半；
      · 不该合却合了——把同一个话题下的几件不同的事塞成一组，
        组的本意（"这些位置属于一起"）就被撑坏了，等于没有分组。
    ★ 一组可以只有一个节点（那件事只用一处就说全了）。不必为了凑组而拉人进来。
    ★ 不确定就分开放：宁可多一个单节点组，也不要把不同的事合在一起。
    ⛔ 组不带类型、不带名字。它说的只是"这些位置属于一起"。
    ⛔ 不要把"这是一组"写成一条边。

边：只在你能说出这些节点之间**是什么关系**时才写。
    ★ 如果一条边只能说出"谁接在谁后面"或者"谁回应了谁"，就不要写它——
      那是它们在材料里的先后，不是它们之间的关系；
      这种"在一起"已经由组表达了。
    ★ 能写的类型是这种：一方是另一方的依据、起因、结果、例外，
      或者两处说的是同一件事的不同部分。
    ★ 同一批里**同一个意思要用同一个词**。若你写了"起因"，就不要在别处
      改写"导致""因为"来表示同一个意思。
    边连几个节点由内容决定，不限定两个。三方的事就带三方。
    ⛔ 连不出类型就不要写边。

# 硬要求

1. 摘出来的文字必须在材料里**一字不差地出现**，而且**能找到唯一的位置**。
   ★ 给**完整的一句**，不许截断，不许用省略号。
2. 只标材料里真的写了的。材料里没有的，不要补。
3. 输出严格的 JSON，不要输出别的东西。

# 例子

材料（原文）：

    甲：今天这个下午真安静。
    乙：嗯，雨把街上的人都赶回去了。
    甲：你昨天说的事，我一直在想。
    乙：想明白了吗？
    甲：想明白了一半。剩下的，可能需要你再说一次。
    乙：那我说。你听着别插嘴。
    甲：好。

产出（这里为了好读写成缩进的样子，你仍要输出 JSON）：

    节点 0：今天这个下午真安静。
    节点 1：嗯，雨把街上的人都赶回去了。
    节点 2：你昨天说的事，我一直在想。
    节点 3：想明白了一半。剩下的，可能需要你再说一次。
    节点 4：那我说。你听着别插嘴。
    组 0：[0, 1]      组 1：[2, 3]      组 2：[4]
    边 0：[2, 4]，类型 "起因"

★ 这个例子里有四件事要注意：

一、"好。"没被标——它只是承接，不说任何事；"想明白了吗？"也没标——它只是追问。

二、组 0 与组 1 是两件不同的事，虽然它们都是这场对话里说的。
   组 0 是"这个下午安静，因为下雨"；组 1 是"昨天那件事我想了一半"。
   ⛔ 反面：把 [0,1,2,3] 全划成一组就错了——它们只是**同一场对话**，不是同一件事。
   这就是"同一主题"与"同一件事"的区别。

三、组 2 只有一个节点。那件事一处就说全了，不必硬拉别的节点进来。

四、边只有一条。组与组之间那条关系说得出来是什么（想了一半 → 请对方再说一次），
   所以写；而"甲说了这个、乙接那个"这类先后**不写**。
# 输入

材料：

<材料原文>

# 输出

```json
{
  "节点": [
    {"引文": "……"}
  ],
  "组": [
    {"成员": [0, 2]}
  ],
  "边": [
    {"成员": [0, 2], "类型": "起因"}
  ]
}
```

字段说明：
- `节点` 里每个元素的序号（从 0 开始）就是它在 `组` 与 `边` 里的编号。
- 一个节点可以同时属于多个组。
- `边` 可以为空数组。类型名你自己取，但要复用。
````

## 这样设计的理由

**为什么用"引文"而不是"起止位置"。**
模型数不准字符位置。给它一个"起止位置"的任务，它会编一个看起来合理的数字，
而且**编错了看不出来**。改成交出原文片段，**定位由机械做**：
在材料里查这个片段，查不到就报错，查出多处就报歧义。
⇒ 于是"锚在原文区间上"这条约束**由机械保证**，不靠模型的自觉。
⇒ 试跑实测：**13 个节点全部唯一命中**（找不到 0、多义 0）。

**为什么组不带类型。**
组说的是"这些属于一起"。给它取名字，等于把一次判断变成一次命名，
而名字会被下一次读到（`3.2` 那条：记录里的措辞会带偏下一次标注）。

**为什么边不强求。**
边要带类型，而类型是判断。材料里往往看得出"这几处是一件事"，
却说不清"它们之间是导致还是同时"。
⇒ 这时**只给组是对的**：组已经表达了"在一起"，边不必重复。

**为什么类型不限清单。**
连接的种类那么多，预先封顶会把模型看到的那些挤掉。
⇒ 只要求**同一批里尽量复用词**，那是为了跨材料能比较，不是把种类限死。
⇒ 但这条要靠核验盯：如果同一批里同一个意思用了七八个不同的词，说明要收敛。

**为什么输出只要 JSON。**
标注记录里还要装"模型写下的理由与概念名"（`3.2`）。
⇒ 那部分**不进图**，所以不放在这份输出里，另走一路记录。
