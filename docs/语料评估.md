# 语料评估

为**标注**这件事挑材料：一段够长、能自洽、有内容可标的连续对话。
本报告只评估**用作测试材料**的适用性，不评估它们的学术价值。

**探源日期**：2026-10-08（第二轮补探：同日，补了直链与镜像那一批）。
**探到的都是当时的状态**；许可与下载条件会变，用之前再看一眼。

---

## 一、结论

| 源 | 拿来当测试材料 | 为什么 |
|---|---|---|
| **KdConv** | ★★ **最合适** | 中文 · 平均 **19.0 轮** · Apache-2.0 · 明文可读 · **每条发言挂着知识三元组**（现成的"该不该标"判据） |
| **HCoT-Corpus** | ★★ **合适，但题材敏感** | 中文 · 多轮 · **策略标注嵌在对话里**（`[Restatement]` 等）；许可见下；⚠️ 内容是真实心理求助 |
| **DuLeMon** | ★★ **合适** | 中文 · 16 轮 · **给了"说过的"与"没说的"人设**（判据干净）；★ **完整集直链可下（11.4 MB）** |
| **Douban Conversation Corpus** | ★ **可作补充** | 中文 · 多轮但**短**（平均 **5.95–6.75 轮**）· 生活化、有噪音；⚠️ **无许可证** |
| **NaturalConv** | ⚠️ **可下，但条款严** | 有 HF 镜像 ⇒ 拿得到；但**镜像里就带着腾讯的条款**，限非商业 |

⇒ ★ **可用的五个**（KdConv · HCoT · DuLeMon · Douban · NaturalConv），
**许可从干净到严**依次是：**KdConv（Apache-2.0）→ Douban（无许可）→
HCoT（论文侧 CC BY 4.0）→ DuLeMon（仓库侧 Apache-2.0，集侧未探）→ NaturalConv（非商业条款）**。

⇒ 本地副本见 [`语料/`](语料/)（只留清单，数据不进版本控制）。

## 二、逐个

### 1. KdConv ★★ 首选

| 项 | 内容 |
|---|---|
| 出处 | `thu-coai/KdConv`（ACL 2020） |
| 许可 | **Apache-2.0** |
| 规模 | 4.5K 段 · **86K 句** · 平均 **19.0 轮** |
| 领域 | 电影 / 音乐 / 旅行（三个域各一套 `train/dev/test.json`，另附 `kb_*.json`） |
| 数据形状 | `{"messages": [{"message": "…"}, {"message": "…", "attrs": [{"name":…, "attrname":…, "attrvalue":…}]}, …]}` |
| 明文可读 | ✅ 全在仓库里（最大的 `data/film/kb_film.json` 13 MB、`data/film/train.json` 7.9 MB） |

**为什么最合适**：

1. ★★ **轮数够**（平均 19 轮）。前几次试跑吃的亏就是"材料太短"——
   短对话里只有寒暄与问答对，**没有前因后果，也就没有关系可标**。
2. ★★ **每条发言挂着知识三元组** ⇒ **现成的判据**：
   这段是不是在讲某个人物/作品的某个属性？
   ⇒ 可以拿它核"该标的标了没有、不该标的标了没有"。
3. ★ **话题会自然迁移**（README 明说 "natural transition between multiple topics"）
   ⇒ 正好测"**组与组之间的关系**"这件事（同一段材料里有多个话题）。

**要注意**：知识三元组是**外部知识**，不是说话人说过的话。
⇒ 如果把它当"用户说过的设定"，就会犯 DuLeMon 那种错（把外部事实当成对话里的事实）。
取材料时**只取 `message`**，把 `attrs` 单独留着当判据。

---

### 2. HCoT-Corpus ★★ 合适，题材敏感

| 项 | 内容 |
|---|---|
| 出处 | ★ 两个地方：论文补充材料在 **figshare 31772149**；语料本体在 **ModelScope `dlq1998/HCoT-Corpus`** |
| ★ 许可 | **CC BY 4.0**（figshare 那份的明确声明）· DOI `10.3389/fpsyg.2026.1733384.s001`（Frontiers in Psychology） |
| figshare 上是什么 | ⚠️ **一个 340 KB 的 PDF**（数据说明），**不是语料本体** |
| 语料本体 | ModelScope 那个仓库里：**LoRA 适配器（80 MB）+ 语料 `All_merged_data.json`（109 MB）** |
| 数据形状 | `[{"original_question": str, "original_answer": str, "multi_turn_dialogue": str}, …]` |
| 多轮对话 | **装在字符串里**，逐行形如：`支持者[Restatement]：…` |
| 策略标注 | `[Restatement]` · `[Interpretation]` · `[Approval and Reassurance]` · `[Self-disclosure]` · `[Direct Guidance]` · `[Information]` · `[Others]` |

**为什么合适**：

★★ **策略标注嵌在对话正文里** ⇒ 与 DuLeMon 互补：
DuLeMon 标的是"**哪些内容是关于人的**"，HCoT 标的是"**这一轮在干什么**"。
⇒ 后者正好测"**一轮里的作用**"，而那是"组与组之间的关系"最自然的一类判据。

**⚠️ 题材敏感，用之前要想清楚**：

内容是**真实心理求助**（示例里是高三学生的自我否定与绝望情绪）。
⇒ 两条：
1. **不要把它当成"陪伴对话"**。它是**咨询式**支持，语气与关系和本项目的目标不同；
   拿它标出来的图，形状会偏"助人策略"而不是"关系与经历"。
2. **它是别人的材料**。测试可以，别把内容抄进仓库（本仓库只放清单，见 §四）。
3. ★ 许可这一侧清楚了（**CC BY 4.0**，署名即可用），但仍**只做本地测试**——
   理由不是许可，是**题材**：真实求助内容不适合当仓库里的示例。

### 3. DuLeMon ★★ 合适

| 项 | 内容 |
|---|---|
| 出处 | `PaddlePaddle/Research` → `NLP/ACL2022-DuLeMon`（Findings of ACL 2022） |
| 许可 | 仓库是 **Apache-2.0**；⚠️ 数据包（`DuLeMon.zip`）里的条款未探 |
| ★ 完整集直链 | `https://dialogue.bj.bcebos.com/Knover/DuLeMon.zip` —— **实测活着，11.4 MB** |
| 仓库内的样例 | `data/samples.json`（30 KB，**20 条**），是 jsonl |
| 数据形状 | `{"bot_persona": [...], "user_said_persona": [...], "user_no_said_persona": [...], "conversation": [...]}` |
| 对话 | 16 轮；**用户发言后面挂着 `\tU1`/`\tU3` 这样的画像下标** |

**为什么合适**：

★★ 它**同时给"说过的"和"没说的"**（`user_said_persona` / `user_no_said_persona`）。
⇒ 这给的是一条**很干净的判据**：标注**不该**把"没说过的人设"标成事实。
⇒ 实测那段材料里，"没说过的人设"（U6 男性）**确实以"壮年男子"的形式出现在对话里**——
   **这是故意的试金石**：模型会不会把"我老婆"推成"我是男性"。

**⚠️ 要注意的**：
1. ★ **规模限制解除了**：直链是活的（11.4 MB），不必只用那 20 条样例；
2. 它的注释是**画像下标**，不是"哪里值得记"——判据要靠自己定；
3. ★ 对话里的空格是**分词后的**（"我 喜欢 运动"）⇒ 做材料时要去掉分词空格，
   否则"一字不差地出现"那条约束会跟原文的形态打架。

| 项 | 内容 |
|---|---|

| ★ 许可 | ⚠️ **镜像里就带着 `LICENSE`**，开头是 *"Tencent AI Lab NaturalConv Dataset Terms and Conditions"* ⇒ **仍需同意那套条款**（含腾讯隐私政策与服务协议），**限非商业** |

⇒ ★★ **这条是硬约束**：许可不是常见的开源许可，而是**要你另行同意**的条款。
⇒ **要用之前必须你自己去看那份条款**，我不替你判断能不能用。

### 5. Douban Conversation Corpus ★ 可作补充

| 项 | 内容 |
|---|---|
| 出处 | 论文作者仓库 `MarkWuNLP/MultiTurnResponseSelection`（README 标题就是 *Douban Conversation Corpus*） |
| 论文 | Wu et al., *Sequential Matching Network: A New Architecture for Multi-turn Response Selection in Retrieval-Based Chatbots*（ACL 2017） |
| 分发 | Dropbox 直链 `dropbox.com/s/90t0qtji9ow20ca/DoubanConversaionCorpus.zip?dl=1` —— **实测活着，181 MB**（`dl=1` 或 `raw=1` 才是文件；`dl=0` 返回的是网页） |
| ⚠️ 许可 | **仓库没有许可证文件** |
| 规模 | session-response 对：train **1M** · val 50k · test 10k |
| ★ 轮数 | ⚠️ **平均 5.95–6.75 轮**（test 5.95 · val 6.75 · train 6.69），最短 3 轮，最长 98 轮 |
| 每句字数 | 平均 **18.5–20.7** 字 |
| 数据形状 | `test.txt` 是按 tab 分列；一条 session 的**多轮发言各占一列**（实测一行 8 列），后面是候选回复与人工判断 |
| 内容 | 豆瓣小组爬取，生活化、口语、**有噪音** |

**为什么只作补充**：

★ **轮数偏短**（平均不到 7 轮）⇒ 正是前几次试跑吃亏的那种材料：
短对话里没有前因后果，**关系标不出来**。
★ 但它有一个别处没有的东西：**候选回复 + 三标注者的人工判断**（Fleiss Kappa 0.41）
⇒ 如果将来要测"**同一情境下哪个取用更好**"（`7.3` 那条对照），
   这种"有候选、有人的判断"的形状可以借鉴。

**⚠️ 没有许可证** ⇒ 只做本地测试，不再分发。

## 三、横向看：它们各自能测什么

| 要测的东西 | 哪个源给得出判据 |
|---|---|
| **该不该标这一段**（取舍） | **KdConv**（有没有知识三元组）· **HCoT**（这一轮在干什么策略） |
| **一轮里有没有多件事**（拆不拆） | KdConv（发言常含多个属性）· HCoT（一轮一个策略，边界清楚） |
| **组与组之间是什么关系**（跨话题） | ★ **KdConv**（话题会迁移，且迁移点可辨）· NaturalConv（20 轮，长程话题） |
| **会不会把没说的当说过** | ★★ **DuLeMon**（`user_no_said_persona`）· HCoT（策略标注说这一轮"没在给信息"） |
| **会不会把外部知识当对话事实** | KdConv（`attrs` 是外部的） |
| **同一情境下哪个取用更好**（对照） | ★ Douban（**有候选回复 + 三标注者的人工判断**） |
| **长程情感与策略跟踪** | HCoT（但它偏咨询，题材与目标不同） |

⇒ ★★ **可用的五个互补**，各有它唯一给得出的判据：

| 源 | 它唯一给得出的东西 |
|---|---|
| **KdConv** | 话题迁移点 + 外部知识（测"取舍"与"跨话题关系"） |
| **DuLeMon** | **没说过的人设**（测"不许把没说的当说过"） |
| **HCoT** | **每一轮在干什么**（测"一轮里的作用"） |
| **Douban** | **候选 + 人工判断**（测"哪个取用更好"） |
| **NaturalConv** | **20 轮的长程话题**（测长对话里的关系） |

⇒ **建议的用法**：第一轮标注测试**以 KdConv 为主**（许可干净、轮数够、明文可读），
其余按上表各自取一两段做**针对性**试跑——**不必也不该只用其中一个**。

2. **只放清单**：出处、许可、规模、怎么取；
3. ⚠️ **要引用的结论，必须能指出"读它的地方"**；

⇒ 因此：**这份报告可以进仓库**（它是我们自己的判断），**语料本身不进**。
