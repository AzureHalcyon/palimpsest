# 事件状态与读取

本文件说明当前记忆层（`memory_v2`）的设计。项目目标是构建具有连续人格与记忆的 AI 个体；
本层负责其中的事件形成、巩固、遗忘与回忆，人格的专门机制尚未实现。

代码位于 [`../memory_v2/`](../memory_v2/README.md)，运行方式见
[`../memory_v2/README.md`](../memory_v2/README.md)，参数见 [`参数.md`](参数.md)。
v1 已归档，见 [`99_归档/v1/`](99_归档/v1/) 与 [`../archive/v1/README.md`](../archive/v1/README.md)。

## 1. 基本单位

记忆的基本单位是事件。事件是围绕同一件事的一段经历：旧入口里是一段对话，`loop/` 里是一串
`note`，都不按轮或消息长度划分。
事件边界由对话过程中的判断确定：旧入口通过 `event` 工具声明，`loop/` 由 `remember`
落到某件事上。

每轮先判断这一轮值不值得记，再判断它是不是新的一件事：

- 没有值得记的内容（寒暄、开场、纯确认/收尾、没有判断的闲扯、只做笔记/索引/格式维护）→ `skip`，不建节点；
- 能被某个已有节点的名字原样盖住（同一问题下的补充、例子、反驳、确认、换说法）→ 挂已有；
- 盖不住 → `new`，起一个新名字；名字重复视为同一件事，按已有节点标；
- 还看不出是什么事（刚起头、要靠上一轮才成立）→ `hold` 先挂起，最多 6 轮，满了必须先落；落盘时这几轮的段落一起并进去。

**名字就是以后点它的那一下**：检索（向量与词面）建在节点名和 `note` 上；旧入口的对话原文
不参与检索，只给重建和编写用，所以名字必须单独读得懂、能搜到——具体主语 + 动作 + 结果，
6–24 字，至少两个实词，不用问句、空词或“谁说了什么”。写错的可以用 `rename` 改，
连错的可以用 `unlink` 断。

本层不设节点层与标签层。事件名称即该事件的短标题。归档阶段不再判断事件是否合并或新建。

`loop/` 不走这套逐轮判断：它在对话进行中由模型自己决定记不记，用 `remember` 把 note
直接写到事件上（见 [`持续在场-API实现.md`](持续在场-API实现.md)）。

## 2. 事件网络

事件之间构成网络，边分为两类：

- `属于`：表示包含关系；
- `相关`：表示其他关联。

现在新建的边只有 `相关`（`links` 建的）；`属于` 是旧数据里的关系，读的时候按关联算。
一个事件可连多个事件；树结构是网络的特例。

## 3. 状态维护

`event` 工具一次调用给出一个判断（`skip` / 挂已有 / `new` / `hold`，见 §1），一轮可以调多次：
先标这一轮说到的旧话题，再标新增的内容。带 `links` 连相关旧节点，`rename` 改错名，
`unlink` 断错边；系统不自动建立连接，同名只当提示。返回这一轮已经标了哪几件事。

工具顺序固定为 recall →（必要时 recollect）→ event → 正文：event 是正文前最后一个工具调用，
两次提示仍不满足时这一轮不落记录。挂起的轮在落盘时并进节点，`held` 可只并指定的几轮。

事件标识为随机字符串（`e-` 加 12 位十六进制），并记录 `created` 与单调的 `seq`。
事件先后按 `(created, seq)` 判定，不按标识字符串排序。

沿革：早期版本用六种模式（继续 / 子事 / 回 / 换事 / 接旧 / 关联）维护一条“栈”；现在改成
上面这种“一轮几个判断”，不再有栈。旧数据里的 `属于` 仍按关联读。

## 4. 回忆

回忆流程如下：

1. 线索输入：仅关键词；回忆读 **live 图**——本场与旧场的事件都在同一张图里。
   图里还没有事件时（第一场）返回“没有找到节点”，提示先 `event new`；
2. 种子选择：以向量相似度为主、词面覆盖为辅，超过阈值的事件成为种子。
   向量与词面建在**节点名和 `note`**上；旧入口的对话原文不参与检索，只给“重建 / 编写”用；
3. 扩散：从各种子出发，沿 `属于` / `相关` 边传播，并按内容相似度感应。
   内容近邻一次算好（`content-index.json` 存每个节点的 top-256，按名字/词集/模型的指纹失效），
   扩散只走这张短表，不再每轮和全图逐个比；
4. 竞争：按查询词的覆盖度归一，不按事件长度归一；抑制相似事件；巩固、可及与近期仅作微调。
   若事件被至少两个不同种子激活，且与线索的余弦相似度不低于 0.5，可作为候选赢家；
5. 时间过滤：模型将相对时间转换为具体日期，使用 `after` / `before`；
6. 重建：将选定事件的材料按时间顺序还原（材料见 §5）；
7. 编写：将重建内容写为第一人称回忆。

回忆不接收当前事件名，不自动排除当前事件，也不携带上一轮激活；
回忆本身不依赖 event 的先后，但事件标注固定为本轮**正文前最后一个工具调用**：
先 recall / 必要时 recollect，最后 event，event 之后直接给正文。
两次提示仍不满足时，这一轮不记录并报错，不会落下 event 不在最后的记录。

### live 图、冻结与续聊

- 本场：`event` / `recollect` 照常维护 live 图与 live 向量，改完立刻对 recall 可见——
  本场刚发生的事也能被回忆到；
- 归档：`consolidate` 完成后，把 live 图 + vectors 写成全局 `冻结/`，作为下一版的起点
  （`freeze` 走的是同一条路径）；
- 续聊：加载 `状态/<场>.jsonl.messages.json`，原样恢复完整 messages
  （含 assistant tool_calls 与 tool 结果），恢复 turn / stack 后继续；
- 旧数据升级：先 `freeze` 生成全局冻结。旧未归档场没有 messages 日志时，
  只能按状态里的 user/assistant 重建，无法保证工具上下文逐字一致。

### 沿革：本场冻结副本（已废弃）

早期版本在本场开场时把全局 `冻结/` 复制到 `状态/<场>.frozen/`，recall 只读这份，
live 图只算工作记忆、不参与回忆——理由是“本场还没落定的东西不该被自己想起来”。
持续在场（`loop/`）要的正好相反：本场刚发生的事得能回忆到，这条限制就撤了。
现在 recall 直读 live 图，`FrozenSession` 已删；旧数据目录里若还有 `状态/<场>.frozen/`，
不再被读取。留下的只有全局 `冻结/`（归档产物，`freeze` 与旧数据升级拿它当起点）。

上下文仅接收编写结果；材料与候选都不进入上下文。

## 5. 编写

材料有两种，取决于哪条入口写的记忆：

- `loop/`（持续在场）：材料是模型自己写的 `note`；`recollect` 一次把该事件的全部 note
  交给编写模型，不挑选、不截断。只有没有任何 note 的旧事件才退回场次记录。
- `memory_v2/chat/`、`serve.py`、App（旧入口，不再维护）：材料是场次记录里那一轮的
  `user` + `assistant` 原文，按轮挂到事件上。选法：不超过 8 段时全部使用；超过 8 段时
  取线索重叠最高的 8 段并保留最近一段（至多 9 段），再从前往后按 2000 字上限取段
  （首段总会保留）。

材料附日期与注意力强度；强度高者写入，低者仅作背景。
同一事件存在先后说法时，以时间较晚者为准。
材料仅含相对时间时，保留相对时间，不转换为具体日期；不补充材料中没有的数字或因果关系。

材料只读：note 只增不改，场次记录不重写。`说法/` 目录为每次编写的追加日志，
不是可编辑的当前说法层。

旧入口有一个已知后果，不修：一轮只要挂在某件事上，整轮的回复就成为它的材料，
包括回想之后把回想说出来的那一轮。转述和当时的话在同一条材料里，没有来源标记；
“以时间较晚者为准”会让这段转述拿到最后发言权。`loop/` 不走这条路：回想只读，
要写什么由模型自己调 `remember` 决定，写下的 note 是它自己的记录。

## 6. 归档与重放

每轮状态在当轮落盘，归档不承担状态判断。
归档由手动触发：一场结束后执行 `replay`，或在 `chat` 中使用 `--replay-on-exit`。
归档成功会写 `状态/<场>.jsonl.archived` 标记；标记存在时这一场只读，不能再开 `chat` / `serve` 写入。
归档最后把 live graph + vectors 写成 `冻结/`（全局版）：本场 recall 不读它，它是下一版的起点。

重放过程如下：

1. 起点选择：本场被标记的事件，加旧事件抽样；一场跑 3 遍，每遍重新抽样，
   避免“一遍里被同一批起点照亮”被当成共现；
2. 不均匀激活：从各起点沿边与内容扩散，逐步衰减；
3. 连接加强：被至少两个不同起点经过的连接，按起点数加强；
4. 旧事件的证据：被点亮的旧事件记一点证据（每场最多 +1，上限 8，每场 ×0.95 衰减），
   并记住最强的几个起点；**证据攒到 4.0 才建 replay 连接**——一次性共现不算数；
5. 连接底：replay 连接的支撑转成强度底（`0.02 × 支撑`，上限 0.35），
   反复被支撑的连接衰减不掉，一次性连接照旧消失；
6. 全局衰减：非结构连接乘以 0.87，取 `max(底, 衰减后)`；支撑每场 ×0.98；
7. 剪枝：强度低于 0.12 且底低于 0.08 的连接删除；模型建的连接保底 0.15，不删除。

旧版本留下的 replay 连接在第一次按新规则重放时清空重建（`source=replay` 且 `v≠3`）；
`pairs` 候选计数不再写入，字段仅为兼容旧图保留。

事件图可由状态记录通过 `ingest` 补齐，命令可重复跑。整体重建用 `ingest --rebuild`：
先备份旧图，再清空重建；状态记录能恢复事件、片段和对话里声明的 `属于` / `相关`，
不能恢复重放长出的边、连接强度、可及、巩固与手动奖励；手动的 `detach` / `unlink`
也会被状态记录重画。

单场数据规模较小时，种子密度高，重放难以形成明显的关联主干；结构连接仍然保留，
回忆仍可依据内容、向量与结构完成。

测试或备份时用 `snapshot` 把一个数据目录打成单文件 `.psnap`（zip），`restore` 解回目录，
graph、vectors、状态（含 frozen / messages）、说法与全局冻结一并带上；
`ingest` 只用于恢复源数据和一致性检查，不当快照用。

## 7. 与大脑结构的对应

本节按功能对应，不作解剖学类比。大模型具备语言与推理能力，但缺少事件形成、巩固、
遗忘与再认等机制；本层在外围补充这些机制。

| 脑结构或过程 | 本层机制 | 说明 |
|---|---|---|
| 前额叶、工作记忆 | 这一步的候选与激活 | 维持当前话题，逐轮更新 |
| 海马体：事件形成 | 事件为单位；片段或 note 挂在事件上 | 将一段经历组织为事件 |
| 海马体：模式分离 | 同名不合并；不同的事各成事件 | 区分相似但不同的事件 |
| 海马体：模式补全 | 线索到种子，落到事件，再扩散 | 由部分线索恢复事件 |
| 海马体：索引 | 随机事件标识指向分散片段 | 索引与内容分离 |
| 新皮层 | 材料（note 或对话原文）、事件向量、内容相似度 | 分布式长时痕迹 |
| 来源记忆 | 场次片段带说话人与场次，note 带日期 | 分得清谁说的，分不清“当时记的”与“后来回想的” |
| 注意与显著性 | 标记新事 / 挂旧事、编写强度 | 决定写入与提取 |
| REM | 稀疏起点、不均匀激活、内容感应 | 离线重激活 |
| SWS、突触稳态 | 连接加强、全局衰减、剪枝 | 强化主干，削弱弱连接 |
| 遗忘 | 连接衰减，材料保留 | 遗忘连接而非内容 |
| 再认 | 先看 `recall` 的候选里有没有盖得住的名字，再决定新建 | 再认优先于重建 |
| 重建与叙述 | 读取重建，编写叙述 | 叙述进入上下文 |
| 再巩固 | 不实现；材料只读，说法追加 | 避免改写材料 |
| 杏仁核、情绪、唤醒 | 不建模 | 不以标点作为情绪信号 |

## 8. 与大脑机制的差异

- 不模拟神经元与突触，连接为符号权重；
- 不包含情绪、唤醒与身体状态；
- 无真实睡眠周期，重放由手动触发；
- 读法固定，不随经历训练；记忆仍为外挂；
- 不实现再巩固；
- 输入仅为对话文本。
