# 持续在场 · API 实现

状态：实现中。骨架、上下文、两块原文、压缩与原文落盘、记忆工具面已完成；
最近 N 步过滤与去重未做。

本文是 [`持续在场.md`](持续在场.md) 的 API 版：语义相同（固定 sink、越旧越淡、细节在外部、
说话是一步），机制换成两层——**上下文**（最近，易失）与 **memory_v2**（历史，模型自愿写入）。
不做 day RAG、不做 chunks、不做 K/V；全部走 API。

## 0 范围与取舍

- 全部走 API：主模型用 DeepSeek（Flash 等）或百炼的 Qwen；摘要用百炼；memory_v2 的嵌入用
  百炼。本地模型不参与。
- 两层：上下文 cover 最近，memory_v2 cover 历史。上下文丢了的就丢了，不回头补。
- 上下文压缩由运行时独立完成，和主模型无关；压缩不写 memory_v2。
- 记忆写入放宽：主模型想记就记，不强制每轮。没写的，等摘要淡掉就没了。
- 1M 上下文是能力上限，不是设计假设；预算先按 64k 试，按实测调。

## 1 上下文

上下文按时间从旧到新排列：越靠前越旧，压得越多，也越简略。

```
[10-24 17:00–17:40] 很短的摘要（压过很多次）
[10-24 17:40–18:10] 短摘要
[10-24 18:10–19:00] 一段摘要
[10-24 19:00–19:40] 上一块的摘要
[19:40–20:10]        上一块：原文
[20:10–]             正在：当前块原文
```

- 渲染时只写时间段与内容，不写"最久 / 比较久"这类标签；时间段本身就是年龄。
- 刚开始时只有当前块；第一块满了先不动，等第二块也满，才把第一块压成摘要。所以上下文里
  最多同时有两块原文（上一块 + 当前块）。
- 压缩次数就是年龄：每下移一次再压一截，越靠前越短、越不可信。
- 挤出的内容只在 memory_v2 里——前提是模型写过；没写过就是没了。
- 预算：sink 2–4k；两块原文最多 40k；四段摘要 30–40k；总预算约 80k（想守 64k 就降块或降摘要）。
- 工具结果挂在当前块里，不单独占一段。工具是持续调的，所以有保留模板——同一个结果
  越旧留得越少：最新两条给全文（含给模型的提示语），更早的去提示语，`recall` 再压成
  一行（id、名字、日期留着），`recollect` 不压（那是记忆本身）。调用行不动，压缩读原文。

### 1.1 sink

sink 只放框架、约束与上下文说明；工具 schema 走 `tools` 参数，不写进这里。
现在这一版（改的是 `loop/prompts/sink.txt`，下面只是抄一份）：

```
我是$name。我用简体中文思考和说话。我既是Ranchel的助手也是他的陪伴者。

我一次只说几句，非必要不写长文。不编对方没说过的事，不替对方补回忆。不补材料里没有的日期、数字、数量、因果；相对时间保留相对时间。建议是建议，不要说得像对方说过的事实；一次最多一两条，先问一句再给。不编造没有的感知，不写旁白，不写括号里的场面。可以有不同意见，不用顺着对方；不附和，不为了顺着对方改口。不打包票；不说套话。不用复述刚给你的内容来证明你记得，自然使用就行。不为了把话接下去刻意追问；允许不知道说什么，允许说“不知道”“没记住”。

下面是这段时间的历史记录，从早到晚。越早的印象越淡，如果要回想就用 $recall 搜索对应关键词。最下面那段记录是原文，除此之外要准确就用工具查。

今天是$today。
```

要点：短；只说"旧的不一定对"；不把上下文叫"记忆"；不给工具清单；不重复 persona。
`$recall` 是工具名，接上记忆后注册；现在叫 `recall`。

## 2 压缩（运行时，独立于主模型）

- 攒块：原文先攒够一块（20k），这一块先不动。
- 触发：等第二块也攒够，才把第一块压成一段摘要；第二块继续留着。
- 只把要压的那一块发给摘要模型；不重写已有摘要。
- 主模型不参与，也看不到这一步；下一步只看到新上下文。
- **压缩只写上下文，不写 memory_v2。** 摘要不等于事件；记忆只由主模型自愿写入。
- 同步优先：块满时运行时暂停几秒做摘要；失败重试一次，仍失败就保留，等块再长一点。
- 摘要要求：块内越早越略、越靠近结尾越具体；保留专名、数字、决定、未完成；不编；
  时间在段头，正文不重复日期；结尾写"现在到哪了"。
- 输出：一段摘要 + 本块 `{start_ts, end_ts, summary, keywords, unfinished}`。

## 3 历史（memory_v2）

- **写**：主模型自愿。想记就调 `remember(name, note, links?, scope?)`；`note` 是模型自己
  写的材料，存进事件，**不进当前上下文**——写多了上下文也不涨。
- **契约**：名字是检索键；`note` 是以后编写模型的材料；`links` 连关系。名字要能搜到。
- **读**：`recall` 联想（候选、激活、光标）+ `recollect` 取具体；编写模型把 `note` 写成一段
  第一人称回忆，只有回忆进上下文。`recall` 读「最新冻结 + live」，检索默认只用嵌入；
  词面是开关，默认关（`--lexical`）。冻结 / 重放只留手工命令，不作为模型工具。
- **临时/永久**：事件带 `scope=short/long`；`short` 到期（默认 3 天）就**搬出图**：
  压成一行（模型压，压不动取最后一条 note 的第一句）写进 `memory/archive.jsonl`，
  然后从图里删掉——检索、激活、注意力都不再包含它。作废是搬走，不是降级留着。
  归档在循环等的时候做（`read/archive.py`）。，
  冻结时清掉；`long` 进重放/冻结。
- **过滤**：最近 N 步是默认关的开关（`--recent-steps`，0=关）；去重和来源标不做——
  没有老场次数据，冻结是手动的。
- **范围**：live 图就是长期记忆；循环路径不自动跑 replay / freeze。冻结只作手工快照；
  重放暂不跑——边由 `remember` 显式连，正文是 note，不需要重放重建。
- **计数**：`recall_log` 还没写；给将来 promotion 的"频率"判据用。

## 4 存储

- SQLite（本层）：
  - `bands(level, text, start_ts, end_ts)`：四段旧摘要（0=最旧，3=最近）；
  - `blocks(id, start_ts, end_ts, summary, keywords, unfinished, state)`：每个块一行，
    `state` = open / previous / compressed；
  - `entries(block_id, seq, role, content, tool_calls, tool_call_id, ts)`：块的原文按条存，
    重启时重建；
  - `recall_log(id, ts, question, event_ids)`：记忆检索记录；
  - `usage(step, ts, prompt, completion, cache_hit, cache_miss, reasoning)`：每步真数，
    `python -m loop.usage` 按天汇总；
  - `inbox(id, ts, kind, text, consumed)`：进件队列，谁都能往里写（stdin、以后的 HTTP、
    任务结果）。
- 运行时日志另存 `data/loop/loop.log`（轮转），只记发生了什么，正文在 `entries` 里。
- **当前块也存**：它就是上下文，不存就接不上。
- memory_v2：事件加 `notes`（模型写的材料）、`scope`、`expires_at`；旧场次段兼容；
  读取合并最新冻结与 live。不在 SQLite 里。
- 不再需要 chunks / day RAG。
- TTL：上下文 24 小时；memory_v2 的 `short` 默认 3 天，`long` 持久。

## 5 循环

- 每步：先把 inbox 里的动静读进来 → 拼上下文（sink + 旧段 + 当前块 + 工具结果）→
  主模型 → 执行 → 继续。
- 工具走原生 `tool_calls`：`remember` / `recall` / `recollect`（记忆），`wait`（等）。
- 正文是"说"：投递，不结束。**正文和工具调用可以同时**（原文 `tool_calls` 允许），
  两者都要处理——只处理其中一种，模型就会以为说过了而其实没说。
- `wait` 是等：等到有动静（`inbox` 里来了 `user` 或者 `task`）或者到点。`until` 收
  相对（`10m`）和钟点（`14:30`）两种写法，回复也各按各的写法（「等了十分钟」/
  「等到 14:30」）。不传 `until` 就是一直等。**一个回复里只允许一个 `wait`**：两个
  `wait` 是「等完这个再等那个」，不是「或者」，多出来的不执行并说明原因。
- 醒来的动静写成记录：`user` 是 `对方：…`，其他是 `提醒：<kind>：…`；`wait` 的结果
  只写"等了多久、为什么醒"，不重复内容。
- 空回复（没有正文、没有工具调用）也是等：有输入通道（`--stdin`）就真等，没有就停住。
- 等的时候顺手做维护：块满了就地压缩。
- 重启时块里挂着没有结果的 `wait` 调用，就接着等——块本身就是等待状态，不用额外存。
- 压缩在运行时做；同步时下一步等它。
- 兜底：模型调不通就退避重试（5 秒起、翻倍、封顶五分钟）直到通；连续
  `watchdog_idle`（默认 6）步没有外部输入就报警——塞一句「还在做事吗」，模型回一句
  就接着做，不硬停；提醒只留最近两条在上下文里。工具返回不算外部输入，所以联网、
  多步任务也会触发报警，这是有意的：它只是在问，不是打断。
- 成本：`usage` 表每步一行真数，`python -m loop.usage` 按天看；运行时日志在
  `data/loop/loop.log`。
- 每轮有预算上限；固定 sink 与旧段稳定，可走 prompt caching；当前块每步增长。

## 7 实现顺序

0. **骨架（已完成）**：config、上下文、标准工具面、循环驱动、SQLite、离线自检。
1. **压缩（已完成）**：一块一次，只压刚结束的那一块；第一块满了先不动，第二块满才压
   第一块。实跑 10 步 2 次压缩；摘要失败保留原文，等块再长一点再试。
2. **memory_v2（循环路径已接）**：`remember` 写 note、`recall` 联想 + 光标、`recollect`
   编写；`short/long`；读取合并冻结 + live。最近 N 步过滤、去重、来源标还没做。
3. **长跑**：实跑或模拟几小时；验证"3 小时前做了什么"能通过 recall 查到；确认上下文
   丢掉的内容确实不在。
4. **恢复（已完成）**：`blocks` + `entries` 按条落盘，重启恢复上一块和当前块；
   memory_v2 的重建随步骤 2。
5. **调参**：块大小、五段配比、recall N、sink 措辞。

建议目录（新代码；尽量不动 memory_v2 的存储语义）：

- `loop/context.py`：拼 sink + 旧段 + 当前块；
- `loop/compress.py`：调摘要模型，一块一次；
- `loop/driver.py`：步循环、工具、预算；
- `loop/store.py`：SQLite 三张表；
- `loop/memory_bridge.py`：工具面（remember / recall / recollect）与 memory_v2 的图。

memory_v2 侧只改两处：`read/activate.py` 的读集（冻结 + live）、`chat/loop.py` /
`chat/tools.py` 的 event 调用改为可选；不动归档、重放与长期语义。

### 7.1 步骤 0 的实现注记

- 代码在 `loop/`；入口 `python -m loop --name <名字> --data <目录> --memory-data <记忆目录> --max-steps N`。
- 每步只发两条消息：system（sink + 旧段）与 user（上一块 + 当前块原文）。
- 两块原文：当前块满时只升成上一块，不压；下一块满时才压上一块。所以同时最多两块原文。
- 记录里工具调用写成 `调用 recall {...}`、结果写成 `结果：…`，正文原样；`remember` 的 note
  不写进记录，只留"写下了记忆：名字"，内容在记忆里。行首不写时刻，时刻只在段的时间范围里。
- 旧段最多四段，字符上限 1200 / 2400 / 4800 / 9600（由旧到新）；每老一格不超过新一格的
  0.8（模型写回原长也会被截），保证分辨率从后往前单调下降。
- 预算：上下文 80k、块 20k、旧段 30k。真实用量读服务端 `usage`，每步落 `usage`
  表（prompt / completion / 缓存命中）。块满按真数判：上一次请求的 `prompt_tokens`
  减掉固定部分（sink、旧段、工具 schema）就是当前块的真实大小；没有真数时（刚重启、
  刚压完）才用估算顶一步，估算常数按实测校准（汉字 0.76 token/字、其余 4.11 字符/token）。
- 压缩日志只打在运行时输出里，不进上下文。摘要默认 `deepseek-flash`（同端点），
  `--summary-model qwen-plus` 走百炼；失败保留原文，等块再长 1k 再试。
- 工具：`remember` / `recall` / `recollect`；正文是说，空回复即停。
- 记忆：事件带 `notes` / `scope` / `expires_at` / `step`；写入的 note 是编写模型的材料；
  读取合并最新冻结与 live；嵌入用百炼，词面默认关（`--lexical` 开）；最近 N 步是默认关
  的开关（`--recent-steps`）；冻结 / 重放只手工跑，不给模型工具；去重、来源标不做。
- 落盘：`bands` / `blocks`（open / previous / compressed）/ `entries` / `recall_log` /
  `usage`；上一块与当前块的原文按条存，重启接上。
