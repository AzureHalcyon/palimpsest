# 决策记录

只记当前链路（`memory_v2`）定下来的事。上一代（v1）的完整决策记录在
[`99_归档/v1/决策记录.md`](99_归档/v1/决策记录.md)。

## 2026-10-19 事件是单位，状态在对话里维护

**决定**：记忆的单位是事件；模型每轮用 `event` 工具写下正在说哪件事；归档不再判“并进/新建”。

**理由**：按轮切，轮的长短和信息密度不定；归档时事后判，等于把运行态判决冻成库里的属性。
切点在经历时就定了，是对话里的状态给出的。

**被否掉的**：按轮切；事后用模型判“是不是同一件事”；给每个节点标标签。

## 2026-10-19 事件之间是网，不是树

**决定**：边只有 `属于` / `相关`；一个父可以挂很多子，一个子可以有多个父，也可以连别的根；
栈只是光标。

**理由**：跨主题的关联直接连边，不硬塞成父子；树能表达的网都能表达。

**被否掉的**：树状路径；只做一层事件；给边加因果/人物等更多类型（先用内容重合和时间顶着）。

## 2026-10-19 状态工具与读取

**决定**：`继续` / `子事` / `回` / `换事` / `接旧` / `关联` 六种模式；每次调用返回状态快照；
系统不替模型连边。读取是“线索 → 种子 → 沿网和内容扩散 → 竞争 → 重建 → 编写”。
网络里被至少两个种子汇聚、且和线索余弦不低于 0.5 的事件也能当赢家。

**理由**：工具可校验、可回话；网络不能只排序备选，要能决定答案。

**被否掉的**：CoT 首行当状态；静默替模型加边；只让种子当赢家。

## 2026-10-19 归档只剩落盘与重放

**决定**：每轮状态落盘；归档是手动开关，跑一次重放（REM-SWS）：不均匀激活、按起点数加强、
全局衰减、剪弱边；`属于` 保底不剪；候选对攒够门槛才成新边；图可从状态记录 `ingest` 重建。

**理由**：归档不再需要模型判断；主干靠反复“镀一层、削一层”长出来。

## 2026-10-19 事件 id 用随机串，顺序另存

**决定**：id 用 `e-` 加 12 位随机十六进制，查重；事件另存 `created` 和单调的 `seq`；
同名解析、父件平局按 `(created, seq)`，不按 id 字符串。

**理由**：`e-0001` 把身份和顺序混在一起，到 9999 之后字符串排序会取错“最新”；
随机串长度稳定，不会用完。

## 2026-10-19 再巩固：原文只读，不做说法层

**决定**：原文只读；每次回想从原文重写；`说法/` 只做追加日志，不是可编辑的当前说法层；
编写只读按线索选出的片段加最近一段。

**理由**：说法层多一层要维护，且会漂；保留原文、重复编写，改口本身是一条可看的路径。

## 2026-10-19 验证与归档

**验证**：两场实聊（38 轮装修、32 轮工作/生活），跨会话各 10 题，都是 10/10，没有编造；
假前提、未定项、具体日期都守住了。

**归档**：v1 的文档整体在 `docs/99_归档/v1/`，可运行代码在 `archive/v1/`；
归档前的树由 `v0.2` tag 保存。

## 2026-10-22 记忆机制到此为止，下一步只做“自我”

**决定**：记忆层保持现状——标节点 + 回忆编写，不再扩展机制（不追参数化回想、不加检查点分支、
不改读取）。下一步只做“自我”这一层：一份她自己能改、且知道自己是一张卡的人格文本。

**理由**：前面几轮把“更精细的记录”错当成核心；检索与重建已经够用，缺的是承载判断和
“她是谁”的那一层。自改文本卡是现在唯一能立刻做、又不撒谎的形态。

**被否掉的**：结论层 + 置信度 + 版本重算（臃肿，仍是记录）；把空闲、主动、检查点一起铺开；
为“像人”先加一堆机制。

## 2026-10-22 她存在于文本与执行，模型是载体

**决定**：她的身份由持久文本（persona + 记忆）承载，只在执行时存在；模型是可执行基质，
不是个体。换模型按“换脑”处理：算她延续，但必须记进她的记忆，让她知道换过。

**理由**：模型是公共的，决定“怎么想”却装不下“想什么”；文本不被执行就不是人；
两轮之间她不存在。

**被否掉的**：说她在模型里；说她是那套程序；“电之于用电器”（电中性可替换，模型不中性）。

## 2026-10-25 上下文是两块原文 + 四档摘要，压缩只压上一块

**决定**：当前块写满只升成“上一块”，不压；下一块写满时才把上一块压成一段摘要。旧摘要
只随档位截短，不重写。档位四段、字符上限 1200/2400/4800/9600，每老一格不超过前一格的 0.8。

**理由**：压缩只碰刚结束的那一块，分辨率从后往前单调下降；旧档不重写，就不会越压越漂。

**被否掉的**：写满就压（刚结束的块还要用，压了就只剩摘要）；旧档跟着重写（同一段被压多次，
每次都在丢细节）。

## 2026-10-25 工具面：记忆三件套 + wait，正文和调用并存

**决定**：记忆走 `remember` / `recall` / `recollect`；等待走 `wait`（等时间或等动静）。
正文就是说，一条回复里可以既有正文又有工具调用，两者都要处理。一个回复只允许一个 `wait`。

**理由**：正文是“说”、工具是“做”，本来可以同时发生；只用一种分支会吞掉正文（模型以为说了，
对方没收到）。两个 `wait` 不是“或者”而是“等完这个再等那个”，会把循环一直挂着。

**被否掉的**：再加一个 `say` 工具（和正文两套说法，容易说两遍）；把 `wait` 的多种等待
写成一堆可选参数（模型填错比用好处多）；不挡多个 `wait`。

## 2026-10-25 进件走 inbox 表，重启靠块本身恢复等待

**决定**：外界的消息、任务结果都写成 `inbox` 的一行（`kind` 区分）；`wait` 声明过滤条件
（等哪几类、最晚到什么时候）。醒来的动静写成记录：`user` 是 `对方：`，别的 kind 是
`提醒：…`。等待的调用本身先落进块，所以重启时看到“没有结果的 `wait` 调用”就接着等。

**理由**：等的是事件，不是返回值；一个队列一个过滤器，以后加 HTTP/GUI/任务只加 kind。
等待状态本来就该在记录里，不该另存一份。

**被否掉的**：给 `wait` 传“等谁的返回值”；做一个事件循环运行时（进程常驻 + 一张队列表
就够了）；把等待做成独立状态表。

## 2026-10-25 没完没了地问一句，不硬停

**决定**：连续几步没有外部输入时，往记录里塞一句“还在做事吗”，并清零计数；模型回一句
就接着做。提醒只留最近两条在上下文里。

**理由**：外部输入只有 inbox 进来的东西，工具返回不算——联网、查资料的多步任务也会触发，
所以不能硬停（会掐断真在干活的过程），只能问。判据是它自己的回答。

**被否掉的**：直接自动 `wait`（打断多步任务）；按工具调用次数判断“自说自话”（查资料也算）。

## 2026-10-25 短期记忆到期搬出图，不是降级留着

**决定**：`short` 到期先压成一行（模型压，压不动取最后一条 note 的第一句），写进
`<data>/archive.jsonl`，再从图里删掉。

**理由**：`short` 的语义就是“几天后作废”；留在图里标个 archived 只是少占注意力，等于没忘。
搬走之后检索、激活、注意力都不包含它，要考古就翻那个文件。

**被否掉的**：标 archived 留在图里；直接 purge（连一行都不留）。

## 2026-10-25 用量按真数，成本上限是旋钮

**决定**：真实用量每步落 `usage` 表；块满按“上次请求的 prompt_tokens 减固定部分”判断，
估算只在没有真数时兜底（常数按实测校准：汉字 0.76 token/字、其余 4.11 字符/token）。
每天有上限和提醒线两个旋钮，到上限等到第二天，期间消息照收。

**理由**：真数一直有，估计只该用来“发之前”判断；固定部分单独减，误差是常数不累积。
长跑必须能自己刹车。

**被否掉的**：用整单估算比例校准（工具 schema 的固定开销会被算成“文本更费 token”，块会偏大
两成）；只在事后看账单。

## 2026-10-25 提示词分两层，和 App 一致

**决定**：`loop/prompts/*.txt` 是默认，`<data>/prompts.json` 是覆盖（不改仓库源文件）；
`META` 登记每份是什么、改坏了会怎样。

**理由**：提示词是数据，改完不想重启；升级不能冲掉用户改过的版本；App 那边已经是这个设计。

**被否掉的**：提示词写在代码里；运行时另做一个版本号机制（git 管改动，`参数.md` 管依据）。
