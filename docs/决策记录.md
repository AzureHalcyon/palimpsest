# 决策记录

只记当前链路（`memory_v2`）定下来的事。上一代（v1）的完整决策记录在
[`99_归档/v1/决策记录.md`](99_归档/v1/决策记录.md)。

2026-10-28 拆仓之前的条目，路径按当时的单仓写（`loop/web.py`、`loop/settings.py` 这一类
现在在另一个仓 `rin`）；条目本身不改，它们是当时的记录。

## 2026-10-19 事件是单位，状态在对话里维护

**决定**：记忆的单位是事件；模型每轮用 `event` 工具写下正在说哪件事；归档不再判“并进/新建”。

**理由**：按轮切，轮的长短和信息密度不定；归档时事后判，等于把运行态判决冻成库里的属性。
切点在经历时就定了，是对话里的状态给出的。

**被否掉的**：按轮切；事后用模型判“是不是同一件事”；给每个节点标标签。

## 2026-10-19 事件之间是网，不是树

**决定**：边只有 `属于` / `相关`；一个父可以挂很多子，一个子可以有多个父，也可以连别的根；
栈只是光标。

**理由**：跨主题的关联直接连边，不硬塞成父子；树能表达的网都能表达。

**被否掉的**：树状路径；只做一层事件；给边加因果/人物等更多类型（先用内容重合和时间顶着）。

## 2026-10-19 状态工具与读取

**决定**：`继续` / `子事` / `回` / `换事` / `接旧` / `关联` 六种模式；每次调用返回状态快照；
系统不替模型连边。读取是“线索 → 种子 → 沿网和内容扩散 → 竞争 → 重建 → 编写”。
网络里被至少两个种子汇聚、且和线索余弦不低于 0.5 的事件也能当赢家。

**理由**：工具可校验、可回话；网络不能只排序备选，要能决定答案。

**被否掉的**：CoT 首行当状态；静默替模型加边；只让种子当赢家。

## 2026-10-19 归档只剩落盘与重放

**决定**：每轮状态落盘；归档是手动开关，跑一次重放（REM-SWS）：不均匀激活、按起点数加强、
全局衰减、剪弱边；`属于` 保底不剪；候选对攒够门槛才成新边；图可从状态记录 `ingest` 重建。

**理由**：归档不再需要模型判断；主干靠反复“镀一层、削一层”长出来。

## 2026-10-19 事件 id 用随机串，顺序另存

**决定**：id 用 `e-` 加 12 位随机十六进制，查重；事件另存 `created` 和单调的 `seq`；
同名解析、父件平局按 `(created, seq)`，不按 id 字符串。

**理由**：`e-0001` 把身份和顺序混在一起，到 9999 之后字符串排序会取错“最新”；
随机串长度稳定，不会用完。

## 2026-10-19 再巩固：原文只读，不做说法层

**决定**：原文只读；每次回想从原文重写；`说法/` 只做追加日志，不是可编辑的当前说法层；
编写只读按线索选出的片段加最近一段。

**理由**：说法层多一层要维护，且会漂；保留原文、重复编写，改口本身是一条可看的路径。

## 2026-10-19 验证与归档

**验证**：两场实聊（38 轮装修、32 轮工作/生活），跨会话各 10 题，都是 10/10，没有编造；
假前提、未定项、具体日期都守住了。

**归档**：v1 的文档整体在 `docs/99_归档/v1/`，可运行代码在 `archive/v1/`；
归档前的树由 `v0.2` tag 保存。

## 2026-10-22 记忆机制到此为止，下一步只做“自我”

**决定**：记忆层保持现状——标节点 + 回忆编写，不再扩展机制（不追参数化回想、不加检查点分支、
不改读取）。下一步只做“自我”这一层：一份她自己能改、且知道自己是一张卡的人格文本。

**理由**：前面几轮把“更精细的记录”错当成核心；检索与重建已经够用，缺的是承载判断和
“她是谁”的那一层。自改文本卡是现在唯一能立刻做、又不撒谎的形态。

**被否掉的**：结论层 + 置信度 + 版本重算（臃肿，仍是记录）；把空闲、主动、检查点一起铺开；
为“像人”先加一堆机制。

## 2026-10-22 她存在于文本与执行，模型是载体

**决定**：她的身份由持久文本（persona + 记忆）承载，只在执行时存在；模型是可执行基质，
不是个体。换模型按“换脑”处理：算她延续，但必须记进她的记忆，让她知道换过。

**理由**：模型是公共的，决定“怎么想”却装不下“想什么”；文本不被执行就不是人；
两轮之间她不存在。

**被否掉的**：说她在模型里；说她是那套程序；“电之于用电器”（电中性可替换，模型不中性）。

## 2026-10-25 上下文是两块原文 + 四档摘要，压缩只压上一块

**决定**：当前块写满只升成“上一块”，不压；下一块写满时才把上一块压成一段摘要。旧摘要
只随档位截短，不重写。档位四段、字符上限 1200/2400/4800/9600，每老一格不超过前一格的 0.8。

**理由**：压缩只碰刚结束的那一块，分辨率从后往前单调下降；旧档不重写，就不会越压越漂。

**被否掉的**：写满就压（刚结束的块还要用，压了就只剩摘要）；旧档跟着重写（同一段被压多次，
每次都在丢细节）。

## 2026-10-25 工具面：记忆三件套 + wait，正文和调用并存

**决定**：记忆走 `remember` / `recall` / `recollect`；等待走 `wait`（等时间或等动静）。
正文就是说，一条回复里可以既有正文又有工具调用，两者都要处理。一个回复只允许一个 `wait`。

**理由**：正文是“说”、工具是“做”，本来可以同时发生；只用一种分支会吞掉正文（模型以为说了，
对方没收到）。两个 `wait` 不是“或者”而是“等完这个再等那个”，会把循环一直挂着。

**被否掉的**：再加一个 `say` 工具（和正文两套说法，容易说两遍）；把 `wait` 的多种等待
写成一堆可选参数（模型填错比用好处多）；不挡多个 `wait`。

## 2026-10-25 进件走 inbox 表，重启靠块本身恢复等待

**决定**：外界的消息、任务结果都写成 `inbox` 的一行（`kind` 区分）；`wait` 声明过滤条件
（等哪几类、最晚到什么时候）。醒来的动静写成记录：`user` 是 `对方：`，别的 kind 是
`提醒：…`。等待的调用本身先落进块，所以重启时看到“没有结果的 `wait` 调用”就接着等。

**理由**：等的是事件，不是返回值；一个队列一个过滤器，以后加 HTTP/GUI/任务只加 kind。
等待状态本来就该在记录里，不该另存一份。

**被否掉的**：给 `wait` 传“等谁的返回值”；做一个事件循环运行时（进程常驻 + 一张队列表
就够了）；把等待做成独立状态表。

## 2026-10-25 没完没了地问一句，不硬停

**决定**：连续几步没有外部输入时，往记录里塞一句“还在做事吗”，并清零计数；模型回一句
就接着做。提醒只留最近两条在上下文里。

**理由**：外部输入只有 inbox 进来的东西，工具返回不算——联网、查资料的多步任务也会触发，
所以不能硬停（会掐断真在干活的过程），只能问。判据是它自己的回答。

**被否掉的**：直接自动 `wait`（打断多步任务）；按工具调用次数判断“自说自话”（查资料也算）。

## 2026-10-25 短期记忆到期搬出图，不是降级留着

**决定**：`short` 到期先压成一行（模型压，压不动取最后一条 note 的第一句），写进
`<data>/archive.jsonl`，再从图里删掉。

**理由**：`short` 的语义就是“几天后作废”；留在图里标个 archived 只是少占注意力，等于没忘。
搬走之后检索、激活、注意力都不包含它，要考古就翻那个文件。

**被否掉的**：标 archived 留在图里；直接 purge（连一行都不留）。

## 2026-10-25 用量按真数，成本上限是旋钮

**决定**：真实用量每步落 `usage` 表；块满按“上次请求的 prompt_tokens 减固定部分”判断，
估算只在没有真数时兜底（常数按实测校准：汉字 0.76 token/字、其余 4.11 字符/token）。
每天有上限和提醒线两个旋钮，到上限等到第二天，期间消息照收。

**理由**：真数一直有，估计只该用来“发之前”判断；固定部分单独减，误差是常数不累积。
长跑必须能自己刹车。

**被否掉的**：用整单估算比例校准（工具 schema 的固定开销会被算成“文本更费 token”，块会偏大
两成）；只在事后看账单。

## 2026-10-25 提示词分两层，和 App 一致

**决定**：`loop/prompts/*.txt` 是默认，`<data>/prompts.json` 是覆盖（不改仓库源文件）；
`META` 登记每份是什么、改坏了会怎样。

**理由**：提示词是数据，改完不想重启；升级不能冲掉用户改过的版本；App 那边已经是这个设计。

**被否掉的**：提示词写在代码里；运行时另做一个版本号机制（git 管改动，`参数.md` 管依据）。
## 2026-10-25 网页只读库、只往 inbox 写

**决定**：`loop/web.py` 的接口一律只读数据库、只往 `inbox` 写，从不碰 `blocks` /
`entries` / `bands`；单写者仍然是循环那个进程。界面是一页 HTML，不起前端工程、不加依赖。
每条连接各开一个 `LoopStore`，库开 WAL，读不挡写。

**理由**：单进程单库是这套东西的前提，破了就要面对两处写同一批表。网页崩了只该影响
「看得见」，不该影响「记得住」。原文多一列 `step` 也是为这个：网页要按步分组，但这条
信息属于记录本身，不该只活在运行时的内存里。

**被否掉的**：网页直接读运行时内存（重启后状态对不上，还得处理线程共享）；让网页也写库
（等于把写者变两个）。
## 2026-10-25 模型可换、主题可切、输入框照 APP 重做

**决定**：三处模型（主 / 摘要 / 嵌入）都进设置页，并且都能点「列表」从端点的
`/models` 里挑；顶栏那个模型胶囊点开也是同一份清单，挑了立刻生效。主题做两套
（跟随系统 / 浅色 / 深色，存 localStorage），浅色值照 DSH 的 light 主题取。
输入框按 APP 的 `ChatComposer.kt` 重做：行号槽、回车只换行、只按按钮发送、
高度 120ms 过渡、5 行封顶后整块滚。

**理由**：模型名原来只能手敲，敲错了要等一次 404 才发现；嵌入模型更是连显示都没有。
主题是用户白天要看的需求，不该只有深色。输入框"回车即发送"和 APP 的手感不一致，
而行号槽是 APP 里已经验证过的做法（用户点名要看那边怎么做的）。
摘要客户端和嵌入器都是**造好就带着模型名**的东西，所以改模型时得重建，不能只改配置。

**被否掉的**：给每个模型做一个静态下拉（端点时不时上新，写死的单子会过期）；
把主题塞进 `settings.json`（那是浏览器自己的偏好，和服务端的旋钮不是一类东西）；
输入框保留"回车发送"（和 APP 相反，用户明确要求只用按钮）。

## 2026-10-25 回忆直读 live 图，本场冻结副本废弃

**决定**：recall 读 live 图（本场 + 旧场）；一场开场不再复制副本；归档只把 live 图写成全局
`冻结/`，当下一版起点；`FrozenSession` 删除，旧数据里的 `状态/<场>.frozen/` 不再读取。

**理由**：持续在场要能想起“刚才”，而冻结副本把本场挡在回忆之外，两者直接冲突。副本还要在
开场、续聊、升级时各维护一遍，多一份状态就多一处不一致——文档里已经同时存在两种说法。

**被否掉的**：recall 只读开场副本（原设计，理由是“本场没落定的东西不该被自己想起来”）；
两套图并存、由调用方挑一个读。

**沿革**：旧设计写在 `docs/事件状态与读取.md` 的「沿革：本场冻结副本」一节，不再当作现状。

## 2026-10-25 App 分仓，memory_v2 复制一份进去

**决定**：Android 客户端搬到单独仓库 `palimpsest-app`；它需要的 `memory_v2` 整目录复制
一份进去（不带测试与说明），不做 submodule、不打成 pip 包。主仓删掉 `app/` 与
`tools/backup-phone.ps1`。

**理由**：两套工具链（Gradle / JDK / Chaquopy 与 Python）挤在一个仓库里，构建缓存、报错和
CI 都互相拖；app 只有一万九千行、1.7 MB，拆出去对主仓的“瘦身”有限，收益是边界清楚。
复制而不是 submodule：手机侧短期不动，submodule 只会多一层同步机制；复制的代价是记忆层
会落后，所以更新时整目录复制，并在提交里写清来源 commit。

**被否掉的**：留在 monorepo（工具链继续混）；把 `memory_v2` 做成 submodule 或 pip 包
（多一层机制，且 Chaquopy 装包更麻烦）；先把 app 改成 HTTP 客户端再拆（方向对，但要改 app，
这次不做）。

**沿革**：`v0.2` tag 里还留着“app 在主仓”时的完整树。

## 2026-10-25 两种材料分开写清，旧 chat 入口不再维护

**决定**：规范里把材料分成两种——`loop/` 是模型自己写的 `note`，`memory_v2/chat/`、
`serve.py`、App 是场次记录里的对话原文。后者明确为旧入口，不再维护；它“回想之后整轮变成
材料”的后果不修，只在规范里写清。

**理由**：`loop/` 的写是模型自己的动作，回想只读，产物要进材料得它再 `remember` 一次，
没有自动回流。旧入口按整轮落材料，转述和当时的话混在一起，且“以时间较晚者为准”会让这段
转述拿到最后发言权；但它是旧入口，本地 8 场 146 轮记录里 `recollect` 一次没调过，没有修的依据。

**被否掉的**：给片段加 `derived` 标记（`loop/` 的材料里没有片段可标，旧入口不值得改）；
`recollect` 收多个 id 一次成文（能力没丢，要对照可以连取几次，没有实际用例）；把“以晚为准”
改成“以一手为准”（会连正常的改口一起压掉）。

## 2026-10-25 墙钟放在记录末尾，不进 sink 也不落库

**决定**：每步在记录的 user 末尾现拼一行「现在 10-25 周日 15:42；距上次对方说话 3 小时 12 分；
距我上次开口 6 分钟」；记录和库里都不出现它。

**理由**：判断“隔了多久”要绝对时间加相对时长，但这两样每步都在变。放进 sink（system、
prompt 最前）分钟级一变，整段前缀缓存每步作废；写进 `entries` 会变成“她说过现在是几点”，
还会被压进摘要。放记录末尾，只动最后一条，缓存和存储都不受影响。

**被否掉的**：sink 里只写“今天是…”（知道日期，不知道隔了多久）；每条记录行都带时间戳
（噪声，token 也涨）；把时间做成工具（每步都要用，白多一次调用）。

## 2026-10-25 输入框下面的数跟着记录退，总账放进设置

**决定**：`/state` 给两份用量——`live`（`store.usage_live()`，只算 `entries` 里还留着的步）
与 `totals`（`usage` 表全部）。输入框下面那行（步数 / 用量 / 命中）用 `live`，删一条记录就
退一点；设置里单列「用量总账」用 `totals`。

**理由**：删了记录还显示「4 步 · 4.4k token」，看着像没删掉——屏幕上的数该和屏幕上的记录
对得上。而钱确实花了，总账不能跟着退，所以两份分开摆。

**被否掉的**：删记录时顺手删 `usage` 行（总账跟着丢，历史花费再也算不出来）；只扣掉被删
那条自己的用量（`usage` 一步一行，一删就是整步，和「删一条」对不上）。

## 2026-10-25 命令工具只给白名单，不经 shell，默认关

> 2026-10-25 晚已改成 Landlock「只有工作区能写」，白名单与"不经 shell"两条都不再适用；见下面那条「命令改走内核沙箱」。


**决定**：加 `run` 工具，在宿主上执行一条命令。规则三条——第一段程序名必须在白名单里
（默认只有读的 18 个）、不经过 shell（`shlex.split` 后直接 exec）、工作目录固定
`<data>/workspace`，外加超时杀进程组、输出截断。默认关，开了才出现在工具面里；白名单
与超时都在网页设置里改。

**理由**：云实例上的命令是它自己的手，比让它只会说话有用；但「什么都能跑」等于没加规则，
第一次误跑就是整台机器的事。按第一段判名、又不给 shell，管道和重定向进不来，行为是可读的
——模型看到的拒绝理由直接写出「现在能跑什么」。

**被否掉的**：沙箱（云实例本身就是一次性的隔离，再加 bwrap 之类只是又一层要维护的东西）；
`sh -c` 跑整串（那就是没有规则）；逐条人工批准（没有人一直守着，模型只会一直等）。

## 2026-10-25 只说话不调工具时，问一次要不要继续

**决定**：推进循环的只有工具调用。模型说了话、没调工具，下一步在记录末尾挂一句中性的
「（这一步已经说完了。还要继续吗？）」（`prompts/ask.txt`，只拼进输入、不落库）；它调
`wait` 就停，调别的工具就继续；**问了还是只说话就停下**，不连着问。同时把 `wait` 的说明
从"不说话，等一会儿"改成"这一步停在这儿"，sink 加一句"说完就停"，watchdog 改成纯事实。

**理由**：2026-10-25 一条消息之后它自己跟自己说了 9 步、每 2 秒一步。根因是 `step()` 的
`elif content:` 把"有正文、没调用"当成"还有下一步"——模型发的 `finish` 被改写成"再来一步"，
而记录最后一条永远是它自己刚说的话，它只能往下接。心跳（第 7 步触发"接着做"）是放大器，
不是根因。原来的设计写了"正文不结束循环"，但没写"没有工具调用时靠什么往下走"，实现就默认
继续了。现在把"停不停"还给模型：`wait` 是它说"不继续"的动作，问一句是把决定权交回去而不
替它续写；问一次就够，再问就变成新的复读机。

**被否掉的**：不调工具就直接停（不用问）——省一次请求，但模型完全没机会表态，"停"变成系统
替它做的决定；连着问直到它调工具——提问本身会变成复读机，且每问一次都是一次请求；
"没有工具调用"当成 `finish` 直接退出进程——持续在场就断了。

## 2026-10-25 记录按原生角色拼，谁说的由 role 说

**决定**：以前整段记录塞在一条 `user` 消息里、靠行首「对方：」标人，现在拆成原生消息：
对方的话是 `user`，自己的话是 `assistant`，末尾再补一条 `user` 装墙钟（要问时带上
「还要继续吗」）。工具调用与结果并进做那件事的那条 `assistant`；心跳提醒走 `system`（实测 deepseek-flash 接受中途插的 system 消息，而且会读）。
墙钟仍留在末尾那一帧、role 是 `user`：有 tools 时端点不接受最后一条不是 user（会当成
续写、要求回传 `reasoning_content`，直接 400）；而且以 assistant 收尾等于叫它接着自己的
话写。系统注入（墙钟、心跳、那句提问）一律套 `<system-reminder>` 标签，sink 里写明标签
里是环境不是对方说的。心跳不进历史：库里留一行 `meta.kind = "watchdog"` 备查，渲染
时跳过，当场那句用瞬时注入——旧文案「接着做」和现在的规矩正好相反，留着只会捣乱。纯文本渲染（压缩输入）另留一套前缀 `对方：` / `我：`。

**理由**：服务器上真出过：整段塞进一条 user、只标了对方，自己那几段没标，它就把自己刚问
的那句当成对方问的，顺着答了一遍（"周日傍晚空下来了？"→"嗯，我在。周日傍晚…"）。原生
`role` 本来就是干这个的，不用教它读前缀，也不会出现"前缀被照抄进正文"这种事；历史只追加
消息，缓存照样命中。

**被否掉的**：继续在一条 user 里标「我：」「对方：」——要教它读这套前缀，而且压缩模型
读不到 sink 里的说明；把工具调用也还原成原生 `tool_calls` / `tool` 消息——`remember` 的
参数里带着 note，按设计不进记录，写成原生调用会原样漏进来，另外"还没结果的调用"（正等着的
`wait`）在协议上不合法。

## 2026-10-25 给模型一个工作区：write 只写 workspace，run 拒读凭证

**决定**：`<data>/workspace` 是它的地方——`run` 的 cwd 在这儿，新加的 `write` 也只写
这儿（相对路径，绝对路径和 `..` 都拒，解析后跑出工作区的也拒，单次上限 10 万字）。
`run` 那边加一条：参数里点到 `/etc/palimpsest`、`credentials.yaml`、`web-token`、
`*.pem`、`.ssh` 一类就拒读。工作区里放一份 `README.md` 说明各放什么。「工作区在哪、怎么读」写在**工具说明**（`prompts/tools/` 里那一份）里，不占 sink——sink 只放人设与边界，工具怎么用跟着工具走。

**理由**：她已经在 `run pwd` 里自己摸到工作区了（还在往上翻到 `/opt/palimpsest`），
但那儿是空的、她也写不进去——"有个屋子没家具"。写入口单独做而不是往 `run` 白名单里
加 `tee` / `mkdir`：`<data>/` 是服务用户可写的，加写命令等于把改 `loop.sqlite3`、
`graph.json` 的权限一起交出去；`write` 只管工作区这一块。拒读凭证是因为读出来就进记录
（还可能被写成笔记），而源码、数据、日志本来就想让她随便读。

**被否掉的**：沙箱（云实例本身就是隔离的，只要规则）；给 `run` 加写命令（见上）；
用 `chmod` 把凭证挡在她看不见的地方（服务自己要以同一用户读它，做不到）。

## 2026-10-25 命令改走内核沙箱：Landlock 只放工作区，不维护白名单

**决定**：`run` 不再有程序白名单，也不再"不经 shell"。命令走 `sh -c`，先被
`loop/landlock.py` 装上一层 Landlock 规则再执行：整台机器可读、可执行，**只有
`<data>/workspace` 能写**；装不上规则就 fail-closed（退出码 125，工具结果说明"这条没跑"）。
`RLIMIT_FSIZE` 限单文件（默认 64 MB）。唯一留下的规则是"命令里点到凭证/密钥就不跑"。

**理由**：白名单挡的是"用哪个程序"，代价是她每个新念头都可能撞墙（当天就被
`nproc`、`free` 挡住，还顺口问要不要加）；而白名单的收益是有限的——写权限真要给，
它挡不住。DSH 的做法是**文件效果策略**：命令不限，副作用限制在工作区，越界由内核拒。
这台服务器上正好可行：`bwrap` 没有，但 Landlock 在内核里（ABI 8，`CONFIG_SECURITY_LANDLOCK=y`），
`unshare -r` 被禁（没有 user namespace，做不了 bwrap 那套挂载）。
实测：读源码 ✓、写工作区 ✓、往 `/tmp` 与 `data/` 其他位置写被 `Permission denied`、
`python3` 能跑 ✓、管道重定向 ✓、`rm` 能删工作区里的东西 ✓。

**被否掉的**：黑名单（要挡的东西无界，`python3 -c`、`find -delete`、`sed -i` 全是口子，
漏一个就等于全开）；bwrap（机器上没有，`unshare -r` 也不可用）；提权（她待着的时候没人守着，
"批准"没有对应物）；断网（Landlock 的文件词表里没有网络，要断得靠 namespace）。

## 2026-10-25 墙钟按间隔刷新，不是每步都念

**决定**：末尾那一帧里的墙钟默认每 120 秒才刷一次（`clock_refresh`）；**有人说话、
`wait` 醒来（或到点）那一步一定给**。其余连续的步只放一句「（接着上面。）」当边界，
不带时间。0 = 回到每步都给。

**理由**：时间在末尾那一帧上，不碰前缀缓存，所以"每步都给"其实不吃命中率（实测总
79%，掉点的几步全是改提示词/重启）；问题在噪声——纯工具链里连着几步都写一遍"现在几点、
隔了多久"，把注意力往时间上拽，而这几秒里时间根本没变。隔一段给一次，既保留"有人说话时
一定知道隔了多久"，又不在工具链里反复念。

**被否掉的**：把时间做成工具让模型自己查（"隔了多久"她不会主动问，而它正是决定语气和
要不要开口的输入）；挪进 sink（每分钟作废整个前缀，比现在还差）；只在外部事件那一步给
（长工具链里她可能几步都不知道过了多久，2 分钟一次的折中更稳）。

## 2026-10-25 给模型一片自己的地方：自我描述，定时重写

**决定**：`<data>/persona.md` 是她自己写的"我是谁"，非空时拼在 system 里（sink 之后）。
**不给工具、不在每一步改**：闲下来且距上次超过 `persona_hours`（默认 24 小时）才由后台
调用重写一次，历史追加进 `persona.log`。上限 1200 字，网页抽屉里能看到当前这版、
带一个「清空」后门。

**理由**：她想改口吻/自我认知，这是合理需求；但这段挂在 system 上，每改一次前缀缓存
整段作废。所以分工成"内容归她、时机归定时"——一天最多一次，缓存损失可控。
sink 仍归人写，边界优先于她的描述（她写的是自我描述，不是规则）。

**被否掉的**：给她一个 `persona` 工具让她随时改（缓存抖动，而且容易越写越长）；
允许她直接改 sink（等于把边界交给她删）。

## 2026-10-26 同一轮调用超量：从挡死改成问一句

**决定**：同一轮里同一个工具连调 `_TURN_CALL_CAP`（3）次之后，第 4 次不执行，只回一句
「还要接着用就再调一次，这次照跑；不用了就说话，或者等」；它确认（再调一次）就真执行，
计数收回 1、重新起算。对方说话计数照旧清零。

**理由**：原来第 4 次起一律"这次没执行"，是个死结——人在让它重试、或者它真要多跑几条
命令时，工具会一直拿上一轮的次数挡回去（线上真发生过：人说「你要不要重新试试」，它还是
被挡）。挡住的本意只是提醒"别打转"，不是禁止使用，所以改成确认制：打转的照样被打断一次，
真要做事的不会被卡死。

**没选的**：把上限调大到 10（等于没提醒）；只对 `run` 放开（当初连写 7 步的是 `remember`，
问题不在命令）。


## 2026-10-28 拆成两个仓：设计与核心 / 落地与配套

**决定**：memory_v2 与 loop 留在本仓（设计、核心算法、循环引擎）；工具实现与工具描述、
记忆工具面、网关、设置表、人格与部署搬到另一个仓 rin。依赖单向：rin 导入本仓，
本仓不认识 rin。memory_v2/chat、serve.py、view.py 暂留（第二批再判）。

**理由**：判断（算不算重复、名字像不像 id、什么时候 graph.save()）和措辞（给模型看的那句话）
各归一处，改措辞不再牵动策略；工具的描述与实现同源，加一个工具不必改核心。
引擎只认「有哪些工具、按名字调哪个」——driver.py 里对三个工具模块的引用从 9 处降到 0。
工具描述也不再由核心硬编码名单：实现方用 prompt_files.register_tools 登记，
核心只负责读、渲染、校验。

**被否掉的**：三仓（网关单独一仓，为还不存在的第二个网关付一份版本配对的开销）；
工具描述留在核心（核心就会列着十个它自己跑不了的工具，加工具得改两边）；
判断留在工具面里（措辞一改，策略跟着漂，自检只能去匹配中文句子）。

## 2026-10-28 外来消息走收件箱：响铃与正文分开，策略按会话

**决定**：通道来的消息（带 source）不直接进上下文，而是进 inbox 并按会话策略投递：
wake 只响铃（记录里拼一行「还有 N 条没看的消息」，正文要用 messages 取）、
batch 只攒着、mute 不提示。策略存在 chats 表，改策略时未读的跟着改。
那行计数只在总数变化时重拼，6 步后离开上下文。网页与标准输入没有 source，正文直接进记录。

**理由**：模型接口只有 user / assistant / tool / system 四个角色，"谁说的、从哪来、
要不要现在看"只能放进内容或元数据。把它们做成**数据**（策略在表里）而不是代码分支，
她就能自己决定看哪些群、哪些人等会儿再看；上下文也不会被"来一条塞一条"淹没。
响铃与正文分开还有一个好处：一次唤醒只花一行，读不读、读多少由她决定。

**被否掉的**：来一条就写一条进记录（会被群聊刷屏，且与她"想再回"的判断打架）；
用 Redis 做队列（异步来自"她没读"，不需要第二个真相，策略与未读计数 SQL 一行就够）；
按人设策略（v1 只按会话，meta 留着以后加）；把通道名写进核心（核心不认识任何通道，
只认 POST /inbox 的字段）。

## 2026-10-28 她说的话带「回给谁」：外部叫醒的那几轮才有

**决定**：外部消息把她叫醒时，循环记下这条消息的来源与会话；此后她说的话落库时带上
`meta.via`（source / chat_type / chat_id / chat_name）。通道适配器照这个标记定向回发，
不再"发回最近说话的那个会话"。窗口在两种情况下关掉：本机（网页 / 标准输入）又说了话，
或者 wait 等到点回去没事。网页那边按 `meta.via` 在气泡下面标一行「→ 已发到 QQ 私聊「谁」」。

**理由**：网页和 QQ 是同一个对话的两扇门。以前适配器只能靠"最近谁说话"猜回发目标，
于是人在这边网页里聊两句，她的话就被复述到 QQ 上——两扇门互相污染。
把"这句话是回给谁的"做成记录上的**数据**，一次解决三件事：定向回发、多个会话不串、
网页看得见话去哪儿了。窗口跟着唤醒走而不是跟着"上一条消息"走，是因为她答一句可能
要好几步（读 messages、查资料、再说），这几步都算同一轮回复。

**被否掉的**：给她加一个显式的 say 工具（多一件要她记得用的事，忘了就静默不回）；
适配器记住"我推过一条所以下一条 assistant 就是回我的"（中途重启、或者她先说一句再看
消息，就错位）；按时间窗口猜（人在这边网页聊的时候照样会漏）；把 via 存成独立表
（它就是这一条记录的性质，跟着记录走，删记录时一起走）。

## 2026-10-28 来源照实写，投递方式另说：`source` 与 `direct` 分开

**决定**：`inbox` 加一列 `direct`。`source` 退回它本来的意思——"从哪儿来的"，照实写
（`网页` / `命令行` / `QQ` / 以后接的别的通道），只是个标签；要不要响铃、正文进不进记录，
看 `direct`。网页 `/say` 与标准输入写 `source=网页|命令行, direct=1`：正文照旧直接进记录、
不盖前缀（人就在这一头跟她说话），但仪表盘上看得见它是哪来的。老库没有这一列，
"没有 source"继续等于本机直投。

**理由**：以前用"有没有 source"同时回答两个问题——是不是外面进来的、正文要不要等她读。
接第二个通道时这两个问题就分家了：网页不是"外部"（她不欠它一个回发目标），可它的来源
同样值得记下来给人看。拆成两列之后，加通道只是换一个 `source` 值，核心不用改；
"外部来过几条"这类统计也不会把网页的对话算进去。

**被否掉的**：用 `source=''` 表示本机、靠约定（接了通道就没法再靠约定）；
另开一张 `local_messages` 表（同一段对话拆两处，`messages` 与对账都得读两遍）；
往 `source` 里塞 `网页:local` 这种复合值（一眼看不出来，还得多写一个解析）。

## 2026-10-29 循环只有步，没有轮：去掉步数上限

**决定**：入口 `--max-steps` 默认 **0**（不设上限），参数留着只给自检和手动跑短场。
循环只在两处收手：她自己的 `wait`（挂起是动作，不是终止），或者说完话没调工具
（问一句「还要继续吗」，再只说就停）。`_TURN_CALL_CAP` 那句从「这一轮已经调了 3 次。
还要接着用就再调一次，这次照跑；不用了就说话，或者 wait。」收成一句事实：
「已经连着调了 4 次。再调一次照跑。」——先说事实，不指路。

**理由**：设计里就没有轮：`持续在场` 写的是「循环不结束；挂起是暂停，而不是终止」，
每一步只产出四类之一（继续想 / 调用工具 / 说 / 挂起）。`--max-steps 20` 是早期"一次跑
一段"那阵子的遗留，默认值一直没人改。10-29 线上撞上了：03:05 起的那一轮先在 03:13
回过人、等了两次（30 分钟、到 10:00），10:00 回来接着验「思考强度旋钮」，第 20 步正好
撞上 `run` 的连调提醒被切断——她刚开始干活就没了下文，网页上最后一条停在工具拒绝，
看着像崩了。切断还顺带把"停"这件事从她手里拿走：设计里停是她自己的动作。

**被否掉的**：把上限调大（40 / 100——只是把切口推后，还是会在某一步切断）；
只在"有外界输入"时才计步（等回来照样算一步，且又把"轮"请回来）；`wait` 不计步而保留
上限（治了等，治不了"她正干到一半"）；去掉上限但加一个"连续 N 步无输出就停"
（等于换一个地方的硬停）。
