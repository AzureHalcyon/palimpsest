# 文档规范

## 范围

- `docs/` 只放当前链路（`loop/` ＋ `memory_v2/`）的文档；代码本身怎么用看各自的 `README.md`；
- v1 的文档整体在 `docs/99_归档/v1/`，只读，不再改；
- 研究、语料是共用材料，留在 `docs/研究/`、`docs/语料/`。

## 新文档

- 不用 emoji（包括表示禁止、重点、通过的符号）；
- 代码标识、文件名、路径用 ASCII；正文用简体中文；
- 一张表能说清的事，不写成长文；需要什么写什么，不抄旧文档；
- 链接用相对路径，改完跑 `python check_all.py`（其中含文档规范自查；只看文档可单跑
  `python tools/文档/check_docs.py`）；
- 当前文档不引用归档文档的具体段落；要指归档，只给归档入口；
- 不写作者自己的部署状态（哪台机器、什么域名、端口、绝对路径）——那对读者没用，还会过期；
  确实跑过就写成**验证证据**：「用一台 4 核 4G 的云主机实跑过」，给的是它能跑、要多大机器，
  不是我的机器长什么样。

## 行为变更改哪里

同一个行为只许有**一处说全**（规范原文），其他地方最多一句摘要 + 链接过去。
两处都写全，迟早打架——「回忆读哪张图」已经打过一次：规范写的是冻结副本，README 写的是
live 图，两个都像现状。行为一改，按下表一次改完：

| 改了什么 | 必须改 | 顺带 |
|---|---|---|
| 记忆层行为（回忆、事件、重放、归档） | `事件状态与读取.md`（规范原文）＋ `决策记录.md`（为什么改） | `memory_v2/README.md` 只留一句摘要；`参数.md` 有受影响的行就改那一行 |
| 参数 / 阈值 | `参数.md` 对应行（同时改代码默认值） | README 里引了具体数字的一并改 |
| 术语 | `术语表.md` | 旧词还会在旧数据里出现时标「（已废弃）」，不要悄悄删行 |
| 循环 / 网页 / 设置 / 提示词 | 引擎与提示词：`loop/README.md` ＋ `持续在场-API实现.md`；网页与设置表在另一个仓 `rin` 的 README | `参数.md` 的「循环」一节 |
| 命令 / 测试入口 | 各自的 README「测试」段 ＋ 根 `README.md` | `check_all.py` 的 `ENTRIES`——入口清单只认那一处 |
| 废弃一个行为 | 规范文件里留一节「沿革」：原来怎么、为什么撤、旧数据怎么读 | 其余地方删干净，不留“现状”口吻 |

## 决策与未定

- 定下来的写进 `决策记录.md`，一条一个主题，写清决定、理由、被否掉的方案；
- 还没定的写在 `事件状态与读取.md` 的“未定”一节，随设计文档更新。

## 归档

- 归档目录里的文档保持原样，不改链接以外的内容；
- 归档入口是 `99_归档/v1/归档说明.md`，旧文档地图 `99_归档/v1/README.md` 不动。
