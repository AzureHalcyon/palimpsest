# 文档规范

## 范围

- `docs/` 只放当前链路（`loop/` ＋ `memory_v2/`）的文档；代码本身怎么用看各自的 `README.md`；
- v1 的文档整体在 `docs/99_归档/v1/`，只读，不再改；
- 研究、语料是共用材料，留在 `docs/研究/`、`docs/语料/`。

## 新文档

- 不用 emoji（包括表示禁止、重点、通过的符号）；
- 代码标识、文件名、路径用 ASCII；正文用简体中文；
- 一张表能说清的事，不写成长文；需要什么写什么，不抄旧文档；
- 链接用相对路径，改完跑 `python tools/文档/check_docs.py`；
- 当前文档不引用归档文档的具体段落；要指归档，只给归档入口；
- 不写作者自己的部署状态（哪台机器、什么域名、端口、绝对路径）——那对读者没用，还会过期；
  确实跑过就写成**验证证据**：「用一台 4 核 4G 的云主机实跑过」，给的是它能跑、要多大机器，
  不是我的机器长什么样。

## 决策与未定

- 定下来的写进 `决策记录.md`，一条一个主题，写清决定、理由、被否掉的方案；
- 还没定的写在 `事件状态与读取.md` 的“未定”一节，随设计文档更新。

## 归档

- 归档目录里的文档保持原样，不改链接以外的内容；
- 归档入口是 `99_归档/v1/归档说明.md`，旧文档地图 `99_归档/v1/README.md` 不动。
