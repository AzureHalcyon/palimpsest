# 文档规范

本文件规定本项目有哪些文档、各自装什么、以及每条记录必须带什么。

## 一、文档分工

| 文档 | 装什么 | 不装什么 |
|---|---|---|
| `README.md` | 方向（它是什么、目标、核心部件）＋ **一段现状**（能跑什么、还没做什么） | 详细过程、历史 |
| `git log` / `docs/决策记录.md` | 每次改了什么、为什么（⛔ 不再维护单独的 CHANGELOG） | 设计论证 |
| `docs/设计.md` | 当前有效的设计 | 被推翻的旧版（进归档） |
| `docs/术语表.md` | 需要消歧的词 | 普通词汇 |
| `docs/文档规范.md` | 本文件 | —— |
| `docs/参数账.md` | 每个参数的取值与依据 | 与参数无关的结论 |
| `docs/记忆层.md` | **展开篇**：记忆层的架构与归档流程（§1–§12）＋ **训练的整理**（§13–§26） | 总设计的结论（那是 `设计.md`）· 参数值（那是参数账）· 效果读数（那是实验记录） |
| `docs/连接-工作记录.md` | **"连接怎么建立"的工作记录**：迭代线 · 训练的对象是连接 · 材料的作用 · 信号 · 赌在哪 · **论文线（已逐字核实）** · 原文 ↔ AI 靠什么连接 | 已定的设计（那在 `设计.md` / `记忆层.md`）· 参数值（那是参数账） |
| `docs/实验记录/` | 每轮实验：预注册、结果、结论 | 事后改写（**一律不改**） |
| `docs/待决.md` | 还没定的、卡住什么 | 已定的（那是设计） |
| `docs/决策记录.md` | 定下来的方向性决定，含被否掉的方案 | 参数值（那是参数账） |
| `docs/常驻记忆.md` | 开场那一段（常驻）的设计与源码事实 | 通用设计（那在 `设计.md`） |
| `docs/实现与框架对照.md` | 代码与设计的差异、已知缺口 | 设计本身 |
| `docs/语料评估.md` | 外部语料的出处、许可、读数 | 语料数据本身（不进仓） |
| `docs/开工清单.md` | 开工时的检查项 | 已完成的历史 |
| `docs/README.md` | **文档地图**：先读哪几份、冲突时以谁为准 | 设计内容 |
| `memory/README.md` · `app/README.md` · `tools/README.md` | **各目录的入口**：能跑什么、怎么构建、有哪些脚本 | 跨目录的设计 |

归档目录 `99_归档/` 放被取代的旧版：**原样存，不改**，文件名带日期。

## 二、通用规则

**一条记录的判据**：它能不能回答"**凭什么**"和"**谁验的**"。
答不上来的，就不该写成结论。

1. **每个断言都要能指回出处**：实测的数、推导的算式、用户的原话，或外部文献。
2. **不确定的要显式标出**，不许藏在陈述句里。宁可写"未复现"，不要写得像验过。
3. **记录一律不改**：实验记录写下就是历史。后来的订正**另起一条**，指向被订正的那条。
4. **否定的结果照记**。它比成功的结论更省时间——它挡掉一整类重复劳动。
5. **方法进代码，不进文档**。给运行时读的文档会腐化，而且会自己长出任务。
6. **超过一条经验的错，要升成规则**。同一个错换个介质再犯，说明该写规矩了。

## 三、依据等级

每个数值、每条结论，都要标等级。**一行都不能漏**。

| 标记 | 含义 | 附带要求 |
|---|---|---|
| 【实测】 | 跑过对照，量出了数 | 写清样本量、口径、日期 |
| 【推导】 | 从设计原文或实测数**算式推**出来 | **写出算式** |
| 【假设】 | 没有数据，只能假设 | **必须显式写出，不许藏** |
| 【护栏】 | 不是调出来的值，是成本或稳定性的上限 | 允许"从没被碰到"，但要说明为什么 |
| 【未复现】 | 来自别处、本机没验过 | 写清出处；**不许当结论用** |

## 四、`docs/参数账.md` 的格式

开头固定放一段依据等级表（同上一节），然后按**功能分节**（读取、时间、训练……），
每节一张表：

| 参数 | 值 | 为什么是这个数字 | 等级 |
|---|---|---|---|
| `名字` | 值 | 依据；算式；样本量；口径 | 【实测】 |

各节的写法要求：

- **用户定的参数**：引**用户原话**，并给出来源。这类值不是算出来的，是要求的。
- **不调的常量**：也要写清出处（为什么是它，而不是别的）。
- **复算入口**：每节末尾给**能跑的命令**。给不出命令的，就写"**不可复算**"——
  并且这一节里的数只能当**历史记录**用。宁可承认不可复算，也不要留一个跑不通的命令。

四类必须**单独登记**的东西：

| 类别 | 放在哪 | 为什么 |
|---|---|---|
| **已删的旋钮** | 参数账保留一行，标"已删"，写清**被什么取代** | 防止后来的人再把它加回来 |
| **否定结果** | 该参数那一行里标出，写清**它在什么情况下不管用** | 值的旁边就是它的边界，最有信息量 |
| **不在生效路径上的参数** | **单列一节** | 否则它"既不生效、又不进账"，会无家可归；下一个人会以为它在起作用 |
| **还没落实的** | **单列一节**，照记 | 别装成已解决 |

## 五、`docs/实验记录/` 的格式

命名：`第N轮-主题-报告.md`。每轮至少含四块：

1. **预注册**：跑之前写下预期与判据。**跑完不许改**。
2. **做了什么**：口径、样本量、参数、以及**精度**（读数能到几位）。
3. **结果**：数字。凡是模型跑出来的，**必须写出 `max_tokens` 与空回复数**。
4. **结论与订正**：结论要标等级；**被证伪的预注册要显式写出"我错了"**。

## 六、`docs/决策记录.md` 的格式

每条决定一段，四行：

```
决定：定了什么。
理由：为什么。
被否掉的方案：还考虑过什么，为什么不选。
能否回退：能退到什么程度，退的时候要改哪里。
```

"被否掉的方案"不许省。后来的人最容易重提的，就是那些被否掉的东西。

## 七、`docs/待决.md` 的格式

| 事项 | 卡住什么 | 不卡的部分可以先做什么 |

一条待决如果**不卡任何东西**，就不要记在这里——它不是待决，是"以后再说"。

## 八、引用与命名

- 文内引用：`docs/参数账.md`；设计内的章节引用：`设计 §N`。
- 时间：绝对日期（`2026-10-08`），不用"昨天""上一轮"。
- 外部材料：给链接或出处；引自文献时给出年份与刊物。
