## 1. 单位：事件

- **轮不是单位。** 一句话可以是一轮，五段话也可以是一轮；长短、信息密度、
  能不能表示一件事，全都不定。
- **节点不是单位。** 节点要标"这一处是什么"，而没有可靠的人来标：
  让对话里的模型边说话边标，标出来的是句子，不是记忆；
  让归档时的模型事后补判，正是被否掉的那条路；用规则标，标不出"要紧的那样东西"。
- **事件是单位。** 范围由对话中维护的状态给出（标题连续相同的轮段）；名字就是那行标题；
  向量拿事件原文算；时间、场、说话人底片里本来就有。**没有第二层要标。**

"是不是一件事"是**对话进行中维护的状态**，不是存下来的属性：模型意识到换了一件事就换，
归档只读这个状态留下的痕迹。详见 [`决策记录.md`](决策记录.md) 2026-10-19
「事件状态在对话中维护，"是不是一件事"不落库」。

## 2. 结构：事件是网里的一个点

事件不止一层，但层不是"路径"，是**网**。

- 一个事件是网里的一个点，有自己的名字；
- **"包含"只是边的一种**（属于 / 包含），不是结构；
- **边只分两种**：`属于`（包含关系，走起来便宜）、`相关`（其余一切，贵一点）。
  因果、同一个人、同一类事这些先不建——要么能用共享词和时间算出来，要么等重放自己长出来；
- 跨主题的关联也是边：`装修` 和 `她妈要来住` 如果其实有关，就直接连一条，⛔ 不硬把一件塞到另一件底下；
- **树是网的特例**：只有"属于"边、且无环的时候，网就是树。所以树能表达的，网都能表达。

时间与场次是**机械边**（同一场、相邻）——"同一个晚上"不需要模型说。
语义的关联由模型在对话里点出来：它本来就在判断"这两件事有没有关系"，
注意到就记一笔，没注意到就不记。

状态因此可以是"当前这一件"，也可以是"当前这几件"——两条线并行的时候，
网天然能挂住，不用先决定谁是谁的父。

## 3. 状态：用工具维护

### 为什么是工具，不是 CoT 首行

| | CoT 首行 | 工具 |
|---|---|---|
| 层级 | 字符串约定 | 参数是数组 |
| 校验 | 没有 | 有返回值 |
| 失败 | 静默 | 能报 |
| 留痕 | 混在思考里 | 每轮一条记录 |

CoT 里写一行字，是把器官的功能塞进语言里：没有返回、不能校验、层级靠字符串约定、
失败了也没人知道。工具不一样——有参数、有返回、有失败，模型能看见自己把状态设成了什么，
这就形成了闭环。**器官要能回话，不然它只是个日志。**

### 契约

```
事件(mode: "继续" | "子事" | "回" | "换事" | "接旧" | "关联",
     name?: string, event?: string, because?: string,
     parent?: string, parents?: string[])
→ { "事件": "e-3f9a1c2b7d4e", "名": "她妈要来住", "mode": "子事",
    "stack": ["e-a1b2c3d4e5f6", "e-3f9a1c2b7d4e"], "related"?: "e-9c8b7a6f5e4d" }
```

- 事件 id 是不含意义的随机短串（`e-` ＋ 12 位十六进制），不带时间、不带顺序；
  先后看 `created` 和单调的 `seq`，⛔ 不按 id 排序；旧 `e-0001` 仍是合法的不透明 id，
  不迁移；
- **继续**：还是上一件，不用给名字；
- **子事**：进到当前这件事里的一个小节；`parent` 指到上一层（不写就挂当前），
  `parents` 列还同时属于别的根；
- **回**：小节说完，退回上一层；
- **换事**：换到另一件不相干的事；
- **接旧**：接着以前某件事说；`event` 给 id（或名字），`because` 写依据
  （同一个对象、同一个人、同一段时间）；
- **关联**：只加一条 `相关`，不换当前这件事。

栈只是**光标**（现在在哪），不是数据：数据是网，一个子可以挂多个父，一个子也能连别的根。
返回里给出现在在哪一层、可不可以回；同名只提示事实（“已有同名 e-xxxx；同一件用接旧”），
不替模型判“同一件”。失败要明说，不默默收下。
⛔ **系统不替模型连**：不自动加边。**每个工具返回都带状态快照**——当前事件、路径、
`属于` / `子件` / `相关`；模型看着这张状态自己决定接不接。

### 顺序

每轮**先定状态，再找线索**：先 `事件(mode=…)` 说清"正在说哪件事"，再按关键词回忆。
反过来就是先查再想，读取又变回查找。

## 4. 读取

### 线索

> **线索 ＝ 系统手里的状态 ＋ 模型给的关键词（2–5 个）。**

- **不用整句**：整句进检索，就是拿一句话去和文本算相似度，读取降级成"查找"；
  关键词进图，才是落点。
- **关键词落在事件上**（标题与原文），不落在标签上——没有标签这一层。
- 几个词同时命中同一个事件，它就更亮（合取码），但**不是严格全命中**：
  命中三个最亮，命中一个也有一点光。
- **时间用具体日期**：模型把“上次”“去年”换成具体日期，用 `after` / `before` 过滤；
  ⛔ 不把相对时间词塞进关键词。
- 模型可能不知道库里有什么词，第一次落空很正常——这就是"话到嘴边"。

### 流程

1. **起意**：模型决定要回忆什么；
2. **落点**：关键词落到图里，命中事件（标题、原文、时间）；
3. **事件内补全**：种子所在的事件靠绑定把整件事点亮（廉价，不衰减或衰减很小）；
4. **事件间扩散**：整件事亮了之后才沿关联往外走，每步衰减，有步数和节点数预算；
5. **竞争**：按事件大小归一后排序，否则大事永远赢；相似事件互相抑制（模式分离），
   用状态（时间、在场的人、当前话题）来分，不是只比内容像不像；一次一个赢家，
   备选只给标题和日期；
   **网络里也能出赢家**：被至少两个不同种子汇聚、且和线索有最低相似（余弦 ≥ 0.5）的件，
   即使不是种子也能赢；巩固/可及只做微调，⛔ 不能压过直接命中；
6. **取原文**：赢家的元素按原文顺序取出，带时间和说话人；
7. **重建**：按原位铺开（机械）；
8. **编写**：写成一段第一人称回忆（只写，不选）；
9. **回话或再查**：不够就换个线索再查；这次查可以**接着上次的激活**继续，不从零开始。

### 在对话里的位置

| 动作 | 何时 | 返回 |
|---|---|---|
| **轻查** | **每轮一次** | 候选：标题、日期、命中词（几行） |
| **展开** | **按需**，有候选像的时候 | 那一件的重建片段（按原文顺序） |
| **编写** | 只用展开过的 | 一段第一人称回忆 |

- 进入上下文的**只有编写那段**；候选与展开是工具结果，⛔ 不进上下文；
- **判定取消**：模型选不选就是判定——不选就不展开、不编写；
- **顺序不是死的**：默认先状态后找；也可以先找再定状态（`接=id`）；
  这一轮**最后一次状态调用为准**——找不改变状态，状态才改变状态；
- 一轮最多展开 **2** 次；第二次用新关键词，或接着上次的激活。

轻查每轮都做，是因为漏查的代价是**编造**，比多几行工具结果大得多；展开才是有成本的。
若实测证明模型自己会查，再放松。

### 重建的定义

> **重建 ＝ 把已经选定的那一件事，按它本来的顺序和位置放回去。**

- 包含：原文、时间、说话人、先后顺序、同事件内的元素关系；
- 不包含：选哪件（在上游由竞争决定）、概括、改写、评价。

编写接收到的输入是"已经摆好的一整片"，所以它没有选择权——它拿到的就是结果。
"编写只写不选"不是一条额外约束，是这条定义的推论。

编写读的范围也是上游给的：按线索选出的片段，加上最近一段，最多 8 段 / 2000 字；
⛔ 不整件读入，原文不动。这样原文再长，编写看到的也不膨胀。

### 认领旧事件

**靠再认，不靠重建。** 模型不需要先把旧事想清楚——那是重建，贵。
给一个**够认**的短形式就行：回想和再认在脑里是两套，再认便宜、也更可靠。

三步：

1. **关键词 → 候选**：返回几件（标题、日期、命中了哪几个词）；
2. **展开一件**：模型觉得像，就点名看这一件的详情（一小段，够它辨认同一对象）；
3. **认领或新建**：认出来就 `接旧(id, 因为=…)`；认不出就新建。

`因为` 必须具体：同一个对象、同一个人、同一段时间。给不出具体的，就不是认领，是眼熟。
**只眼熟不算**——眼熟是虚假记忆的来源。

系统只给事实（哪几件命中了哪些词），⛔ **不给"它们可能是同一件"这种结论**——
给结论就是拿相似当同一。

默认：**认不出就不认领**。宁可多一件，不可错并一件——多出来的以后还能连，并错的以后分不清。
认领是**加一条边 / 挂一个片段**，不是把两段文本压成一份；认错就剪那条边，内容不动。

### 查不到

给"接近的"两三件（标题、日期），明说"不确定是不是这个"，不给一个空的"无"。
脑里是"话到嘴边"——有东西，只是这次没钩上来。

## 5. 与脑的对应

把大模型看作一个**残缺的高智商大脑**，我们补的是它缺的器官：

| 缺的 | 补的 |
|---|---|
| 工作记忆 / 海马对"当前这件事"的维持 | 事件状态工具（每轮一次，带名字与关联） |
| 皮层里的长期痕迹 | 底片 ＋ 事件图（事件是单位，边是算的） |
| 睡眠里的巩固与剪枝 | 归档时的离线作业（重放、衰减、剪） |
| 线索进网、模式补全、竞争 | 回忆工具（关键词落点、扩散、竞争） |
| 把想起的东西说出来 | 编写模型（已有） |
| 稳定的人格 | 参数层（LoRA 一类，第二阶段） |

依据见 [`研究/REM-SWS-机制参考.md`](../../研究/REM-SWS-机制参考.md)：选择发生在清醒时，
睡眠只巩固被标记的——事件状态就是清醒时的那个选择。

## 6. 归档因此变成什么

- **时机**：归档是一个**手动开关**，不会自己跑；每轮的状态记录在那一轮就落盘，⛔ 不等归档。
- **不再做**：按轮切 cell、提候选、粗筛细筛、判"并进 / 新建"、建"件"、建"组"。
- **要做**：把事件记下来（状态给的）、把边算出来（共现 / 共享词 / 时间相邻）、
  巩固（重放、衰减、剪）。
- **剪**：弱边衰减、强边留下；剪的是边和权重，⛔ 不删事件、不删原文。
- **剪的判据**：被多少**不同的起点**共同走到（结构冗余），不是相似度、不是使用次数。
  经过枢纽没关系——枢纽本来就该被走到，区分靠枢纽周围那几条岔路。
- **半加成**：每轮重放先**镀**——被至少两个不同起点走到的边 `+0.02 × 起点数`；
  再**全局削**——所有非结构边 `×0.87`；低于 `0.12` 剪掉。
  **主干也会被削**，但它每轮镀得更多，削到见底时还连着；细边没镀过，只被削，最后剪掉。
  `属于` 是结构，保底 `0.15`，⛔ 不剪。

### 起点从哪来（标记）

| 标记 | 怎么来 | 备注 |
|---|---|---|
| 新异 | **事件切换**：新开一件、名字没出现过 | 不需要额外的误差读数 |
| 重复 | **接旧**（认领历史事件）、同名再现 | 接旧可靠，同名是弱信号 |
| 奖励 | 手标（用户说"记住" / 点赞） | 只记一次；重复说算重复 |
| 唤醒 | 暂不做 | ⛔ 不拿感叹号当情绪 |

⇒ 原来那步 token 级误差读数（②）**不再用于标记**，只留作调试。

### 重放怎么走

- **沿已有的边走**（属于 / 相关）；
- **沿内容重合感应**：事件由内容组成（人、物、时间、地点、说法）。激活一件事，
  会流到它的内容上；同样的内容出现在哪些旧事件里，那些旧事件就被带亮。
  **相似只是"内容重合"在粗粒度上的近似**，⛔ 不另设一条"相似边"；
- 粗细两档：粗＝整件向量（便宜，先筛）；细＝词 / 特征（准，能说清为什么亮）；
- 被一起点亮的一对，记进**候选对表**；攒够门槛才落成 `相关` 边，否则衰减；
- 常见词（"她""今天"）要按稀有度加权，否则人人相连。

### 强度两列

| 列 | 回答什么 | 怎么变 |
|---|---|---|
| **巩固** | 有多牢 | 被多少不同起点走过（重放支撑） |
| **可及** | 最近多容易被想起 | 真的被取用时加一点，半衰期短 |

检索排序以直接命中为主；巩固、可及只做微调（`1 + 0.2×巩固`、`1 + 0.1×可及`），
⛔ 不能把老件放大到压过直接命中。两列都挂在事件和边上。
⛔ 可及只按"真的取用"算，不按"扩散经过"——经过太廉价，会把整片邻居都喂肥。

## 7. 与现在代码的差距

| 现在 | 新方向 |
|---|---|
| 按轮切 cell | 事件是单位（状态给的） |
| 候选 → 粗筛 → 细筛 → 判"并进/新建" | 不需要 |
| 件 / 组 | 不需要 |
| `recall` 取 top-k 余弦 | 关键词落点 → 扩散 → 竞争 |
| 自然语言查询 | 关键词（2–5 个） |
| 编写紧跟取件 | 编写在重建之后（只写） |

可复用的：底片、原文、时间与说话人、编写模型、旧场回看、势、共现边。

**写法**：新链路放在仓库根目录的 `memory_v2/`，分 `core / store / read / consolidate / chat` 五层，
⛔ 不混进 `archive/v1/memory/`，⛔ 不复制旧代码——看清逻辑后重写；基础设施（模型调用、凭证、提示词文件）
可以直接 import，逻辑（状态、图、读取）重写。旧层不删、不改，原地保留。
规矩见 [`CODE_STYLE.md`](../../../memory_v2/CODE_STYLE.md)。

## 8. 还没定

- 工具：一个还是两个、是否每轮都调、失败怎么报、叫什么；
- 关键词：要不要带类型（人 / 物 / 时 / 地 / 动作）、几个、同义词怎么办；
- 扩散：步数、阈值、预算；竞争：归一化方式、抑制强度；
- 边：要不要记"为什么"、名字解析不了怎么办；
- 事件标题的质量：写得太泛（"聊天""日常"）检索就废；
- 旧数据：没有状态记录，只能靠重放旧对话生成。

## 9. 怎么验

- **先手动调用，人看输出**：切点、候选、展开、编写、认领的"因为"——一条条读，
  不对就当场看出来。这是最直接的一层，后面几层是它不够用时才加的；
- 不够时再加：**可复算**（同一份底片重跑，结果一致）、**切点**（人工抽 10–20 个）、
  **认领**（人工小集，真值只在这里）、**回忆**（重放旧对话，题目要能证伪）、
  **下游**（真实对话里的纠正与追问）；
- 原则：真值从**人或对话**来，⛔ 不从系统自己的输出来；小样本、可证伪；看错在哪，不只看分数。

配套：查一查页面应该变成这个"手动调用、看输出"的地方——选事件、跑轻查 / 展开、
看候选为什么亮、编写用了哪几件。⛔ 不是再做一个指标面板。
