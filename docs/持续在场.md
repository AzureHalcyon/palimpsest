# 持续在场

状态：设计草案，未实现。第一版只改推理，不训练。

本文提出一种把请求-响应的模型调用改造成不停机循环的设计：模型始终处在同一个循环里
（运行或挂起），对外输出只是其中一步；上下文按时间线处理，窗口内的文本保持完整，参与
注意力计算的 K/V 按年龄从稠密到稀疏，离开窗口的内容直接归档。下文依次说明目标、依据、
机制、验证与备选方案，使读者只读这一页即可了解设计动机与取舍理由。

## 1 目标

### 1.1 问题

当前形态是请求-响应：模型被调用一次，生成一段文本，结束。由此产生三个后果。

1. **跨调用没有状态。** 两次调用之间不存在任何延续；所谓连续，是多次生成靠上下文拼接出来的
   表象。
2. **多步执行只在单次窗口内成立。** 窗口一旦填满，过程必须中断，或者丢弃内容。
3. **输出即终点。** 模型不会在给出回答之后继续处理；一轮结束，过程结束。

### 1.2 设计目标

本层的目标可以逐条检验。

| 编号 | 目标 | 检验方式 |
|---|---|---|
| G1 | 过程常驻：没有"结束"，只有挂起与唤醒 | 挂起后能被事件唤醒并继续；无事件时不计算 |
| G2 | 状态有界：每个计算拍的代价与历史长度无关，只与窗口长度成正比 | 计算拍耗时与显存随拍数保持平稳 |
| G3 | 说话降为一步：输出不再是终点 | 存在连续的、不含输出的步 |
| G4 | 旧的自发变糊：越旧的位置参与计算越少，且单调 | 同一位置随年龄增长，所在带的保留密度单调下降 |
| G5 | 窗口外即弃：离开窗口的内容不再参与计算 | 窗口外内容不可被注意力访问 |
| G6 | 打断可续：打断后可从当前窗口重新开始 | 恢复只需重新装入 sink 与窗口文本 |
| G7 | 不改权重即可验证 | 第一版无训练、无权重修改 |

### 1.3 非目标

- 不解决长期记忆、跨会话恢复与人格；这些属于别的层，本文不讨论。
- 不追求无限输出 token。目标是循环不停，不是生成不停。
- 不提供"想什么"的动机。本层只提供循环与上下文处理；为什么继续想，不在本文范围内。
- 不讨论哲学意义上的"思考"。可检验的只有一件事：多步执行的质量能否跨过稀疏边界。

## 2 依据

本节回答"为什么这样想"。每条给出理由与推论，而不只是立场。

### 2.1 人记不住三小时前的思维

人能够保留的是结论、语气与印象，而不是推理过程本身；需要细节时，通常是重新想一遍，
而不是回放原始过程。这一事实对设计有两个含义。

- 旧内容变糊是合理的，不是缺陷；因此不必追求完整保留。
- 需要细节时的正确动作是重新读、重新想，而不是把旧位置还原。

### 2.2 细节只能存在于此刻

据此，上下文被建模为一条时间线，满足四条性质。

1. 分辨率从后往前**单调下降**：越旧的位置越粗。
2. 旧位置只能变短、变模糊，不能被展开。
3. 需要细节时，重新读取并重新思考，产生新的一段，接在时间线末尾。
4. 单调的是**位置**，不是内容：任何时刻都可以把完整内容读进"现在"，但它进入的是现在，
   不是旧位置。

一句话概括：**细节只能存在于此刻，过去永远是摘要。**

### 2.3 重要性不是规则，是频率

如果旧内容只能变糊，那么"什么留下来"就不应由一条人为规则决定。常被重读、重述的内容会自然
在末尾反复出现，衰减得慢；无人触碰的内容会自然退掉。因此本设计不给任何内容"钉住"。
被钉住的内容实际上是记忆，不是思维。

这条推论同时解释了为什么不需要账本、指针或保留区：三者都会把记忆塞回思维。

需要区分的是：频率不改变剪枝的保留权重。本层剪枝只看年龄；频率通过"重述"改变新近度——
重要的内容被反复重新写在末尾，因而留得久。所以本层不需要重要性规则：频率只通过重述起作用，
不进入剪枝的权重。

### 2.4 说话只是其中一步

循环不结束；挂起是暂停，而不是终止。由此有三条推论。

- 用户消息是注入流中的一个事件，不是一次请求；对话从回合变为流。
- 输出与生成解耦：任何一步都可以说，也可以不说；多数步不说。
- 状态必须记录"已经说过什么、对方现在知道什么"，否则模型会重复自己，或把讲过的事当作
  新发现。

具体到动作，每一步只产出四类之一：继续想、调用工具、说、挂起。"说"与"调用工具"同级，
不再是循环的终点；正文因此降为一次动作调用——模型在某一步选择"说"，说完继续。这是
"思考—调用—思考—调用"的循环得以拉长的关键：输出不再承担"结束"的语义。

模型也可以主动挂起：写下恢复点，暂停，等事件到达再继续。挂起是循环的一个动作，不是终止；
它使"不为了输出而输出"在实现上有落点。

### 2.5 思维与记忆解耦

思维是循环，记忆是循环之外的东西；循环通过调用获取记忆，不把记忆放在循环里。本层只负责
循环与 sink、窗口内的上下文，记忆的内部结构不在本文范围内。

这条解耦的后果是：**sink 与窗口就是全部工作状态。** 不需要跨窗口的持久状态，不需要账本，
也不需要指针。打断后恢复只需重新装入 sink 与窗口文本。

可以用"思维是处理器、上下文是缓存、记忆是外部存储"作比喻，但仅是比喻，不应照处理器的结构
设计。实际差别至少有三条：上下文很大（8k–32k，不是几百 token 的寄存器）；模型是随机的
（一拍可能写错）；没有时钟与原子性（tick 需由事件或定时器驱动，一拍可能只写了一半）。

### 2.6 为什么压缩落在 K/V 而不是文本

文本层压缩有两种代价：其一，需要模型反复概括，损失随压缩次数累积；其二，压缩后的文本是
被改写过的叙述，模型读到的不再是原话。

连续表示有两条路径。

| 路径 | 表示所在空间 | 冻结模型能否直接使用 | 需要改什么 |
|---|---|---|---|
| 输入侧：文本换成向量再输入 | 词嵌入空间 | 不能；未训练的向量对模型是噪声 | 编码器与模型适配，均需训练 |
| K/V 侧：模型读完文本后产生的 K/V | 模型自身的注意力空间 | 能；K/V 本来就是注意力的输入 | 只改注意力的 K/V 管理 |

本设计选择 K/V 侧：窗口内的文本保持完整，压缩只发生在参与计算的 K/V 上。如此，"模型如何
计算"不变，改变的只是"给模型算什么"。

### 2.7 为什么先剪再算

若先完整计算、再剪最终缓存，各层已经用全量 K/V 算出了表示，只有最后一层看到稀疏；
表示与计算不一致。正确做法是每层投影出 K/V 之后先剪，再运行原来的注意力，使所有层看到
同一份稀疏。

注意力算子本身不变，模型只是拿到更少的 K/V。被剪掉的 token 并非没有参与计算：它自身的
query 仍对更早的保留项计算，只是此后没有 query 再看到它。这正好对应"读过，但不留在将来"。

### 2.8 为什么只剪不并

K 在进入缓存前已按位置旋转（RoPE）。把不同位置的 K 取平均，所得向量不对应任何合法位置，
注意力分数会失真。合并需要改变旋转的应用方式，属于架构改动。

剪枝保留原 token 的 K/V 与绝对位置，RoPE 不受影响。因此第一版只做剪枝，不做合并。

合并并非不可行：FADE 一类做法先 un-RoPE，合并后再按新位置重新旋转；代价是必须改旋转的
应用方式。第一版不做，留作后续。

### 2.9 为什么按年龄带降密度

若在已保留的样本上继续抽样，总条数仍随窗口线性增长。按"带"降密度可以避免这一点：
第 i 带的密度为 1/2^i，带宽为 2^(i-1)·W0（i≥1），每带约保留 W0/2 条。总条数约为

    W0 + (W0/2)·log2(W/W0)

随窗口对数增长，而非线性增长。sink 的长度另计，不参与该式。

sink 是序列绝对开头的固定前缀，不随窗口滑动：每次输入都是"同一段 sink + 当前窗口"。
它承担两件事：一是注意力汇，若开头被裁掉，整体容易发散；二是承载基础约束与设定，
使这些内容在窗口滑动时始终以全密度出现。sink 的位置固定在序列开头，不参与年龄带降密度。

### 2.10 为什么每次剪得不一样

固定保留集会让某些位置永远不被看到。每次前向用随机偏移重新抽样：第 i 带只保留满足

    (pos - offset_i) mod 2^i == 0

的位置，offset_i 每次前向更换。密度不变，但每个位置在多次前向中都会轮到，期望上不会被
永久遗忘。

抽样以"一次前向"为单位，不以 token 为单位：同一次 prefill 与 decode 内保留集固定，否则
过去的 K/V 会在生成过程中变化。代价是同一输入在不同前向中结果会有差异；该方差也需测量。

这意味着每次前向看到的过去并不完全相同：稀疏区的可见集合会在两次前向之间变化，模型对
同一段旧内容的理解可能随之改变。从模型的角度看，稀疏区的两次前向接近于两段不同的历史；
稳定的只有序列开头的 sink（基础约束与设定）与最近的密集区（当前线程）。这是该设计的固有
代价：旧内容在窗口内是被抽样的，而不是被完整保留的；它换来的是覆盖轮转与有界成本。

### 2.11 为什么窗口外直接丢弃

窗口与 sink 就是全部工作状态。若保留跨窗口的 K/V，会引入前缀不一致问题：同一 token 在
前缀不同时算出的 K/V 不同，拼接两套 K/V 会得到互相矛盾的状态；此外还需管理跨窗口的合并
与恢复。

因此窗口外内容直接丢弃，归档是唯一去处；循环不自动读取归档，除非显式调用。恢复只需重新
装入 sink 与窗口文本，从它们重算，简单且确定。

### 2.12 与稀疏注意力的关系

DSA（DeepSeek Sparse Attention）的做法是：索引器为历史 token 打分，只取 top-k 参与精细
注意力，复杂度由 O(L²) 降为 O(Lk)；训练需先密集预热索引器，再做稀疏训练。其选择依据是
相关性，且选择可随步变化，不具单调性。

本设计只借"稀疏"这一思想，选择依据改为年龄：不做索引器，不按重要性多留，保留密度随年龄
单调下降。二者的差别，是"过去还在，只是此刻不看"与"过去永远是摘要"的差别。以后可以在
年龄带之内再叠加相关性筛选，但属于下一步。

Lethe 的 RASR 已经在年龄之外叠加了演化中的注意力相关性，可以作为叠加时的参照；本设计
第一版保持纯年龄。

## 3 机制

### 3.1 循环与动作

循环是一串顺序单元，不按固定时长切分。一个单元称为一拍：一次动作加它的产物。拍的时长由
动作决定——想可能是几百 token，调用可能是几秒，挂起为零。抢占只在拍边界发生。

一拍大致归为四类动作（暂定，具体动作集待实践）。

| 动作 | 作用 | 是否对外 |
|---|---|---|
| 继续想 | 在窗口内推进一段推演 | 否 |
| 调用 | 执行工具，结果写回窗口 | 否 |
| 说 | 向用户输出一段正文 | 是 |
| 挂起 | 写恢复点并暂停；事件到达后从恢复点继续 | 否 |

"说"与"调用"同级，都是循环中的一步；它不是终点。正文因此降为一次动作调用：模型在某一
步选择"说"，说完继续，而不是"答完即结束"。是否把"挂起"与"等"分成两个动作（等某个事件
与无限期挂起），留待实践决定。

挂起不是结束：它把"现在到哪了、下次从哪接"写进窗口，运行时随即停止计算；用户消息、工具
返回、时钟任一事件到达后，循环从恢复点继续。空闲时不跑前向，模型也不必为了产出而产出。

窗口需要能区分"想过的"与"说出去的"，否则模型无法从转录里知道自己上一拍做了什么。最小
约定待定；一个自然的候选是给每拍加类型标记，例如 `[T]` 推演、`[S]` 说、`[C]` 调用、
`[R]` 结果、`[U]` 用户、`[P]` 挂起；图例若采用，随 sink 固定，不随窗口滑动。标记由
运行时按动作渲染、模型只输出动作与内容，只是倾向；具体格式待实现时定。

`[S]` 与 `[T]` 一样随年龄衰减（方案 A）。模型可能忘掉自己说过的话，重复由用户纠正；
这是接受的代价。若实践里重复严重，再考虑给 `[S]` 单独一档保留率（方案 B）。

每次输入 = sink + 窗口（按约定的格式拼接）。窗口保存所有拍的内容，包括没有说出去的推演；
因此"窗口就是全部工作状态"指的是循环的状态，不是对外可见的对话。

单拍推演应有内容上限，量级建议 128–512 token；具体值与是否硬截断待实践。上限既是成本
边界，也是抢占与落盘的粒度。

### 3.2 每层算法

```
1. 正常投影出 K / V
2. 按年龄带决定保留哪些位置：
   固定 sink（序列开头）  全留
   最近 W0               全留
   再往前一带（W0）      密度 1/2
   再往前一带（2W0）     密度 1/4
   ...
3. 用保留的 K/V 跑原来的 attention；causal mask 按原始位置重建
```

causal mask 不能沿用压缩前的列索引；它必须按原始位置生成：query 位置大于等于 key 位置时
可见。

### 3.3 保留索引

保留索引只依赖位置，不依赖层，也不依赖内容。因此每次前向只需计算一次，所有层共用。

### 3.4 窗口与归档

窗口长度固定为 W，输入为"固定 sink + 窗口"。每个计算拍从 sink 与窗口文本重算，不保留
跨拍的 K/V；挂起不计算。离开窗口的内容丢弃并归档。窗口内文本完整，不做摘要。重算的代价
见 3.5。

### 3.5 成本

计算拍从 sink 与窗口文本重算，不保留跨拍的 K/V；挂起拍不跑前向，空闲代价近零。记 d 为
隐藏维，W 为窗口长度，k 为保留条数，t 为本拍生成的 token 数；下列均为单层，乘层数 L 即为
全模型。

- 投影与 FFN：每层 O(W·d²)。这部分不因剪枝而减少：所有位置都要先投影出 K/V，前向仍要
  计算每个位置的隐藏状态；
- 注意力：每层 O(W·k)。剪枝减少的是这一项；
- 解码：每生成一个 token，O(d²) 的投影与 FFN 加 O(k) 的注意力；
- KV 显存：每层 O(k·d)，与历史长度无关。

因此每个计算拍的总代价与**历史长度**无关，与**窗口长度 W**成正比。窗口固定，所以计算拍
的代价有界，但不是常数：预填充 W 个 token 是主要开销。在 4B 级模型、8k 窗口上，预填充为
秒级，这决定了计算拍的频率上限；挂起不占这份成本。剪枝节省的是注意力与 KV 显存；W 较小
时 FFN 占比更高，剪枝收益有限，随 W 增大才显著。

不采用增量复用跨拍 K/V，原因见 2.11：窗口滑动会改变前缀，复用会得到不一致的状态。

### 3.6 训练（可选）

第一版不改权重，直接在推理中剪枝；模型未在这种稀疏度上训练，质量必然下降，先测下降幅度。

若需要训练：训练时用布尔掩码，推理时用物理剪枝，两者语义相同，共用保留索引。目标仍为
next-token；剪枝在环内进行，半衰期与偏移均随机化，使模型适应一族节奏而非单一配置。

## 4 验证

### 4.1 待验证的假设

- H1：按年龄带剪枝后，模型仍能完成需要长距离信息的任务。
- H2：随机偏移抽样优于固定保留集，因为后者会造成永久盲区。
- H3：质量下降是渐进的，且集中在早期约束与长距离指代，而非全面崩塌。

### 4.2 设置

- 底座：4B 级模型，4-bit 量化，窗口 8k，密集区 W0 = 2k；
- 实现：在注意力层按保留索引 gather K/V，再运行原注意力；一次前向一个抽样；
- 三组：不剪（基线）、固定保留集、随机偏移保留集；
- 任务：长对话中的早期约束、长距离指代、数字回查。

### 4.3 指标

- 任务成功率；
- 错误类型分布（早期约束、指代、数字）；
- 重复率与自相矛盾率；
- 每个计算拍的耗时与显存；
- 同一输入在不同前向中的输出方差（抖动带来的副作用）；
- 稀疏区可见集合在两次前向之间的重叠率（抖动幅度）。

### 4.4 判据

- 固定组与随机组必须同密度（同样的 k），否则差异可能只是可见条数不同；
- 随机组须多种子、按任务实例配对比较，并报告方差与可见集合的并集覆盖率；
- 必须是多拍序列：永久盲区只在时间上显现，单次问答区分不了覆盖轮转与单次运气；
- 加定点探针：把一个关键事实放在固定集永远保留不到的位置，N 拍后提问；随机组能恢复、
  固定组不能，H2 才成立；
- 若两组下降幅度接近且都很大，则说明该稀疏度超出模型可承受范围；应增大 W0 或进入训练；
- 若下降集中在特定错误类型，则据此调整保留策略。

## 5 备选与已否掉的方案

| 方案 | 结论 | 理由 |
|---|---|---|
| 文本反复压缩 | 否 | 同一段被反复改写，损失随次数累积 |
| 文本金字塔 | 降为归档备选 | 适用于归档与审计，不承担"让循环跑下去" |
| 输入侧连续表示 | 暂不采用 | 冻结模型无法直接使用，需训练编码器与适配 |
| K/V 平均合并 | 否 | K 已按位置旋转，平均后不对应合法位置 |
| 跨窗口持久 K/V | 否 | sink 与窗口即全部工作状态；会引入前缀不一致与状态管理 |
| 增量复用跨拍 K/V | 否 | 窗口滑动改变前缀，复用会得到不一致状态 |
| 账本 / 指针 / 保留区 | 否 | 把记忆塞回思维，违反解耦 |
| 无限输出 token | 否 | 目标是循环不停，不是生成不停 |
| DSA 架构 | 否 | 需训练索引器；8–32k 上无必要；只借思想 |

## 6 未定

- W0、sink 长度与内容（放哪些基础约束与设定）、每带条数：决定变糊的速度与稳定锚点，需要
  标定；
- 动作集：四类是否足够；"挂起"与"等"是否分成两个动作；
- 转录的标记与图例格式，以及标记由模型写还是由运行时写；
- 偏移抽样与伯努利抽样的取舍；偏移按前向更换还是按拍更换；
- 是否在年龄带内叠加相关性筛选（RASR 是参照）；
- 单拍推演上限的具体值（128–512 token 只是建议）；
- 挂起恢复点写什么：只写位置，还是写一句"下次从哪接"；
- 唤醒条件：只靠事件，还是也允许时钟（久无输入时自己继续想）；
- 训练是否进行、进行到哪一步（LoRA 或继续预训练）；
- 窗口大小与模型规模的匹配；
- 主动开口的门槛；
- 打断粒度：拍边界，或更细。
