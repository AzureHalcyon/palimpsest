# 流程框架（流水线 · 一页看全）

> **这是"看全局"的那一份。** 只写"**数据从哪来、经过什么、变成什么、落到哪**"。
> ⛔ 不重复论证 —— 理由与实测在别处（见 §七 索引）。

> **一句话**：**用户说的话 → 一段文本 → 大模型 → 她的话 → 底片 → 图 → 循环。**

## 一、流水线（按执行顺序，每一步带输入 / 输出 / 落到哪）

★ **编号用①–⑥（文档约定），但执行顺序是 ① ② ③ ⑤ ④ ⑥** —— 见 §二。

### A. 对话中（只读图，不改图）

```
[0] 对话开始 · 常驻记忆
    输入：手写的部分（她是谁 · 关系 · 工具 · 时间锚 · 上次的余温）
    做  ：回忆(线索 = 那一段)                        ← 见 [R]
    输出：一段文本
    落到：上下文的【开头】                            【占位：外部大模型 ＋ 提示词】

[1] 每一轮 · 刺激
    输出：刺激 ＝ 用户说的那句话

[2] 每一轮 · 她要查吗（第一阶段：她自己决定，tool_call）
    输入：刺激  或  她自己明确想知道的
    做  ：回忆(线索)                                 ← 见 [R]
    输出：件（k 个候选 ＋ 分数）
    落到：逐轮记录

[3] 每一轮 · 她说
    输入：上下文（含 [2] 的件渲染出的文本，若有）
    输出：她说的那句话
    落到：逐轮记录

[4] 每一轮 · shadow 路（离线）
    输入：同一线索
    做  ：采样 N 份候选
    输出：候选（⛔ 不许进池子）
    落到：存档

[5] 对话结束
    输出：底片 ＝ 整场原文（逐字）＋ 每轮 logprobs ＋ 指纹
    落到：存储（不可再生成）
```

★★ **注入冷却**（`Config.cooldown.turns` = 3）＝「**同一段原文**隔两轮才许再给一次」。
★ 它不是"这一轮不许查"，而是**别把刚说过的那段再说一遍** —— 需求来自"他连发几条消息、
每轮都想起同一批、于是每轮都回类似的话"。三条口径必须一起成立：

- 判据是**原文文本**（⛔ 不是件）：一件这次新露出来的那几段**照样给**
  （场 12 轮 2：挡 8 条、仍给 1 条）；
- 实测（12 场真数据）：**场 7 以后 44 轮里 18 轮有注入（41%）、26 轮被挡空（59%）**
  ⇒ 实际效果是"同一段每 3 轮念一次"；
- 挡掉**不等于丢掉**：注进去的那段还在 `msgs` 里（`ask` 只追加、从不删上下文），
  所以"取到的全在冷却期 ⇒ 一条没注"是**正常收束**，⛔ 不是"编写失败"
  （2026-10-17 我本人就把场 12 轮 3 这么读错过一次）。

⚠️ 于是「这一轮一条没注」必须分清**四种**原因（`逐轮记录.参数.注入`）：
`编写` · `清单` · `空（没取到件）` · `空（都在冷却期）` · `空（编写说没有）`。
混成一个 `"空"` 就会把"刚说过"读成"坏了"，也会**盖住真故障**。

### B. 归档（唯一会改图的环节）

```
[6] ① 切 cell
    输入：底片
    做  ：按天然单位切（★ 新对话 ＝ 按【轮】切；一场 ＝ 第 1..N 轮的 cell）
    输出：cell（原文区间）
    落到：缓存

[7] ② 算误差
    输入：cell ＋ 读法
    做  ：调模型拿 logprobs（★ 每轮一个数）
    输出：误差（逐 cell）
    落到：记录（和原文一起）

[8] ② 定标记
    输入：误差序列 ＋ **手工标记**（底片里的 `手工标记`）＋ ★ **归档时问她一句**
    做  ：① 误差 > μ_{t−τ} + γ·σ_{t−τ} ⇒ 标记
          ①b ★★ **兜底**：① 一个都没标出来 ⇒ 用**同一个公式**回头看**整场**
              （`误差 > μ + γσ`，μ/σ 取这一场全部轮）。⛔ 每场都用（会多标）
          ② ★★ **手工标记的轮** ⇒ **无条件进标记**（⛔ 看误差大小）
              ★ 手工标记的两个入口：她某一轮自己调 `remember` · **归档时系统问她**
    输出：标记 ＝ 那几个 cell（每个带 `来源`：`意外` / `手工`；兜底标的另带 `判法: 全场`）

★★ **标记有三个来源**（`REM-SWS 机制参考 §9`：novelty / repetition / reward）：

| 来源 | 怎么来 | 状态 |
|---|---|---|
| **意外**（novelty） | `误差 > μ + γσ`＋★ **全场兜底** | ✅ 在跑（★★ 两次真机读数都是"窗口 0 个"，见 `待决 §24`） |
| **手工**（reward）· **用户明说** | ① 他说「这个记住」 | ✅ **无条件进**，且 **−0.02 / 地板 0.5 ⇒ 永不剪出** |
| **自报**（reward）· **她自己标** | ② **归档时系统问她「这一场有没有你想记牢的」** | ✅ 无条件进，但**按普通档走**（作者定 2026-10-17：「她自报的给普通，当兜底用」） |
| ~~重复~~（repetition） | ~~和已有件的相似度高~~ | ❌ **实测不成立，见 `待决`** |

★★★ **为什么"手工"最靠得住**：**它⛔ 猜，它是明说的**。
⇒ **实测**：给场 3 第 27 轮打一条手工标记（"那种『我见过所以等着』的沉"）
⇒ 归档时它**无条件进标记**，而**分堆顺手把 28、29 轮（本来也没被标记）合成了一件** ✓
（那正是前面"本场最该抓的整段丢了"那三连）

★★★★ **"记牢一些"要落在三处，缺一处就是空的**：

| 层 | 无条件？ | 落点 |
|---|---|---|
| **① 会不会进标记** | ✅ **真无条件** —— 不看误差、不过阈值 | `标记(…, 手工=…)` |
| **② 会不会落成件** | ✅ 会 —— 拿不到候选就 fallback 新建，不丢 | `完成()` |
| **③ 留多久** | ★ **件带「来源」，衰减分档** | `图.件来源表()` → `markset.衰减(来源=…)` |

| 档 | 每窗口 | 地板 | 结果 |
|---|---|---|---|
| **意外** | −0.1 | 0.1 | **第 9 场**后剪出 |
| ★ **手工** | **−0.02** | **0.5** | 30 场后仍 0.5（> 门槛 0.2）⇒ **永不剪出** |

★★ **而且「合并也会让衰减变慢」**（【作者口径 2026-10-17】）：
一件本来普通的件，被并进一条**手工标记**的格子 ⇒ 它跟着变牢。**单向**：只会 意外 ⇒ 手工，
⛔ 反过来（否则"记牢"会被后来一次意外冲掉）。
⇒ **实测**：场 3 第 27 轮手工标记 ⇒ `件-0013 来源=手工 conf 0.980 成员 3`，
其余 12 件 `来源=意外 conf 0.700–0.900` ✓

★ **为什么手工档不用"永不衰减"而是"慢衰减 + 高地板"**：
保留「真的一直没用到就淡出」的能力 —— 只是手工的要**几十场**才淡，而普通的 9 场就淡。

[9] ③ 配对
    输入：标记（这一批）  ×  标记集里的「件」（上一次归档留下的）
    做  ：枚举（纯算法，不问模型）
    输出：候选连接

[10] ⑤ 判（模型 · 唯一需要判断的地方）
    输入：★ **这一批所有新标记的 cell** ＋ 候选件
    做  ：① 先「激活提候选件」（从上千件里取 k 个）
        ② 一次判**三问**（★ 分开判，⛔ 混成一个判断）：
           【一】a. 哪些 cell 归进哪个已有件（★ 可多个 cell 归进同一个件）
              b. 剩下的里，哪些**彼此属于一起** ⇒ 新建成一个件
                 ★★ **新件可以含多个 cell** —— 那才是"一件事"的最小单位
           【二】★ 它和候选里的某件，**是因为什么连在一起**？⇒ 给一个**短名字**
                （自由文本，如「猫的事」「工作硬撑」「那种沉」；⛔ 用"同一类事"这种套话）
                ⇒ ★ 可以连好几件（不同名字），也可以一件都不连
           【三】★★ 它是不是**改掉了**某个说过的说法？（"以前不吃辣 → 今天试了还行"）
                ⇒ `改口: {件: 被改掉的那件, 说法: "以前… → 现在…"}` 或
                  `改口: {轮: 同一场更早的那一轮, 说法: …}`（那一轮归档时才成件）或 null
                ★ 这一问⛔ 「同一件事」（那是【一】）、也⛔ 「连在一起」（那是【二】）：
                  它是**同一个话题上前后两个说法** —— 两条都留，由 `改口` 串起来，取用时成对带出
        ★★★ **判的输入 ＝ 整场真实对话**（`Session.msgs`）＋ 一条归档指令 ——
          归档就是「对话完了，fork 这一段接着问」，⛔ 由我们把整场重渲染成一段文字。
          （「轮」＝ **一次 `ask`**：他说一句 + 她回一段；一场有很多轮。）
        ★ 还能**自己查记忆**：候选只是按余弦提的 8 个，没进前 8 的那件用 `find_pieces` 查
          （上限 `knobs.判.找件次数`）—— 否则"真该并进去的那件"它永远看不见。
        ★ 候选**每件给几段原文**（`代表` 只是锚点，⛔ 内容）· 可以 batch（一次判一批）
    输出：归进 ｜ 新建（★ 新建的件可含多个 cell）＋ **连**（一串 `{件, 因为}`）＋ **改口**
    落到：★ 同时触发 [11] 的强化，以及**并块**（同名 ⇒ 同一个块）

★★ **⛔ 每格一次判** —— 那样"新建"只含一格 ⇒ **一件 ≠ 一件事** ⇒
`[R]` 的组内 α / 组间 β 会退化成摆设（真机首跑实测暴露过）。
★★★ **"聚组"⛔ 是独立的一步** —— 它就是 ⑤ 的第二个输出 (b)。
★★★★ **【二】⛔ 是"再一次判是不是同一件事"** —— 它回答的是**另一个问题**：
两件事可以**不是同一件、却都关于同一件事**（"猫的两件事"）。⛔ 别把两问混成一个。

★★★ **「同一件」的判据是硬的，而且收紧过一次**（2026-10-17 · 按真数据测出来的）：
同一个对象 ＋ 同一件**具体发生的事**（同一个场合 / 动作 / 念头）。
⛔ 只是**同一个话题**、同一种心情、同一个人 —— **不算**，那种关系走【二】的「连」。
⛔ 拿不准就**分开**（宁可两件，别合成一件）；每组的 `说法` 只许讲一件事
（⛔ 用「以及 / 还有 / 另外」把两件缝在一起）。

> **为什么收紧**：图里 19 个"合出来的件"共 32 对，组内相似度中位 **0.562**；
> 而"同一场里随机两件事"的基线中位是 **0.440** ⇒ **4 对（12%）比随机还更像两件事**。
> 最典型的 `件-0029`：把「碗和柜子一块清了」（轮 3）与「我妈问周末回不回去」（轮 5）
> 合成了一件 —— 而分堆模型自己给的 `说法` 里就带着「**以及**」。
> 收紧后拿 7 个件重判：**5 个偏松的全拆开了**（0.45–0.48 的那几个），
> **2 个真是一件事的（0.77 / 0.79）仍然合着** ⇒ 只收紧了糊涂账，没打散对的。
> （提示词在 `archive_step.分堆提示()`；`p2 [9e]` 守着"收紧了且真被用上"。）

[11] ④ 层1 ＋ 强化
    输入：⑤ 的判 ＋ 已有的标记集
    做  ：新建的件 ⇒ 进标记集（confidence = 1.0）
        ~~归进的件 ⇒ +0.05~~
        ★★★ 【作者定 2026-10-17】**归进⛔ 再加分** —— 归档只管**结构**（这一格并进哪件），
            强度**归激活**：那一场每一轮的 `激活` 分布累积强化已有件
            （`强化 = 系数 × 这一场的平均激活`，见 `§3.1.4` 与 `knobs.件.激活强化系数`）。
            ⇒ 为什么必须删：不删就是**同一件事被强化两次**（归进一次 + 激活一次），
              而两次的权重没人能定。
        ★ 并把该件里冷掉的成员拉到 max(当前, 0.25)
            ⚠️ 2026-10-17：**这一条在跑的路上没接** —— 标记集的键是**件**，而「成员」是
              **`cell`**，两者不是一个东西 ⇒ `完成()` 只能传空。能力留着（`markset.强化`），
              等做出「多 cell 一组的层级」再接。
    输出：更新后的标记集
    落到：缓存

[12] ④ 层2（长期维护）
    输入：标记集 ＋ 每件的 `来源` / `稳定度`
    做  ：每过一个窗口，按档衰减：
         · **手工**（只有用户明说）⇒ −0.02、地板 0.5 ⇒ **永不剪出**
         · **自报 / 意外**（她自报 · `②` 挑出来的）⇒ `每窗口衰减 / 稳定度`，夹到 `衰减下限` 之上
           ★★ 【作者定 2026-10-17】艾宾浩斯 —— 「如果重提的多，那么应该衰减的越来越慢」
           S=1（没被重提过）⇒ −0.1（与原来一字不差）· S=2 ⇒ −0.05 · S=4 ⇒ −0.025
           · S≥20 ⇒ 触底 −0.005（**保底**：仍会淡，但 0.9 掉到门槛 0.2 要 140 场 ⇒ 实际留下）
        ≤ floor ⇒ 剪出标记集（★ 不删，仍在图里）
    输出：更新后的标记集
    落到：缓存

[13] ⑥ 训练（还没做）
    输入：图
    输出：读法参数
    落到：存储（参数）

[14] 产出五样
    图 · 记录 · 卷子 · 材料 · 逐轮记录（＋版本对与指纹）
```

★★ **「完成」那一步的四个状态**（写进 `pending`，也写进转写那一行 —— ⛔ 别混成一个值）：

| `land` | 含义 | 池子动了吗 |
|---|---|---|
| `yes` | 草案已出、**在等你按「完成」** | 一字未动 |
| `done` | **已落地**（图写了、版本 +1），正在收尾 | 动了 |
| `failed` | 图**没写成**（草案留着，可以再按一次） | 没动 |
| `no` | 旧版遗留（等价于"已落地 / 幂等命中"），只为读旧数据保留 | 动了 |

⛔ 原来"已落地"和"没落地"**都写成 `no`** ⇒ 转写里分不清这一场到底走到哪一步
（场 12 实见：屏幕上是 `land=yes`、转写里是 `land=no`）。

## 二、流水线上两个容易搞错的顺序

**① 执行顺序是 ① ② ③ ⑤ ④ ⑥，不是 ① ② ③ ④ ⑤ ⑥**
因为 **⑤ 的输出是 ④ 的输入**（归进 / 新建 ⇒ 谁被强化）。
⇒ **④ 分两段**：**[11] 层1 ＋ 强化**（在 ⑤ 之后）· **[12] 层2 衰减**（长期，随时可跑）。

**② `③` 的"另一半"来自【上一次归档】**
`③` 是"标记 × 标记集"，而**标记集是上一批留下的** ⇒
⇒ **第一批归档时标记集是空的** ⇒ **`③` 没有候选 ⇒ 全部走 `⑤` 的"新建"**。

## 三、数据库 vs 数据集（⛔ 两件不同的东西）

| | **数据库** | ★ **数据集** |
|---|---|---|
| 目的 | **跑起来**（回忆要用 · 衰减要维护） | ★★ **之后拿回来继续改进用的** |
| 内容 | 运行时的全部状态 | ★ **材料 / 卷子 / 能回放的记录** |
| 形态 | 表（会增长 · 每次归档都改） | ★ **快照（冻结 · 可比较）** |
| 能改吗 | ✅ 会变（图版本 +1） | ⛔ **出了就不改**（改了要新建一版） |
| 依赖库吗 | 是（就是库） | ⛔ **要能独立用**（离开这个库也能跑） |

⇒ ★★ **判据一句话**：**要拿回去"改前 vs 改后"对比的，才是数据集。**
⇒ **所以数据集必须带「版本对 ＋ 指纹」** —— 否则分不清"是改法变了"还是"材料换了"。

### 3.0 两者怎么流动

```
库 ──导出──▶ 数据集（冻结）──▶ 训练 / 评估 ──▶ 改了读法
 ▲                                              │
 └──────────── 库重建（从底片）◀────────────────┘
      ★ 数据集不随之改变（它已经冻结了）
```

### 3.1 数据库（运行时 · schema）

★ **两档**：
- **存储**（不可再生成）⇒ **只追加**，改了就没法复现
- **缓存**（可复算）⇒ **可删可重建**（但仍落盘，免得每次从头算）

| 数据集 | 档 | 一条 = | 主键 |
|---|---|---|---|
| **底片** | 存储 | 一场 | `场id` |
| **逐轮记录** | 存储 | 一轮 | `(场id, 轮)` |
| **版本对** | 存储 | 一场一次归档 | `(场id, 图版本)` |
| **图** | 缓存 | —— | —— |
| ├ **cell** | 缓存 | 一轮 | `cell_id` |
| ├ **件** | 缓存 | 一件 | `件id` |
| ├ **标记集** | 缓存 | 一个件 | `件id` |
| └ **待观察池** | 缓存 | 一个单元 | —— |

> ⚠️ **这里纠正一处**：`①` 原写"新对话 ＝ 天然分段（一场一段）"，
> 但 `②` 的误差是**逐轮**的 ⇒ **cell 的粒度是「轮」，不是「场」**。
> 「场」只是**给 cell 分组用的标记**（一场 ＝ 第 1..N 轮的 cell）。

### 3.1.4 图（缓存 · 可重建）

```
cell     = { id, 场id, 轮, 起, 止 }                  ★ 起止是原文里的【字符区间】
件       = { id, 成员:[cell_id], 点亮:[cell_id], 取材:[cell_id],
             强度: float, 代表: cell_id, 表示: vector,
             ★ 来源: 意外|自报|手工,        ← 决定衰减档（只有 `手工`＝用户明说，永不剪出）
             ★ 稳定度: float ≥ 1,           ← 艾宾浩斯：重提越多 ⇒ 衰减 `每窗口衰减 / 稳定度`
             ★ 修正: [{件, 说法}],           ← 这一件**改掉了**谁（有方向，⛔ 覆盖）
             ★ 被修正: [件id] }              ← 谁改掉了这一件（反查，取用时成对带出）

★★ **`代表` 只是"这件用哪一格当锚点/标题"的记账字段，⛔ 内容**：
   件是个**组**，它的 `表示` ＝ 成员向量的**池化**（平均），⛔ 首格；
   给模型看的时候要**整组几段**，⛔ 只给代表那一格（这两处都犯过，各修过一次）。
★★ 边    = { a: 件id, b: 件id, 关系: 自由文本, 说法 }   —— pairwise，**原子**（存这个）
★ 块     = 某关系名下的**连通块**（并查集）             —— **派生视图，⛔ 存**
标记集   = { 件id: confidence ∈ [0,1] }              ★ 当前"活着的件"
待观察池 = [ { 单元, 为什么进来, 批号 } ]             ★ 标记，不删
```

★★★ **改口（冲突）⛔ 覆盖**（【作者定 2026-10-17】作者原话：「之前说不喜欢的食物，今天试了
发现还不错……显然直接覆盖不太好」）：两条都留（旧的＝"当时确实说过"是事实），只落一条
**有方向**的关系 `新.修正 → 旧`、旧的记 `被修正`；**取用时成对带出并按时间排**（以前 → 后来）
⇒ 她拿到的是"前后两个说法"，⛔ 只拿到一半。

★★ **`边` 是「多归属」那一层**（【作者定 2026-10-17】）——
**v16 的三个视角里，「同一件事」＝件；另外那两个只是块常见的两个名字，⛔ 硬性分类**：

| 视角 | 结构 |
|---|---|
| **同一件事** | ★ **件**（cell 的组） |
| **同一类事 · 同一种情绪 …** | ★ **边**（关系名由模型自己起） |

⇒ **关系名是自由文本**（"猫的事" · "工作硬撑" · "打开编辑器" · "那种沉" …）。
⇒ ⛔ 写死"类/情绪"两槽：那等于"块只有两种、而人得事先知道有哪两种"，太粗
（作者原话："**得能自己增加块才行**"）。
⇒ **为什么要有它**：两件事"都关于那只猫"**该连得上**，可它们**不是同一件事** ——
只靠"件"必然二选一；有了边就两者都对。

⇒ ★★★ **为什么「存边」⛔ 「存块」**：块是"某关系名下的连通块" ⇒ **它是视图**。
存块会有一串无解的问题 —— **名字漂**（同一组件两个名字）· **块数抖** · **要不要去重**；
而「**合并也行、不合并也行**」恰好说明**它本来就不是存储该有的东西**。
⇒ 于是"**同一对件起了两个名字**"**不再是冲突**，而是**两条不同关系的边** ✓
⇒ ★★★ 而这也正是作者最初那句：「**一个节点-组可以归在不同的边里**」—— **边才是原子**。

⚠️ **实测**（三次从同一批底片重跑）：**件 13/13/13** ✓ · **边 18/18/16** ✓ · **块 5/6/4** ✗
⇒ **块⛔ 能当读数**（一条边的差别就能把两块并掉或拆开）。

★ **重建** ＝ 从**底片**重跑 `①–⑤` ⇒ **图版本 +1**。

### 3.1.5 三条铁律

1. **存储只追加**（底片 / 逐轮记录 / 版本对）—— 改了就没法复现
2. **缓存可删**，但删了要能**从底片重建**
3. **每个可变的量都要带「版本对」** —— 否则"变了"和"记录错了"分不开

## 六、「原文 → 输出」这一步的提示词 · 本体

> 【作者要 2026-10-16】"提示词指的是「原文 → 输出」这一步。"
> 它只是**占位阶段**的（表达头还没训）；终态是"**文字化用固定模板**"（`记忆层 §15.4`）。

```text 编写-占位
下面是你记忆里被取用的 {件数} 件事（都是你自己说过的话）。

{件的原文，一条一行 —— 不带编号}

请把它们整理成【你的回忆】—— 第一人称，像你在回想。
· 每一件都要说到，一件都不许省；
· 每件事各自分明，不要揉成一件；
· 用原文里的说法，不加解释、不总结；
· 不要把编号、序号、分条带出来（写成回忆，不是列清单）；
· 不要提「取用」「记忆」「槽位」这些词。
```

★ **每一条都不是猜的**（改前改后的对照见 [`参数账.md`](参数账.md) §3）：

| 要求 | 为什么 |
|---|---|
| 不给情境 | 实测：给了 → 它把线索原样抄进了输出 |
| 不授权丢槽位 | 实测：写了"用不上就别写" → 4 个槽位只用了 2 个 |
| 不说"写成一两句" | 实测：与"不要概括"互相冲突 → 它必然拼接 |
| 不带编号 | 实测：带编号 → 出口变清单（编号是内部结构） |
