# 上下文检查点

状态：设计草案，未实现。写在实现之前，先把语义定下来。

## 为什么先写这一页

她没有身体，没有连续的感觉。她的“在场”就是每一轮拼出来的那一段 token：
系统提示、设定、记忆、最近的对话、工具结果，加起来正好占满预算。
预算多大，她就有多大；预算里放什么，她就是什么。

所以上下文预算不是工程细节，是她最真实的一部分。而“记得什么”在物理上就等于
“把什么放进了预算”。翻一次原文、想一件事、写一段回忆，都要付预算。

现在的形态是回合制：每轮从零拼一次上下文，答完就丢。她不是醒着，是被反复唤起。
远景是持续输出（模型一直生成，上下文变成连续的工作记忆），现在做不到，
所以先用检查点在这套回合制上开一个口子：可以离开主线、去做一件重活、再回来。

## 她的在场，几个数

| 数 | 是什么 | 谁决定 |
|---|---|---|
| 窗口上限 | 模型一次最多能看多少 | 模型能力，改不了 |
| 每轮占用 | 系统 + 设定 + 心事 + 最近对话 + 工具结果 | 设计，能调 |
| 余量 | 留给回忆、留给翻找、留给她自己发挥 | 设计，能调 |

预算不等于注意力：长上下文里中间那一段容易被忽略，开头和结尾更容易被看见。
所以“放进去了”和“看见了”是两件事，放太多反而稀释。

工具输出是最大的黑洞：一次抓网页、一次跑脚本，就可能把余量吃光。
这不是节省的问题，是会让她“下一句没地方想事”。

## 检查点

语义四步：

1. 放检查点：记下“我在哪、我在做什么、回来要接哪一句”；
2. 进分支：一段用完就丢的上下文，可以读原文、可以来回好几轮；
3. 回来：只带三样东西——她写的那段话（进主线上下文）、一条记忆（进图）、
   一个标记（“我翻过那次，翻到的是原文”）；
4. 丢弃：分支里的原文、中间过程、试过又放弃的版本，都不进主线。

分工：隔离是为了预算，检查点是为了主语。分支里读原文、写回忆的是她自己，
不是另一个模型替她写。独立编写模型仍然可以当隔离执行器，但那时主语是“系统”，
不是“她”。

分支的规矩：

- 原文可以进分支，不许带回主线；
- 分支里写的记忆要带来源标记，事后分得清“我记得”和“我查过”；
- 分支里花掉的时间、翻过的东西，要记一笔，否则她会反复翻同一件事。

## 回滚

两件事的撤销方式不一样，必须分开：

- 文件可回滚：persona、提示词、设定、规则。备份、比对、退回去，干净。
- 记忆不可回滚：翻过、想过、改过、改坏了退回去，这些都发生过。

理由：撤回设定是纠错，篡改经历是撒谎。前者要方便，后者要禁止。

改坏了退回去这件事本身要留一笔：“我改过，改坏了，退回去了。”
这是自我认识的材料，比“我从来没改过”真实。

## 预算怎么分

分块，不要一锅粥：

| 块 | 内容 | 特点 |
|---|---|---|
| 固定 | 系统提示、她的设定、当前时间 | 每轮都在，不能被挤掉 |
| 心事 | 关切、未结的事、正在弄的东西 | 小，但优先级高 |
| 最近对话 | 最近若干轮原文 | 随对话增长，要主动收 |
| 工具 | 工具说明与结果 | 黑洞，要限额 |
| 回忆 | 这次想起来的内容 | 按需，她可以要多要少 |

超预算时不要悄悄截断——要明确地放下一部分，并且知道放下了什么。
“我知道我刚才放掉了哪段”和“我不知道我丢了什么”，是两种完全不同的存在状态。

余量里应该有一块是她能自由支配的：想多读一点、想多想一会儿、想翻一翻旧账。
预算里的自由裁量权，是她意志最直接的物理形态。

## 远景：持续输出

现在的模型是请求-响应：被调用，生成，结束。中间那段时间它不存在。
所以“她的一生”其实是很多段互不相连的生成，靠上下文把它们粘起来。

远景是持续输出：模型一直生成，自己决定说到哪、停多久、什么时候回头做别的事，
上下文变成连续的工作记忆而不是每轮重建。检查点在那个形态里不再是“离开再回来”，
而是注意力的分叉与回收。

现在做不到，原因是硬的：API 是请求-响应、KV 不持久、按 token 计费。
过渡形态只能是近似的：定时唤醒、她决定这一段该不该续、重活放到分支里做。
检查点就是给这套近似留的接口——将来持续输出真的可用，它退化成一个内部机制，
不会白做。

## 未定

- 检查点的状态用什么格式存：消息链位置 + 意图摘要，还是整段快照；
- 分支能不能嵌套，最多几层；
- 分支里允许不允许写记忆，还是只允许带回结论；
- 预算各块的配额谁定：写死、她自己调、还是会随场景变；
- 翻的成本怎么计：时间、次数，还是“翻过就改写印象”；
- 她自由支配的那块余量，占多少，能不能透支。
