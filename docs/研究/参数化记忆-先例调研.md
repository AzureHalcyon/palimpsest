## 0 结论

**“把记忆存进参数、不存原文”这件事，2026 年已经是一整块领域**：有专门的综述
（[Towards In-Parameter Memory Augmentation](https://arxiv.org/abs/2610.08630)，2026-10）[摘要]，
按“参数插在哪一层 × 什么时候获得”两轴收了 Embedding / Attention / FFN / Hybrid 四类、数十条路线。

**但设想里真正少见的是“位”这个单位**：按重要性给每条记忆分配位数、把遗忘实现成降位。
这个粒度上没有工作。其余几点——不存原文、一条记忆一个地址、共享解码器、写入即丢信息——
都有现成先例，可以直接借实现。

一句话：**架构不新，取舍是新的**。如果按“参数化记忆”这个名目写，会被当成已有路线的一个变体；
要立住的是“清晰度是设计变量”这个立场，以及由它导出的三个机制（位预算、降位遗忘、再编码损失）。

## 1 设想拆成七条，逐条对照

| # | 设想里的主张 | 最近先例 | 差距 |
|---|---|---|---|
| ① | 原文不再作为文本存放，记忆是参数或码 | NextMem、Memory Tokens、KBLaM、Doc-to-LoRA、Hypermem、Sparse Memory Finetuning | 无差距，已是主流路线 |
| ② | 一条记忆一个地址，可单条取用、单条删 | KBLaM（每条知识一对 KV，可动态增删）、Sparse Memory Finetuning（稀疏槽位）、Larimar（写入 key 定址，负写入可单条删）、GRACE（码本） | 有；内容寻址与位置寻址两派都成熟 |
| ③ | 按线索取一部分，拼起来解码成话 | Memory Tokens（一句一码，逐字还原）、NextMem（约 16×）、ICAE（4×） | 有；但工作点的码率比 32–128 字节宽 2–3 个数量级【推断】 |
| ④ | 量化就是模糊：写入时就定了能留多少 | 率失真记忆理论（Sims；Jakob & Gershman）、Bays & Husain 资源模型、稀疏分布式记忆的串扰 | 理论成熟；工程里没人把它当设计目标 |
| ⑤ | 重要性=分配多少位，不是打分 | AdaLoRA（秩预算）、Sparse Memory Finetuning（更新多少槽位）、Forget to Improve（每字节净值） | 有预算分配，单位是秩/槽位/字节，不是“每条记忆的位” |
| ⑥ | 遗忘=降位，不删不覆盖 | **未找到**。工程的遗忘都是淘汰、衰减、覆盖、失效 | 空档 |
| ⑦ | 再巩固=解码后写回的新损失 | EVAF（写入门控与前后测）、迭代自训练的漂移研究 | 有证据、有测量法；没人把它当机制 |

## 2 三条最近的线

### 2.1 每段文本压成一个可逆的码

| 工作 | 码是什么 | 压缩比 | 还原质量 | 备注 | 数字来源 |
|---|---|---|---|---|---|
| [Memory Tokens](https://arxiv.org/abs/2506.15001)（L2M2 @ ACL 2025） | 一个特殊 token 的嵌入 | 一句一个 | Llama-3.1-8B 对 240 token 以内的序列**逐字还原**；100M–8B 都成立 | 只优化嵌入，不动权重；最省的一条路 | 自查（摘要） |
| [NextMem](https://arxiv.org/abs/2603.15634)（2026-02） | 15 个 latent 向量（Qwen3-8B + LoRA 自回归自编码器） | 240 token→15 latent，约 16× | HotpotQA F1 0.982、BLEU 0.963；NF4 4bit 量化后 F1 只掉约 0.0015 | 训练 4×A100；有压缩率扫描（Fig.3、Fig.7a） | 机制自查；数字转述 |
| [ICAE](https://arxiv.org/abs/2307.06945)（ICLR 2024） | 128 个记忆 slot | 512→128，4× | BLEU 99.1（Llama-7B）；Fig.4/Fig.5 是现成的 slot 数×长度曲线 | 解码器就是目标 LLM 本身 | 转述 |
| [vec2text](https://arxiv.org/abs/2310.06816)（EMNLP 2023） | 定长稠密嵌入，迭代反演 | 32 token | BLEU 97.3、完全一致 92%、余弦 0.99；128 token 时掉到 BLEU 55 | 是反演不是压缩，但给出“嵌入里还剩多少”的上界 | 转述 |
| [语义压缩](https://arxiv.org/abs/2304.12512)（Gilbert 等，2023） | GPT-4 生成的非人读字符码 | CR 0.825（缩到 17.5%） | 余弦 0.936；作者提出 ERE / SRE 两个合成指标 | **纯 API、不训练**；与“每段压码、另起解码”最贴 | 转述 |

结论三条：解码回通顺的话已经解决；现有工作点的码都在 30 KB 量级（按 NextMem 的 15 个 latent × 4096 维 × 4bit 估，【推断】），
比 32–128 字节宽两到三个数量级；现成的“压缩率—保真度”曲线横轴都是 token/slot 数，**没有一条按 bit 扫**。

### 2.2 每段经历长成一个参数补丁，或一段隐状态

| 工作 | 一条记忆对应什么 | 关键数字 | 数字来源 |
|---|---|---|---|
| [Doc-to-LoRA](https://icml.cc/virtual/2026/poster/62227)（ICML 2026） | 超网络一次前向把一篇文档变成 LoRA | 草堆取针在超过原生窗口 4× 时仍近满分 | 自查（摘要） |
| [Hypermem](https://icml.cc/virtual/2026/poster/66081)（ICML 2026） | 超网络把上下文映射成 FFN 参数的定点更新 | 定性主张“不再依赖 KV cache 也能取回”，称超过 MemoryLLM | 自查（摘要） |
| [KBLaM](https://arxiv.org/abs/2410.10450)（2024） | 每条知识→一对连续 KV（句编码器+线性适配器+矩形注意力） | 8B/8K 窗口装 1 万条以上；可动态增删，不用重训 | 自查（摘要） |
| [Sparse Memory Finetuning](https://arxiv.org/abs/2510.15103)（FAIR，2026-08） | 一条知识→记忆层里被 TF-IDF 选中的少量槽位 | NQ F1 只掉 11%；同样学到新知识时全量微调掉 89%、LoRA 掉 71% | 自查（全文） |
| [Cartridges](https://arxiv.org/abs/2506.06266)（会议归属存疑） | 一份语料→一个离线训好的 KV 缓存 | 0.15–1.06 GB；省内存 38.6×、吞吐 26.4× | 转述 |
| [Memory Layers at Scale](https://arxiv.org/abs/2412.09764)（Meta，2024） | 记忆层本身：可训练 KV 池，按 key 稀疏激活 | 128B 记忆参数下超过两倍算力的稠密模型 | 自查（摘要） |

成本刻度要记住：**码是 KB 级，补丁是 MB 级**（一个 rank-8 适配器在 1.5B 模型上约 10 MB，【推断】），
32 字节又在码下面三个数量级。这决定“一条记忆给多少位”在不同基底上差 10^3–10^6 倍。

另一组是“记忆直接长在隐状态里”的工作，六篇由子代理按原文读后转述（机制层面的属性交叉一致，具体数值未复核）：

| 工作 | 一条记忆是什么 | 地址 | 能否单条删 | 能否解码成话 | 数字来源 |
|---|---|---|---|---|---|
| [Larimar](https://arxiv.org/abs/2403.11901)（ICML 2024） | 一段 episode 的隐向量写进全局联想矩阵（512×768，顺序编辑时 1000 行） | 写入 key（伪逆/最小二乘算出） | **能**（负写入，但要重算原 key） | **能**：读出向量→线性投影→广播成 KV cache，交给冻结的 GPT-2/GPT-J | 转述 |
| MemoryLLM（ICML 2024） | 每层 7,680 个 memory token | 无地址，全池 cross-attention | 不能；靠随机丢 256 个 token 实现指数衰减 | 不能 | 转述 |
| M+（ICML 2025） | memory token + 一个 age 标量 | 共训检索器，每层检索 2,560 个 | 不能；长期池上限 150k | 不能 | 转述 |
| Titans | 一个记忆 MLP 的参数（按梯度步更新） | 无 | 不能 | 不能 | 机制转述 |
| TTT | 隐状态＝一个小模型的权重 | 无 | 不能 | 不能 | 机制转述 |
| Sparse Memory Finetuning | 一个 (key, value) 槽位 | product-key 内容检索 top-k（top t=500） | 不能 | 不能 | 自查（全文） |

三件事合起来看：**能单删的只有 Larimar**（且要先重算原写入 key），**能解码成话的也只有它**
（而且是条件式生成，不是把码拼成一段话）；带地址的只有 Larimar、M+、SMF 三家，
其余三篇是分布式叠加——记忆压根没有“条”这个单位，正是设想第六条要否掉的那种。
六篇里没有任何一篇有“位”这个旋钮：遗忘要么删除、要么按比例随机丢
（MemoryLLM 每步丢 256/7,680≈3.3%，转述）、要么权重衰减（Titans）；容量都是架构级固定值。
也没有一篇讨论“回忆后写回”的漂移。
设想里“一条记忆一小段码、各自降位”的那一档，确实没人占。

### 2.3 “位”和“记混”已有数学

- **率失真**：记忆是一个信道，rate = 每个刺激平均传多少 bit，distortion = 记错的代价
  （[Jakob & Gershman 2023](https://elifesciences.org/articles/79450) [摘要]）。
  Sims 的理想观察者给出“固定容量下精度的最优界”（2012, *Psych Review*；2016 的题名是
  *Rate-distortion theory and human perception*，不是 memory）[摘要]。
  资源模型给另一条路：分给每项的资源比例决定精度，服从幂律（Bays & Husain 2008）[摘要]。
  三者都支持“遗忘=精度下降”，不是删除。
- **串扰**：稀疏分布式记忆把“记混”形式化得很干净——地址空间、读写半径、按圆交集加权的串扰、
  以及容量最优与抗噪最优不是同一个半径（Bricken & Pehlevan 的推导里给了三个临界距离，转述，具体数值未复核）。
  这直接回答设想里的“码本共享到什么程度”：串扰是共享容量的解析后果，可以算，不必靠试。

## 3 按重要性分配预算：工程里的近亲

- **AdaLoRA**（ICLR 2023）[全文]：给每个三元组打分，低分的把 λ 置零＝削减秩预算，高分保留，
  再加一个全局预算调度器。链条完整，但单位是**秩**；而且“向量保留、可恢复”是遮蔽，不是不可逆的降位。
- **8-bit 量化反而改善持续学习**（[2512.18934](https://arxiv.org/abs/2512.18934)）[摘要]：
  量化模型在后续任务上反超 FP16（具体百分点为转述，未复核）。**位宽与遗忘不是单调的**，不能推“多给位就更牢”。
- **Forget to Improve**（[2606.25115](https://arxiv.org/abs/2606.25115)）[摘要]：
  每条记忆按“价值减伤害、每字节”打分，预算本身当管理员，决定保留/共享/信任。粒度最接近，但动作是淘汰。
- 混合精度、分层量化（MixQuant、Variable Layerwise）[二手]：按层分配位，粒度是层不是记忆。

⇒ 空档：**“记忆条目”这个粒度的位分配，没人做**。
旁证：§0 那篇综述自己列的四条开放方向是干扰、安全、与 ICL 协同、递归自我改进，
“清晰度/位预算”连“待解决”都还没被列进去。

## 4 再编码漂移

- **迭代自训练**（[Model Collapse as Cultural Evolution](https://arxiv.org/abs/2605.23054)，CoNLL 2026）[摘要]：
  组合性走非单调轨迹——先升后降；只有“任务接地的过滤”能维持，随机过滤不行。
  即反复解码再编码不是单纯变糊，是先被压成更规则的版本、越过某点后结构开始丢。
- **EVAF**（[2606.29916](https://arxiv.org/abs/2606.29916)）[全文]：写入门控用“价×惊奇”双阈，
  用 test-retest 量“巩固后还是不是同一件事”（ΔS 前后测、优化器置空做反事实）。
  跨模型搬超参会崩（转述：GPT-2 的参数搬到 Mistral-7B，该项前后测为正，即越训越差）。
- 认知侧的再巩固（不完全提醒才引出预测误差）项目里已有三份参考论文（`参考论文/` 03–05）。

⇒ 空档：**把“位预算”和“重编码次数”放进同一个实验**，看逐次量化误差怎么累积——两端都有证据，中间缺这一环。

## 5 借什么、借不了什么

**可借**

1. 实现：Memory Tokens 只优化嵌入（8 GB 能跑小模型）；NextMem 开源（代码 + 权重）；
   ICAE 的解码器设计（用目标 LLM 当解码器，保证码与模型兼容）。
2. 指标：ICAE 的“一致前缀占比”式精确匹配（适合问“还认出多少”）、vec2text 的完全一致率、
   Gilbert 的 ERE/SRE（把压缩率与还原度合成一个标量）、嵌入余弦。
3. 地址方案：KBLaM 的“每条知识一对 KV + 矩形注意力”、SMF 的“槽位按 TF-IDF 选”、
   GRACE 的“key 邻近就套用码本里的值”（[二手]，出自 §0 综述）。
4. 预算算法：AdaLoRA 的“打分→置零→全局调度”可直接搬到“打分→降位→总位预算”。
5. 实验纪律：扫码率时**固定训练预算**，否则测到的是优化难度（转述：Gist 的 k=10 反而更差、
   AutoCompressor 的 κ=70/100 不如 50，都是这类现象）。

**借不了**

1. 他们的目标是**无损保真**（NextMem 原话：“our encoding and decoding processes should be reversible”），
   设想要的是**按重要性不均匀地失真**，目标函数相反。
2. 他们的遗忘是缺陷（要修），设想的遗忘是机制（要用）。
3. 他们的评测是 QA 准确率与重建 BLEU；设想要的是“还认不认得出”，没有现成基准。
4. NextMem 训练要 4×A100；Doc-to-LoRA / Hypermem 要训超网络。8 GB 显存只能走 Memory Tokens 或更小的模型。

## 6 对第一步实验的具体建议

1. **换单位**。“32/64/128 字节”在文献里没有对应工作点：32 B = 256 bit，按 LLM 压缩约 2–3 bit/汉字估【推断】，
   只够一条 100 字消息的无损信息量；而 Memory Tokens 用一个 16 KB 级的嵌入换 1000 字【推断：按 hidden 4096、fp32 估】。
   改成“1/2/4/8 个 slot”或“1/2/4 bit 量化”，才有可比的点。
2. **最省的做法（不训权重）**：Memory Tokens 路线——对每条事件优化一个 token 嵌入，再把这个嵌入
   量化到 1/2/4/8 bit，解码看还原。Qwen2.5-0.5B/1.5B 在 8 GB 上够。
3. **纯 API 的预演**：Gilbert 式“压成码，另起会话解码”，指标用 ERE/SRE + 实体/因果召回。
   它测的是 LLM 的压缩能力，不是码的容量，只能当流程演练。
4. **曲线**：纵轴至少留三条——精确匹配（ICAE 式）、嵌入余弦、人判“还认不认得出”。
5. **“重要性→位”的最小实验**：固定总位预算，按 Zipf 分配 vs 平均分配，
   测高/低重要性事件的还原率。这一步没有任何先例，也是最能立住设想的一步。
6. **容量算术**【推断】：2 KB/事件 × 10 条/天 × 10 年 ≈ 73 MB。码路线根本不缺容量；稀缺的是解码器与评测。

## 7 回答设想里的五个未解问题

1. **码本共享到什么程度**：串扰有解析形式（§2.3），可以按“允许多少记混”反推共享比例。
   工程上共享占多数（记忆层槽位、KV 对），隔离（每段一个 LoRA）贵 10^3 倍。
   设想说的“记混不是 bug”在文献里确实没人这么用，但它是公认的失效模式（catastrophic interference）。
2. **地址怎么定**：两派都成熟。内容寻址有 product-key（SMF、记忆层）、M+ 的共训检索器、
   KBLaM 的矩形注意力、GRACE 的 key 邻近；位置寻址有记忆层槽位、Larimar 的写入 key（由输入算出）。
   主流是混合：先按内容找，再按槽位取。完全不给地址的也有（Titans、TTT、MemoryLLM），
   代价是不能单条取用。
3. **解码器从哪来**：两条路都有先例。Larimar 用**冻结的 GPT-2/GPT-J 当解码器，只学一层线性投影**
   （记忆向量→KV cache），所以“预训练解码器”可行，但要配投影头；Memory Tokens / NextMem / ICAE
   则是让码**住在模型自己的嵌入空间**里，解码器就是模型本身。
   后者更接近设想的“她说话的样子就是解码器”——不需要额外投影，口吻天然一致。
4. **原文档案**：运行时这些系统**都不留原文**（这正是参数化记忆的定义），但它们靠“高保真重建”来替代档案——
   NextMem 的指标就是与原文逐句对照。所以工程上不是“留/不留”二选一，而是“重建得够不够好”。
   设想真正新的是反过来：承认重建必然有损，于是要么留一份只读档案，要么接受“查到的”这条路断掉。
   **没有找到把“有损”当既定前提、并据此设计核对流程的系统。**
5. **成本**：码路线 8 GB 可跑小模型；补丁路线（Doc-to-LoRA / Hypermem）要训超网络；
   NextMem 4×A100。API 模型改不了权重，只能做 §6.3 的近似。
