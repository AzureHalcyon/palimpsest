## 0. 一句话

这一层的成熟方案**全都建立在"嵌入 / 向量相似度"或"结构化三元组"之上**；
我们当前走的是**标签空间 + 逐字证据**。
⚠️ **"标签空间"是"不用 pip、可复算、证据可机械核"这三个工程约束下选定的实验路径，不是本项目的定义。**
（`[原话 2026-10-02]` 用户要向量，并且自己列出了向量的失效面；"不引嵌入"是从任务书的**工程约束**被硬化成**设计约束**的
—— 这是把工程约束硬化成设计约束的一个实例。**要不要引向量是设计选择，不是禁区。**）
所以能借的**不是它们的打分公式**，
而是四样东西：**（a）"好用"该怎么量、（b）时间怎么进模型、（c）冲突怎么消解、（d）权重凭什么这么定。**

## 2. engram（有源码，`github.com/TAIPANBOX/engram`）

### 2.1 它是什么

一个**可嵌入的"agent 记忆层"**（自称 "the SQLite of agent memory"）：单文件 SQLite + `sqlite-vec`，
建三种记忆（episodic 事件 / semantic 双时间三元组 / procedural），带重要性衰减、
**扩散激活检索**、血缘追踪。`[源码] README.md:1-40`

**注意**：它是**用嵌入的**（`fastembed` + `bge-small-en-v1.5`，384 维）。
所以它整体不能照搬，但**它有几处正好压在我这一轮卡住的地方**。

### 2.2 ★ 最重要的一处：**它把"权重凭什么这么定"真测了**

`docs/api-reference.md:781-811`「The blend weights, swept」`[源码]`：

- 原来的默认 `0.7/0.3` 是**没人测过就发出去的**（原文：`shipped as the default without anyone measuring it`）；
- 500 题全量、每题同一份 store、八种配比一次跑完：

| blend（余弦 / BM25） | session@5 | turn@5 | session@10 | turn@10 |
|---|---|---|---|---|
| 纯 BM25 `0.0/1.0` | 0.938 | **0.750** | 0.960 | 0.814 |
| `0.3/0.7` | 0.954 | 0.786 | 0.970 | 0.860 |
| **`0.5/0.5`（现默认）** | **0.970** | **0.830** | **0.982** | **0.894** |
| `0.7/0.3`（旧默认） | 0.968 | 0.820 | 0.982 | 0.892 |
| 纯向量 `1.0/0.0` | 0.956 | **0.772** | 0.978 | 0.862 |

**它自己的读法（这段最该学）**`[源码] api-reference.md:799-807`：

> Read the margin honestly. 0.5 beats the old 0.7 by 1.0 point of turn@5,
> which is **five questions out of five hundred**. It is the default because it
> leads on all four metrics at once and costs nothing to adopt, not because the
> gap is large. **The two sit on the same plateau.**
> **The shape is the real result.** Both ends are clearly worse than the middle.

**⇒ 对我们直接有用的两条**：

| 借什么 | 为什么 | 怎么落到我们这里 |
|---|---|---|
| **①读法**：中点赢一档不算赢，**"两端都差、中间好"的形状才算结果** | 我上一轮报的"等权 vs 连乘差 0.016（p=0.54）"正是同一量级 ⇒ **我当时的结论下得对**（说不显著），这条给了外部佐证 | 我们的 `w` 曲线**也是两端差、中间好**吗？——**不是**：我们那条是**单调**的（w=0 → 年龄最小命中最低；w=1 → 反之），**没有中间峰**。⇒ 差别要在报告里说清 |
| **②做法**：**把扫参放进同一次跑**（每题共用同一份 store，八种配置一次跑完） | 我们现在的困境正是"分母口径丢了、历史数字不可复算" | 下一轮把 `w` 的扫描与主实验**放在同一次运行里出数**，禁止引用历史值 |

### 2.3 ★ 它有一条"再检索就变重要"的加法式重要性

`engram/importance.py:14-54` `[源码]`：

```
importance(m, t) = salience(m) · exp(−λ · (t − last_access(m)))     # 艾宾浩斯，时钟从"上次被取用"起算
                 + α · log(1 + access_count(m))                     # 强化项（加法！）
                 + β · emotional_valence(m)                         # 情绪项
默认 λ = 0.1 /天（半衰期≈7 天）· α = 0.2 · β = 0.1 · 剪枝阈值 0.1
```

**三个可以直接搬的点**：

1. **衰减时钟从 `last_access` 起算，不是从发生时间起算** ⇒ **这正好补上我们缺的 `access_count`**：
   "常被想起来的认知老得慢"，而且是**加法项**（不会被别的乘子一起压掉）。
   ⚠️ 与我上一轮的发现拼起来看：我测出**加法/等权聚合与乘法在命中率上无显著差别**，
   但 engram 的加法是**"衰减项 + 强化项"相加**（一个降、一个升），**不是三个相似度相加** —— 这是另一种用法，**没测过**。
2. **`emotional_valence` 是一个独立维度（−1..+1）** ⇒ 我们的 892 条认知**没有这个字段**，
   而"情绪作为调制函数"正是用户最初的构想之一。**借字段，不借公式。**
3. **重要性是"每次衰减任务批量重算并落库"**（`decay.py:35-54`，一次 GROUP BY 读 + 一次 executemany 写）
   ⇒ 它是**派生量，会随时间自己变**，而不是抽取时定死的常数。我们现在的 `重要性` 是**抽那一刻定死的**（缺口）。

### 2.4 ★ 双时间（bitemporal）：冲突消解的现成做法

`engram/models.py:56-90` 的 `Fact` 字段 `[源码]`：

```
id, subject, predicate, object,
valid_from, valid_to,                # 现实里什么时候是真的
recorded_at, superseded_at, superseded_by,   # 系统什么时候知道 / 什么时候被替换 / 被谁替换
confidence, derived_from[], extracted_by
```

- 冲突检测：`core.py:447-466` `contradictions()` —— **同 `(subject, predicate)` 但 `object` 不同** ⇒ 一对冲突
  （原文注释：同三元组是**一致**不是冲突）；
- 消解：`store.py:721-725` `close_fact(fact_id, valid_to, superseded_by)`
  ⇒ **不是删，是把旧事实的时间区间关掉** ⇒ "他以前喜欢 X、现在不喜欢"两句话**同时存在且都可查**；
- 查询：`as_of` 只认 `valid_from <= T and (valid_to is null or valid_to > T)`（`store.py:1238-1244`）。

**⇒ 对我们最有用的一点**：我们的"认知"**目前没有失效机制** ——
一条"他享受看别人卡住再揭晓"一旦抽出来就永远在那，**没有办法表示"这已经不成立了"**。
这正是用户最初设计里"簇会随时间漂移"要的东西。

**⛔ 但不能照搬的地方**：它靠 `(subject, predicate)` **精确相等**来判断"这是同一件事"。
我们的"说法"是自由句（"我感觉他习惯先接住一个现成论断，再一步步拆它的前提"），
**没有主谓宾结构** ⇒ 我们得先回答"**两条认知怎么算在说同一件事**"。

### 2.4.1 ★ 这个问题我自己先量了一遍（探针脚本，留档不在本仓；`[实测]`）

拿现有 892 条认知试了四种"抓手"：

| 抓手 | 结果 | 能不能用 |
|---|---|---|
| **A. 精确标签集合相同** | 771 个不同标签集合，其中 **65 个组 ≥2 条**，覆盖 **186 条（20.9%）**，组大小中位 2、最大 14；**65 个组全部跨对话** | ✅ **能当候选集**（规模合适、且天然是"不同时间点说的同一类事"） |
| **B. 标签交集 ≥ k** | ≥2 时：19370 对，**连通分量 14 个，最大分量 878/892** —— **整份语料几乎连成一片** | ❌ **不可用**（退化，跟 v1 规格里"图传播退化成比 bucket 大小"是同一个病） |
| **C. 同一 `关于` 实体** | 526 条有实体（59%），297 个实体；≥2 条的 116 个，覆盖 345 条（38.7%），最大 12 | ⚠️ 偏粗（"同一个书/人"≠"同一个判断"） |
| **D. 同一条对话内** | 196 条对话，平均 4.55 条认知 | ⚠️ 这是"同一次谈话"，不是"同一件事" |

**★ 但抓手 A 只是候选集，不是等价类** —— 实测的组长这样：

```
标签 ['幽默','提问方式','语言']
  [2026-06-21] 我感觉他喜欢用这种半出题半分享的方式和人互动，答案本身不如「你猜猜看」这个动作重要。
  [2026-02-08] 我感觉他读书时对"措辞"本身有敏感度，会停下来掂量一个译名是不是戏谑、是不是恰如其分。
```

**同一组标签，装的是两句不同的判断。** ⇒ **标签相同 ≠ 同一件事。**

**⇒ 结论（这一条是本轮最硬的发现之一）**：
**"两条认知是不是在说同一件事"不能靠现成字段判定，必须引入一次外部判断**（LLM 判官，
或者人）。标签/实体只能用来**缩小候选对**，不能用来**下结论**。

**⚠️ 而且这引出一个更麻烦的事**：如果"同一件事"要靠 LLM 判，
那它就成了**又一个不可机械核的环节**（像"说法"一样）。
我们唯一能机械核的是**证据**。可用的办法是把判据绑到证据上：
**两条认知的证据是否指向同一段对话/同一件事** —— 这是可核的。
`面向`（事实/倾向/在意/想要/抗拒/回避）也可能有用：实测**65 个标签组里只有 17 个（26.2%）面向完全一致**，
面向一致的才**可能互相矛盾或互相印证**（其余是"同一类事的不同侧面"）。

### 2.5 扩散激活：一个"带权重混合"的写法 + 一个防重复计数的细节

`engram/graph.py:13-109` `[源码]`：

```
最终分 = α·余弦 + β·图激活 + γ·重要性          默认 α=0.6, β=0.3, γ=0.1, depth=2, 每跳 decay=0.5
种子节点只贡献余弦，不计入图激活  ← 注释明说：否则种子会被算两次
Hebbian 边权可以长到 >1，读取时 clamp 到 [0,1]  ← 否则单条热边会主导
```

**⚠️ 与我们既有实测的关系**：我们测过"一跳/两跳标签传播"，结论是**在粗标签下退化成"比 bucket 大小"**，
于是 v1 规格把传播**关掉了**（冻结规格 §4：不用图传播）。
**⇒ 它这套不能推翻我们的结论**（它是在**实体图**上扩散，我们是在**标签**上扩散，图的性质不同），
但**两个工程细节值得记下**：①种子不要重复计数；②边权要 clamp。

### 2.6 压缩与"按重要性清理"，以及一个**时间戳的坑**

`core.py:747-831` `[源码]`：

- 三个闸门：`episode_count > max_episodes(1000)` **且** 有 `importance_score < 0.3` 的 **且** 配了 LLM，才压缩；
- 每 `batch_size(20)` 条调一次 LLM 生成一段摘要，**原条目硬删**，摘要条目的 `summary_of` 指回原 id；
- **★ 坑（值得抄进我们的纪律）**：摘要条目的时间戳**必须盖成"它覆盖的那批里最新的时间"，
  不能盖成 `now`** —— 否则 `as_of` 查那段历史时，"原件已删、摘要还在未来"，**那段时间变成空的**。

**⇒ 对我们**：这套**不能照搬**，原因不是工程，是**原则冲突**：
我们的规矩是**原语层永不改写**（冻结规格 §1），而它是**硬删原件**。
我们该做的是**"降权不下沉"**：低价值认知降低检索权重，但**原文与证据永远留着**。
⇒ 但那个时间戳的坑要记住：**凡是派生物，时间戳必须继承来源，不能盖 `now`。**

### 2.7 还能借的小东西

- **`WorkingMemory`：容量 7（Miller 7±2）的 LRU 草稿纸**（`working_memory.py:1-6`）
  ⇒ 对应"当前对话的工作区"，与我们"每次取 8 条"是同一类约束的两种写法。
- **它的工程纪律**（`CLAUDE.md` invariant 2 / 9）`[源码]`：
  **每个发布的数字都必须有人量过，且量的命令写在数字旁边**；**每个闸门都必须被故意弄失败过**，
  以证明它能区分"没失败"和"没跑"。⇒ 这正是我们"数字可复算"规矩的更硬版本（我们已经在做，可以学它的**闸门自证**）。

- **Membrane**`[源码]`：衰减曲线**写死为指数**，分化只在半衰期（情景 1h / 工作 1d / 语义·能力·计划 30d）；

- **EvoLib**`[源码]`：`is_improving` 写入门控（只有胜过历史最优才入库）——**唯一完整的防幻觉污染骨架**；
  ⚠️ 但它依赖"自评信号"，**陪伴场景没有标准答案** ⇒ 移植的最大障碍是**信号来源**，不是工程量。

  ⇒ 对应"想了不说"，与本层（检索）无关，属于交互层。

### 4.1 它是什么

**一个提示词注入器**（dynamic dictionary）：关键词命中 ⇒ 把预先写好的条目文本插进上下文。
原文自述：`It functions like a dynamic dictionary that only inserts relevant information from
World Info entries when keywords associated with the entries are present in the message text.` `[官方文档]`

### 4.2 ★ Timed Effects（`sticky` / `cooldown` / `delay`）—— 这是唯一与我们相关的机构

**规则（原文五条，逐条抄）** `[官方文档]`：

1. **单位是"消息数"，不是对话对数，0 = 无效果**；
2. 效果**只在激活它的那个 chat 里有效**，分支继承父 chat 的状态；
3. **chat 没往前走（最后一条被 swipe/删除）⇒ 计时效果被移除**；
4. **改动条目本身 ⇒ 计时效果被强制清除**；
5. **★ 关键词再次命中不会刷新时长**（`Consequent triggering of keywords does not refresh the effect duration if it's already active.`）

三种效果的定义（原文）：

| 字段 | 精确定义 |
|---|---|
| **sticky** | 激活后**保持激活 N 条消息**；粘住期间**忽略概率检查**直到过期 |
| **cooldown** | 激活后**N 条消息内不能再被激活**；**可与 sticky 连用**（粘住期结束后才进冷却） |
| **delay** | **消息总数不足 N 条就不能激活**（delay=1 ⇒ 空 chat 不能激活；delay=2 ⇒ 只有 0/1 条消息时不能激活） |

原文例子（`sticky=3, cooldown=2, delay=2`）：

```
Message 0: delay
Message 1: entry activated
Message 2: sticky
Message 3: sticky
Message 4: sticky
Message 5: cooldown
Message 6: cooldown
Message 7: entry can be activated again
```

**⇒ 为什么这三件事对我们是重要的（`[推断]`，但依据是上面的原文语义）**：

我们的检索现在是**每轮重新算 top-8**，**没有"刚想起来的事，别马上又想起来"这回事**。
而一个真的在陪人的系统，这两件事都必须有：

- **不能每轮重复想起同一件事** ⇒ 这就是 **cooldown**（"三条消息内别再提这件事"）；
- **一件重要的事想起来之后该留在台面上** ⇒ 这就是 **sticky**；
- **刚认识时不该提第三次见面才该知道的事** ⇒ 这就是 **delay**（"关系还没到时候"）。

**而且它的第 5 条规则（不刷新时长）是反直觉但正确的一笔**：
如果关键词每次命中都刷新 sticky，一件"总被提到"的事就会**永久霸占上下文**。
不刷新 ⇒ sticky 是**有限的**，自然会退场。**这是一条防止"常客垄断"的机制**，
与我们在 `decay2_report.md` 里测的"衰减防止垄断"是同一件事的另一种解法。

**⛔ 但有一处不能照搬**：它的计时**只在 chat 内有效、且 chat 回退就清空**（规则 2/3），
**不是"记忆随时间衰减"**。它的时间轴是**消息序号**，不是**真实时间**。
我们的半衰期是真实日历时间（情景 1h / 工作 1d / 语义 30d）——**两者不能混用**，
正确的关系是：**真实时间决定"还算不算数"，消息序号决定"刚说过的别再说"。**

### 4.3 预算耗尽时怎么办（**我们正缺的一环**）

原文 `[官方文档]`：
`If the budget is exhausted, then no more entries are activated even if the keys are present in the prompt.`
`Constant entries will be inserted first. Then entries with larger order numbers.`
`Entries inserted by directly mentioning their keys have higher priority than those that were mentioned in other entries' contents.`

⇒ **有明确的、写下来的优先级序**：常驻 > 直接命中 > 递归命中，同级按 `order` 大者优先。
**我们现在的做法是"top-8 硬截断"** —— 没有这一层优先级。
当预算不够时，**"谁先被牺牲"应该是明文规定的，不是排序函数的副产品**。`[推断]`

### 4.4 它的其他机制（记下形状，暂不深入）

- **选择性逻辑**：`AND ANY / AND ALL / NOT ANY / NOT ALL`（主键 + 次级键的组合）`[官方文档]`；
- **递归扫描**：条目内容里提到别的条目的键 ⇒ 把那条也拉进来；每条目三档
  （`Non-recursable` / `Prevent further recursion` / `Delay until recursion` + `Recursion Level` 分层）
  `[官方文档]`；
  **⚠️ 这条与我们已测过的"标签传播"形状相同，而我们实测它在粗标签下会退化**
  —— 区别在于它是**精确关键词**（不会退化成比 bucket 大小），我们是**标签交集**（会）。见 §5 的边界说明。
- **Inclusion Group / Prioritize Inclusion / Use Group Scoring**：同组多条被激活时**只留一条**；
  默认按 `Group Weight` 随机抽，开 `Prioritize Inclusion` 则**确定性地取 `order` 最大的**；
  开 `Use Group Scoring` 则**按键命中数**先筛出最优子集（主键 1 命中 = 1 分）`[官方文档]`。
  ⇒ **这正是我们缺的"同主题只取一条"，而且它给了一个确定性的选择规则（命中键数最多的赢）。**
- **Probability（触发 %）**：激活后再掷一次骰子，是"加噪"用的 `[官方文档]`。
- **位置（Insertion Position）**：`Before/After Char Defs`、`Before/After Example Messages`、
  `Top/Bottom of AN`、`@ D`（指定深度 + system/user/assistant 角色）、`Outlet`（不自动插，用宏手工放）
  `[官方文档]`。**位置决定影响力**（越靠后影响越大）——对我们意味着：
  **取回的认知该放在提示词的哪一层**，是独立于"取哪几条"的第二个决策。
- **向量匹配（Vector Storage）**：可以只用嵌入、不用关键词（`Scan Depth` 设 0）。
  ⚠️ 文档自己有一句警告，值得抄给我们自己看：
  `Since the retrieval quality depends entirely on the outputs of the embedding model,
  it's impossible to predict exactly what entries will be inserted.
  If you want deterministic and predictable results, stick to keyword matching.` `[官方文档]`
  ⇒ **这是"确定性"这条理由的外部背书**，也正是不引嵌入能得到的东西。

### 4.5 ⚠️ 根本差别（**为什么它只能是参考，不是蓝图**）

| | SillyTavern World Info | 本项目 |
|---|---|---|
| 条目谁写的 | **人手写**（卡作者） | **从真实对话抽出来**（LLM 抽 + 代码核证据） |
| "真相"在哪 | 作者的设定 | **互动本身（逐字证据）** |
| 会不会长大 | **不会**（除非人手改卡） | **会长**（这是全部意义所在） |
| 有没有"错"的概念 | **没有**（设定即真） | **有**（`说法`允许有偏，所以需要证据与失效） |
| 时间轴 | **消息序号**（chat 内，回退即清） | **真实日历时间**（跨月跨年） |
| 相似度 | 关键词精确匹配（或可选嵌入） | **标签交集（IDF 加权）** |
| 要解决的问题 | "扮演得像不像" | **"三个月后他了解我多少"** |

**⇒ 一句话**：**它解决"作者写的设定怎么在对的时候出现"，我们解决"关于这个人的判断怎么从互动里长出来、并且能被推翻"。**
前者是**注入**，后者是**认知**。⇒ 它的**调度机构**（sticky/cooldown/delay/预算优先级/同组择一）
可以借，**它的"记忆"本身**（静态条目）不能借。

### 4.6 与我们既有规划文的关系（**订正一处**）

项目内已有 `动态演化设计-种子与三向认知.md:162-174` 把酒馆当编译目标，
其中写「`sticky/cooldown` 是"长大"的机构」。

**这句话要订正**：按上面的原文核实，`sticky/cooldown/delay`
**管的是"这条要不要在接下来几条消息里继续出现"，不是"这条还算不算数"**——
它**不含任何"随时间变淡"的语义**（规则 5 甚至明说再次命中不刷新）。
⇒ **"长大"（权重与半衰期随真实时间演化）必须我们自己实现**；
`sticky/cooldown` 只能承担其中的**"刚想起来的事别马上重复"**这一小块。

## 5. ★ 已在本项目语料上**实测**的一条（不是转述）：绝对阈值到底管不管用

**来源（外部）**：ACT-R 只取 `A_i > τ`（`τ` 默认 0.0），全部低于 `τ` 就**明确返回"想不起来"**，
**它没有 top-k 这回事**；SOAR smem 是"cue 精确匹配后用显式权重 `balance`（默认 1）合成一个**绝对分**"。
⇒ 启发是：**top-k 恒定返回，把一个"想起 / 没想起"的离散问题强行连续化了。**

**实测**（阈值探针，留档不在本仓）：
把 top-8 换成"分数 ≥ τ 才要，可以返回空"，τ 按**实测 top-1 分数分位**标定（不能凭空取 0–1）。

### v1 语料（892 条 / 196 条对话，基线精度 0.6575）

| τ | 覆盖率 | 返回条数 | 精度 | **命中条数** | **每命中代价（取回/命中）** |
|---|---|---|---|---|---|
| 无阈值 | 1.000 | 7.84 | 0.657 | **1018** | **1.51** |
| **1.662（甜点）** | **0.898** | **6.55** | **0.733** | 814 | **1.42** |
| 1.955 | 0.704 | 4.83 | 0.720 | 441 | 1.51 |
| 2.188 | 0.245 | 1.96 | 0.708 | 67 | 1.40 |

### v2 语料（198 条 / 40 条对话，基线精度 0.2000）

| τ | 覆盖率 | 返回条数 | 精度 | 备注 |
|---|---|---|---|---|
| 无阈值 | 1.000 | 7.80 | 0.200 | — |
| 1.267 | 0.725 | 4.52 | **0.382** | 精度接近翻倍，仍答 72.5% 的查询 |
| 1.617 | 0.175 | 1.00 | 0.429 | 只剩 7 条查询 |

### ★ 实测结论（**与启发它的直觉不完全一致，这句必须一起说**）

1. **阈值确实能把精度抬上去**（v1：0.657→0.733；v2：0.200→0.382），
   而且**中间存在一个甜点**（v1 在 τ≈1.66、v2 在 τ≈1.27），**不是"越严越好"** —— 这与
   engram 那条"**两端都差、中间好**"的扫参形状**同型** `[实测]`。
2. **甜点上它是严格改善，不只是换权衡**：
   v1 在 τ=1.662 时 **精度 0.657→0.733（↑）、每命中代价 1.51→1.42（↓，即更省）**，
   代价是**覆盖率 1.000→0.898**（约 10% 的查询变成"没想起"）。
   v2 同向：τ=1.267 时 **精度 0.200→0.382、代价 4.88→3.45**，覆盖率 0.725。
   ⇒ **甜点之内，"少塞几条"同时买到了"更准"和"更省"。**
3. **但过了甜点就恶化**：v1 的代价从 1.42 回升到 1.65（τ=2.078），
   因为阈值开始把**本来会命中的条目**也筛掉（命中条数 1018 → 814 → 441 → **67**）。
   ⇒ **阈值不是白拿的，"精度 ↔ 覆盖"的取舍在甜点之外立刻回来。**
   上一轮那条"相关性 ↔ 新鲜度"的曲线，**换一个旋钮又出现了**。
4. **这条给了一个比"主题命中率"好的量具**：`每命中代价 = 取回条数 / 命中条数` 是**比值的比值**，
   对"取回几条"不敏感 —— 而"主题命中率"会随 top-k 自动变化（k=5/8/15 时基线分别是
   0.408/0.333/0.211，见 `decay2_report.md`）。**指标随 k 漂，就因为它是比例而不是代价。**
5. **一个负面结果（也很重要）**：我原本想用"该对话里有没有具体锚（`关于≠无`）"当
   **与 applicability 不共线**的外部信号来判"该不该答"。**实测它完全分不开**：
   τ=1.955 时"答"的有锚率 0.855、"不答"的 0.897（不答的反而更高）；各阈值下都在 0.86–0.90 之间打转。
   ⇒ **这个抓手作废**，得另找量具（候选见 §6.5、动作 A7）。

**⇒ 落到工程上的动作（可以直接写进下一轮预注册）**：
① 保留 top-k 作上限，但**加一个按语料标定的绝对下界**（`score ≥ τ`，τ 用**本次运行**的分数分位现标）；
② 判据改用**每命中代价**与**覆盖率**两个数，不再只看"精度"（也不再看会随 k 漂的"命中率"）；
③ **返回空必须有一条下游规则**（不注入记忆 ⇒ 只靠人格/情绪回话），否则阈值没有意义。

## 7. ★★ 能落地的动作清单（按"值不值得做"排序）

> 每条都写：**改什么 / 依据是谁 / 怎么验收**。**没有依据的不写。**

### A1 · 加一层"时序可见性"：`sticky` / `cooldown` / `delay`（**当前完全没有**）
- **改什么**：每条认知在**会话内**带三个计数器（单位先定义成"一个 user turn"）：
  `sticky_until_turn`（粘住到第几轮）、`cooldown_until_turn`、`min_turn`（第几轮之前不许出现）。
  规则照抄 SillyTavern：**cooldown 从 sticky 结束那一刻起算**；**已激活期间再次命中不刷新时长**。
- **依据**：SillyTavern 源码 `world-info.js:604-611`（计时器结构与单位）、`:518-529`（`#onEnded.sticky` ⇒ cooldown 起算点）、`:648`（过期判定）、`:626-630`（会话未前进即移除）；官方文档 Timed Effects 五条规则 `[源码][官方文档]`。
- **为什么值钱**：**这是唯一一条能把"半衰期"从打分轴里挪走的机制** ——
  现在我们用半衰期当**分数权重**，于是它必然和 applicability 抢同一根轴（上一轮那条单调权衡曲线的根源）。
  改成"**半衰期决定粘几轮**"之后，它就不再进打分函数了。
- **验收**：同一批 196 条查询，跑"有/无时序层"两版，比 **①重复率**（连续两轮取回同一条的比例，应当下降）
  与 **②每命中代价**（不应变差）。
- ⚠️ **必须先定接口**：我们现在的评测是"一条对话 = 一次查询"，**没有 turn 的概念** ⇒
  要先定义 tick（建议：一次检索 = 一轮），否则单位落不了地。

### A2 · 给认知加 `access_count` 与"再取回就变重要"（**用户最初设计里就有，至今没有**）
- **改什么**：字段 `access_count`、`last_access_ts`；重要性从**抽取时定死的常数**改成**可重算的派生量**：
  `importance = salience·exp(−λ(t−last_access)) + α·log(1+access_count) [+ β·情绪项]`。
- **依据**：engram `engram/importance.py:14-54`（λ=0.1/天、α=0.2、β=0.1，阈值 0.1）`[源码]`；
  同一形状在 ACT-R `B_i = ln(Σ t_j^(−d))`（d=0.5）与 SOAR 的 Petrov 近似（k=10）里独立出现 `[官方文档]`。
- **工程要点**：**取回时必须写回**（`log_access`）——engram 是在排序**之后**才 log 的
  （`graph.py:104-107` 注释："so the recorded rank reflects what callers actually got"）。
- **验收**：`access_count` 分布不应退化成幂律长尾（engram 的 gini 门槛思路可借）；**且必须验它不改坏命中率**。

### A3 · 把"多久以前"和"有多确定"当一等元数据交给下游（**改一处输出格式，几乎零成本**）
- **改什么**：取回的每条认知附带
  `{命中标签数, 查询标签数, score/查询标签数, 生成距今天数, 上次取回距今天数}`，
  且**写给 LLM 的记忆块里显式带上"多久以前"**（现在只给文本）。
- **依据**：SOAR epmem 的 `normalized-match-score = match-score/cue-size`（官方称可当相对置信度）
  与 `present-id − memory-id`（"这事儿过去多久了"）`[官方文档]`。
- **为什么值钱**：**"我记得你喜欢 X（3 年前）"和"（昨天）"是两句话**——
  这是陪伴场景里比命中率更值钱的东西，而且我们原料全有。

### A4 · 准入的第 (3) 道闸：**效用门**（现在只有"质量门"）
- **改什么**：新认知入库前，用 **IDF 加权标签交集**取最相似的 **s=10** 条旧认知，
  交 LLM 选 **ADD / UPDATE / DELETE / NOOP**。
- **依据**：Mem0 论文 §2.1（`s=10`、`m=10`、四操作）`[论文原文]`；
  Membrane 的"先查重再强化"是同一件事的更简版本 `[源码]`；
  CBR 的方向性结论：**参照系是"系统能力"，不是"这条好不好"** `[未能核实]`。
- **为什么值钱**：我们现在的准入是**质量门**（证据能不能核、标签合不合规），
  **完全没问"存了会不会让检索变差"** —— 这正是 892 条里那 65 组近似重复的来源。
- **验收**：入库条数下降比例 vs 命中率变化；以及"同一标签组的组内重复率"应下降。

### A5 · 冲突表示：借 Zep 的**四个时间戳**（**不用它的三元组**）
- **改什么**：给认知加 `valid_from / valid_to`（**这件事在现实里何时成立**）与
  `recorded_at / superseded_at`（**我何时知道 / 何时被新看法取代**）；
  检索时**默认只取有效的**，但可 `as_of` 回看"我当时认为他是什么样"。
- **依据**：Zep/Graphiti §2.2.2-2.2.3（四个时间戳 + 只在"时间上重叠的矛盾"才失效旧边 + **事务时间线上以新信息为准**）`[论文原文]`；
  engram 的 `Fact` 字段与 `close_fact()` 是更简版本 `[源码]`。
- **⚠️ 卡在哪（必须诚实说）**：**"两条认知是不是在说同一件事"我们还没解决**（§2.4.1 实测：
  精确标签集合相同只能当候选集，组内仍是不同判断；标签交集 ≥2 会退化成一片）
  ⇒ **A5 依赖 A4 落地**（让 LLM 在候选集内判"同不同一件事"），否则四个时间戳没有对手方。

### A6 · 判据改用"每命中代价 + 覆盖率"（**改判据，不改代码**）
- **改什么**：不再只用"主题命中率"（它随 top-k 自动漂：k=5/8/15 时基线 0.408/0.333/0.211），
  改用 **①每命中代价 = 取回条数/命中条数**（§5 实测 1.40–1.54，对 k 不敏感）与 **②覆盖率**。
- **依据**：§5 的实测（`out/threshold_gate.json`）+ LongMemEval 用"下游答题 + token"而非"是否共享标签"`[论文原文]`。
- **为什么值钱**：这是**解"拿尺子量自己"的第一步** —— 代价是比值的比值，不再以 applicability 为定义。

### A7 · 换量具：抄 LongMemEval 的 **`knowledge-update` / `temporal-reasoning` 子任务**
- **改什么**：从 196 条对话里**手工造**两类小测题：
  ① **知识更新类**（"他以前说 X，后来说了 Y" ⇒ 问"他现在怎么看 X"）；
  ② **时间推理类**（"这件事发生在什么时候 / 多久以前"）。
  用 **LLM-as-Judge 判下游回答**，而不是判取回集合的标签重叠。
- **依据**：LongMemEval（arXiv 2410.10813）§3.3（Recall@k / NDCG@k / LLM-as-Judge >97% 一致）、
  §5.3-5.4（key 扩展 +9.4%、time-aware 查询扩展 +6.8~11.3%）`[论文原文]`。
- **为什么值钱**：**这是唯一一条真正"不与 applicability 共线"的量具路线**，
  而且 `knowledge-update` 量的正是用户最初设计里的"**簇会随时间漂移**"。
- ⚠️ 成本：要人工造题。**但 196 条对话里造 30 条就够出一个有意义的读数。**

### A8 · ★ 用 **PPR** 替掉"标签交集求和"（**这条可能直接解决上一轮的死结**）
- **改什么**：把现在的 `score = Σ_{t∈交集} idf(t)` 改成——**先按这个和取种子，再在"认知-标签"二部图上跑带重启随机游走（PPR）**，
  用收敛后的概率排序；阻尼系数用 **`damping = 0.5`**（HippoRAG 的默认值）。
- **依据**：HippoRAG（arXiv 2405.14831）`[论文原文]`：
  - **`damping = 0.5`、synonymy `τ = 0.8`**，**在 MuSiQue 训练集 100 例上调出**；
  - 它把 **`node specificity s_i = |P_i|^(−1)`** 明确定位成 **"IDF 的局部替身"**
    ⇒ **我们的 `Σ 1/log(N/df+1)` 与它同动机**，这是我们这条路线**第一次拿到可引用的理论依据**；
  - **★ 消融（对本项目是判决性的）**：PPR 的两个替代方案 —— ①只用种子节点、②种子 + **一跳邻居** ——
    **都显著劣于 PPR**；而且 **"加一跳邻居但不做传播"比"只用种子"还差**。
- **为什么值钱**：**我们测过"标签传播"并得出"会退化"的结论，因此把传播关掉了。**
  HippoRAG 的消融说明：**退化的不是"传播"，是"朴素扩一跳"** ——
  真正的传播算子（PPR）在两个朴素方案之上都是正收益。
  ⇒ **我们当初的结论可能下早了**：该关掉的是"扩一跳"，不是"传播"。
- **验收**：同一批查询，比 **每命中代价 / 覆盖率 / 取回年龄** 三个数；
  并做与 HippoRAG 同构的消融（PPR vs 只用种子 vs 种子+一跳）。
- ⚠️ **诚实边界**：HippoRAG 的图是 **OpenIE 三元组图 + 稠密 synonym 边**，
  我们的是 **认知-标签二部图**。**图的性质不同，结论不能直接搬**，只能当"值得一测"的依据。

### A9 · 造"他变了没有"的量具（**目前完全没有，且 Literature 已把造法给全**）
- **改什么**：从 196 条对话里挑出**被推翻的例子**，照 MemoryAgentBench 的 **FactConsolidation** 造法做多选题：
  一条真认知 + 一条**更晚的、矛盾的**认知，**新事实排在后面**，问"他现在是怎么看的"，
  判分只看**选项正确率**；再加一个 **oracle 变体**（把前后两条一起喂进去）分离"找不到"与"读不懂"。
- **依据**：MemoryAgentBench（arXiv 2507.05257）`[论文原文]`：第四项能力 **`Selective Forgetting`**，
  子任务 **FactConsolidation-SH/-MH**，用 **MQUAKE 反事实编辑对**，上下文 6K–262K，指标 **Accuracy**；
  LongMemEval（arXiv 2410.10813）的 **`knowledge-update`** 题型与 **oracle 检索设置**。
- **为什么值钱**：**这是唯一真正"不与 applicability 共线"的量具**，
  而且它测的正是用户最初设计里的"**簇会随时间漂移（观念变化）**"。
- **落地提醒**：不要用 Mem0 的 DELETE / 原地 UPDATE 来"消解"矛盾
  ⇒ **学 Zep 的四时间戳，只标失效、不删**（见 A5）。

## 9. 收口：这一轮调研改变了什么

1. **"权重该定多少"这个问题，公开文献里没有答案 —— 而且是"没人在做"级别的空白。**
   generative agents 论文说 α 全 1、代码是 `[0.5,3,2]`，作者自注"应该学出来"；
   MemoryOS 在 limitation 里承认这些参数 "**without theoretical grounding**"；
   Mem0 的 `m=10/s=10` 直接给定、无消融；Zep 干脆不混权。
   ⇒ **我们上一轮那条"单调无拐点"的权衡曲线不是方法不对，是这个旋钮在外部就没有被解过。**
   能做的只有两件：**把权衡显式化**，或 **换算子（见第 3 条）**。
2. **但"用什么量"有答案，而且我们量错了。**
   LongMemEval 用"检索指标 + 端到端 QA + oracle 设置"三档；MemoryAgentBench 的 `Selective Forgetting`
   用"以新压旧"的 Accuracy；MemBench 把 **`Reflective Memory`（隐式高层偏好）单独列为一个维度**，
   并给出 **Memory Capacity**（容量-性能拐点）。
   ⇒ 我们的"主题命中率"**既与 applicability 共线、又随 k 漂**，**该换**（A6/A9）。
3. **★ 最重要的单条发现：我们可能过早否定了"传播"。**
   我们测过标签传播、结论是"会退化成比 bucket 大小"，于是把它关掉了。
   而 **HippoRAG 的消融说的是另一件事**：**"种子 + 一跳邻居"比"只用种子"还差，但 PPR 显著优于两者**
   ⇒ **该关掉的是"朴素扩一跳"，不是"传播"**。且它的 `damping = 0.5` 是现成默认值。
   **这条直接对应我们上一轮的死结**（A8）。
   > ⚠️ **2026-10-02 订正：这条已被实测否掉。**
   > 第十轮第二步真做了 PPR：**零交集条目最优名次中位 633**（要求 ≤8），**P1 / P2 / P3 全部不满足**。
   > ⇒ **传播在我们的语料上确实不成立**——原因不是"朴素扩一跳 vs PPR"，
   > 而是**查询太宽**：种子中位 **640/892 = 71.7%**，
   > 且重启项 `1−d = 0.5` **结构性锁住 ≥50% 的质量留在种子集里**。
   > ⇒ **v1 规格 §4「不用图传播」不需要改——本轮给了它机制解释。**
   > （见 §6 第 3 条；那次否掉它的实测见本文 §9 的订正）
   >
   > **★ 这条订正的教训值得单独记**：我把它写成"最重要的单条发现"时，**它还只是一个文献推理**。
   > ⇒ **乐观假说没有先测，就不要写成结论。**
4. **"不用嵌入"在文献里不是孤例，但我们这个组合没人走过。**
   > ⚠️ **2026-10-02 订正（措辞与立场，两处）**：
   > ① **"不用嵌入"这个说法的出身是错的**——它来自任务书里的**工程约束**
   > （不许 `pip install` / 不许下模型 / 不许引向量库），被错误硬化成了设计约束。
   > **用户真实立场是"要向量"，而且他自己列出了向量的失效面**
   > （`00_项目文档.md` §3.1 / §3.2）。**中介层走的是连续几何路线。**
   > ② 本节列的**文献证据仍然有效**——SeCom 的 BM25 反超、HippoRAG 的 `node specificity ≈ IDF`、
   > Zep 把 BM25 列为一等检索函数。但它们说明的是
   > **"词法/符号通道不该被丢掉"，不是"不能要向量"** ⇒ **正确读法是两条通道并存**。
   > ③ "**没人做过的那一格**"——按 `00_项目文档.md` §1 的立场读：
   > **"未找到"是成本项，不是卖点；有现成的能用更好。**
   - **有背书**：SeCom 实测 **BM25 词法反超 MPNet 稠密**（LOCOMO GPT4Score **+11.98**）；
     HippoRAG 的 `node specificity` 明确是 **IDF 的局部替身**（与我们的公式同动机）；
     Zep 把 **BM25 列为三种一等检索函数之一**；MemBench 专门有 `Reflective Memory` 这一维。
   - **没人做过的**：**"标签交集 + 逐字证据 + 三档真实时间半衰期"** 这个组合。
     大家都是"符号/词法通道 + 向量通道"并用。
     ⇒ **我们的位置是生态里没人占的那一格 —— 不是坏事，但也意味着没现成答案可抄。**
5. **我们真正缺的不是打分，是"时间"的三层（这三层一个都没有）。**
   ① **会话内可见性**（sticky/cooldown/delay 的语义，单位要自己定）；
   ② **跨会话有效期**（Zep 四时间戳 `valid_at/invalid_at` + `created_at/expired_at`）；
   ③ **再取回就变重要**（MemoryBank 的 `S += 1`、engram 的 `α·log(1+access_count)`、
   AI Dungeon 的"最少被使用先淘汰"）。
   ⇒ 其中 ① 最值钱的地方在于：**它能把半衰期从打分轴里挪走**，
   而半衰期与 applicability 抢同一根轴**正是上一轮那条单调曲线的根源**。
6. **engram 那句自我批评值得抄进我们的纪律**：它的 README 曾在默认值改了之后
   继续挂着旧数字当"default"，没人能从表格里看出来 ⇒
   它的硬规矩是"**每个发布的数字都必须有人量过，且量的命令写在数字旁边**"，
   并且**每个闸门都被故意弄失败过**，以证明它能区分"没失败"和"没跑"。
   **这与我们 `0.286` 锚点被引用好几轮、却在冻结语料上重建不出来是同一个形状。**
   （准确地说：我上一轮证明的是**它在冻结语料上重建不出来**（同口径实测 0.4677），不是"不许引用"。）
   ⇒ 建议把"A6 每条判据必须与所测的数在同一次运行里现测"升级为本项目硬约束。
7. **一个必须一起说的反面证据**：Mem0 论文的表里，
   **full-context 的 LLM-as-a-Judge（72.90）高于 Mem0（66.88）与 Mem0^g（68.44）**。
   它赢的是延迟（p95 1.44s vs 17.12s）与 token 成本，**不是准确率**。
   ⇒ **"记忆系统比长上下文更好"这句话，在它自己的论文里就不成立**；
   我们的目标也不是"打败长上下文"，而是**"长期不崩 + 像记得他"**——
   而这恰好是它测不了的东西。
