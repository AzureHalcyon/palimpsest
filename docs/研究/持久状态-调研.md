# 持久状态：调研

起因：SST 声称冻结权重下，靠维护跨生成步的隐状态缓存就能“涌现元认知”。本文核查这条证据，
再看桌宠、陪伴产品、agent 框架实际怎么维护 persona，最后回答：在只有 API 的前提下，
“一个连续存在的状态”能做到什么、该怎么落。

分稿：[`持久状态-分稿/E-SST核查.md`](持久状态-分稿/E-SST核查.md)、
[`持久状态-分稿/F-产品做法.md`](持久状态-分稿/F-产品做法.md)。

## 0 结论

1. **SST 的机制是真的，增益和“元认知”不可信。** 它的状态视界只有 26–37 个 token，
   是工作记忆，不是记忆层；跨会话一点忙也帮不上。
2. **现实世界里 persona 几乎全是常量。** 做成变量的只有“事实层/变量层”，
   没有一家把“她是谁”交给模型自由改写，**也没有一家对 persona 设衰减**。
3. **能搬的是三条原则**：状态持续且增量、衰减；状态外化成可读文本；每轮装载 + 周期性重锚。
4. **不能搬的是隐状态本身**。API 侧最接近的替身是“稳定的缓存前缀 + 只追加”，
   它让设定在多次调用里是同一份计算，但绝不是“跨步延续”。

## 1 SST 到底怎么回事

机制：32 层各一份缓存，位置在注意力之后、FFN 之前，存该层 FFN 之后的残差流，
把本层输出回灌本层输入（绕 FFN 的自环）；α 手设、全维度共用；写入整块覆盖，
衰减只发生在读取侧 ⇒ 残留是几何衰减，α≈0.027 时半衰期约 26 token。`[一手]`
摘要写的 sliding window 其实没有窗口，只用到最近一格，续作自己承认。`[一手]`

增益：基准是两阶段——先 r=2 全跑，再把**答错的题**用 r=4 重跑。还原论文自己的中间数，
GSM-8K 重试前 83.02%（对照 84.50%）、ARC 重试前 86.35%（对照 86.86%），**两个都低于对照**；
89.01/91.04 是靠“用测试集标签决定给谁加算力”拿到的。没有任何同等算力对照。`[一手]`

元认知：五类证据每条 n=1，无 rubric、无第二读者；“metacognitive framework”只出现一次且未定义。
引用面：Semantic Scholar 1 次（且只是转述作者自述）、OpenAlex 0、无代码、无复现、v1 从未修订。
续作 V2 承认 v1 的递归“是为稳定，不是深思”，改成语料微调 + oracle 路由，同算力下 GPQA 高 5.05 分
——机制有真东西，但和元认知不是一回事。`[一手]`

判定：**信机制 / 不全信增益 / 不信元认知。**

## 2 桌宠、陪伴产品、agent 怎么维护 persona

| 系统 | persona 是常量还是变量 | 谁改 | 衰减 | 防漂移手段 |
|---|---|---|---|---|
| Letta / MemGPT | **变量**（内存块，XML 前置） | 模型自己，或 sleep-time 模式下另一个 agent 后台改 | 无 | 字符上限（写满必须重写）、`read_only` 标记、description 指导、注入 last-modified 时间戳 |
| SillyTavern 角色卡 | 常量 | 人 | 无 | 位置 × 频率（author's note 按深度插入、每 N 轮一次） |
| SillyTavern + EJS 扩展 | **变量**（只到变量层：好感度、flag） | 模型（输出里的隐藏标签被执行） | 无 | 无（社区扩展） |
| Character.AI Facts | **变量**（事实层） | 系统自动抽取 | 无 | 身份层根本不给写 |
| Open-LLM-VTuber | 常量（yaml 文件） | 换文件 | 无 | 表情标签对话结束回默认 |
| DesktopMate | 常量（IP 角色） | 不适用 | 无 | 无 |
| Generative Agents | 常量→切成初始记忆 | reflection 写回记忆流 | 无 | 无 |
| AutoGen / MetaGPT | 常量字符串 | 无 | 无 | 无 |

三处半是真的变量，且都停在事实/状态层：

1. **Letta**：模型用 `memory_insert` / `memory_replace` 改自己的 persona 块；更狠的是 sleep-time 模式
   会把编辑工具从主 agent 收走，交给另一个**可更强的** agent 在后台按频率改。这是目前唯一找到的
   “正式的后台改写者”。防护只有四件：字符上限、`read_only`、description、时间戳。
   **没有版本历史、没有 diff、last-write-wins、没有一致性校验、没有衰减。** `[一手]`
2. **SillyTavern + EJS**：模型输出 `<% setvar('affinity', …) %>`，渲染时执行并写回变量。
   只到变量层，且是社区扩展；官方同类 PR 已关闭未合并。`[一手]`
3. **Character.AI**：自动抽事实，可改可关；身份 Definition 静态不动。`[二手]`
3.5) **Generative Agents**：身份是一段自述被切成记忆，没有 persona 槽位；reflection 改的是推断。`[一手]`

空白很清楚：**没有人做“身份衰减”，也没有人做“身份改动的版本化与核验”**。
Letta 的 last-modified 时间戳是唯一一个把“设定多久没动”变成模型可见事实的做法。

## 3 对 API 的可迁移映射

| SST 的要素 | API 侧能不能还原 | 怎么还原 |
|---|---|---|
| 状态持续存在 | 能（三到五成） | 一个常驻、只增量更新的状态块，不是每轮重拼 |
| 加权衰减 | 能 | 文本状态里带强度与半衰期，按轮衰减、回基线 |
| 状态外化成可读 | 能，且更好 | 文本天然可读可审计，代价是丢掉“不可读的压缩” |
| 生成步之间延续 | **不能（0）** | 模型每次调用都是新的；缓存前缀让“同一份设定”是同一份计算，但状态不会自己延续 |
| 位置内多遍复算 | 部分 | v1 的可测增益很可能全在这一条；我们能做的是“同一位置再看一遍”，不是同一 token 多算 |

**缓存前缀是真的东西，但不是状态延续**：DeepSeek 的上下文硬盘缓存让固定前缀不重算，
所以 persona + 状态块放前面、只往后追加，比每轮重拼更接近“同一份想法”。
它省的是算力，不是记忆。

## 4 我们能做什么（草案）

三块分开，写权限不同——这是本次唯一直接可用的结论：

| 块 | 内容 | 谁能写 | 变化 |
|---|---|---|---|
| 身份块 | 她是谁、怎么说话、在意什么、知道自己是什么 | 只能她提议 + 外部核验；平时只读 | 极少改，改时留版本 |
| 状态块 | 现在在做什么、上回停在哪、心境（强度/缘由/时间）、最近在意的事 | 她自己，每轮可写 | 持续、增量、带衰减 |
| 记忆块 | 事件 | 记忆层 | 只增，归档时巩固 |

四条工程约束，全部来自人家的教训：

1. **身份块有字符上限**，写满就必须重写而不是追加（Letta 的做法，防止越写越厚）。
2. **状态块不进身份块**：改状态自由，改身份要核验。
3. **装载顺序**：身份 → 状态 → 记忆；身份在最前，状态紧随，记忆按需。
4. **周期性重锚**：身份块每隔 N 轮尾置一行短句（SillyTavern 的“位置 × 频率”），
   另外注入一行“设定上次改动：日期”，让“多久没动”成为她看得见的事实。

不给状态设“向量”：调研的结论是向量不可读、绑模型，且表达不了“对象与缘由”，
最多是半个心境。

## 5 该验证什么

- 状态块在不在，会不会让她“接着上次说”（对照：有/无状态块，同一组追问）；
- 衰减做不做，隔天/隔周提到同一件事，语气与详略是否不同（对照：不衰减）；
- 周期重锚有没有用（8 轮后的探针分数，对照：不重锚）；
- 身份块字符上限会不会逼出“重写”——重写完身份是否还认得出（人读）。
