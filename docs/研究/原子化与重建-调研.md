## 0 摘要

1. **“全都打碎再重建”不是 2026 年文献的收敛点。** 收敛点是**选择性原子化 + 原文保真 + 读取时组装**。
   最强的几篇里，TriMem、AnchorMem、E-mem 都在说同一件事：原子可以加，原文不能丢；
   ROAM 补的是另一条：原子用于管理，不用于表达。
2. **palimpsest 已经在做“重建”了。** `recollect` 不是检索，是把材料交给编写模型写成第一人称回忆，
   只有回忆进上下文。真正缺的是**跨事件组装**、**读侧线索拆解**、**反馈只动结构**，不是“重建”这个口号。
3. **REM 复核结果：token 级精确成立，byte 级不成立；“语义键”不参与重建；“zero-knowledge-like”不成立；
   存储膨胀 3,000–6,000 倍。** 它是“语义索引 + 每段一个过拟合查表网络”，概念可借，实现不可借。
4. 对 palimpsest 的建议：**事件仍是记忆的单位，原子只做可弃的索引层**；先做读侧线索拆解（不动存储），
   再做影子原子，再做跨事件重建，最后才考虑共激活边。

## 1 问题

朋友的想法：把记忆编码、处理之后“全都打碎”，原子化，再以某种方式重建；新记忆进来也走同一条流水线。

这句话里其实捆了三件可以分开的事：

| 动作 | 通俗说法 | 代表工作 |
|---|---|---|
| 写入时原子化 | 把一段经历拆成命题/单元再存 | AtomMem、MemCode、ai-memory-mcp |
| 读取时重建 | 按当前情境现场组装，而不是取回原文 | MRAgent、MemHarness、EverMemOS |
| 反馈再巩固 | 检索本身反过来改写记忆结构 | REALM |

另外还有第四件，属于第二阶段：**参数化**（把原子编译成 LoRA/潜 token），代表是 Doc2Atom、MemGen。

本文只回答三个问题：文献到哪一步了；palimpsest 该接哪一段；REM 的自报能不能复现。

## 2 文献地图（逐篇核过）

### 2.1 写入时原子化

- **AtomMem** `[论文]` [arXiv 2606.19847](https://arxiv.org/abs/2606.19847)
  用 Fact Executor 抽“高价值原子事实”，再组织成**层级事件结构 + 时间画像**；检索时激活关联图。
  LoCoMo 多跳 F1 从 20.97 提到 37.03（相对 +76.6%），而且 AtomMem-Flat（去掉层级、只留原子）
  仍然比原始对话基线强，说明**原子本身有用**；层级和画像再加一层。
  可借：原子可以做事实层；不可借：它仍然保留了事件骨架，不是“只有原子”。
- **ROAM** `[论文]` [arXiv 2609.09778](https://arxiv.org/abs/2609.09778)
  原子积累后必然冗余/重叠/冲突。ROAM 把原子对分成独立/等价/包含/冲突四类，用 Primary/Evidence
  两种角色管理，回答时再 **Fusion** 成更紧凑、甚至非原子的视图。最高 +29.8 个百分点；
  消融显示 Fusion 在角色组织之外还有独立增益。
  **这是最重要的一条设计原则：原子用于管理，不用于表达。**
- **MemCode** `[论文]` [arXiv 2610.19472](https://arxiv.org/abs/2610.19472)（NeurIPS 2026 poster）
  把对话改写成自包含的原子记忆单元（AMU），映射进可学习码本，用码本共现拓扑做向量之外的检索路径；
  在线原子写入、离线异步巩固。构建时间 40–130 秒，比 LightMem 快 3–21 倍。
  可借：原子化可以和“码本/离散索引”结合；不可借：它仍是问答基准上的工程。
- **ai-memory-mcp** `[二手]` [PR #751](https://github.com/alphaonedev/ai-memory-mcp/pull/751)
  `memory_atomise` 把一条粗记忆拆成 2–10 条原子命题，每条独立存储并保留父指针。
  这是“写入原子化”的最小工程实现，适合当原型参考。

### 2.2 读取时重建

- **MRAgent** `[论文]` [arXiv 2606.06036](https://arxiv.org/abs/2606.06036)（ICML 2026）
  记忆表示成 Cue–Tag–Content 图，**把 LLM 推理直接接进记忆访问**：边推理边探索、边剪枝，
  不跑固定的 top-k 或固定跳数。LoCoMo/LongMemEval 上最高 +23%，同时降 token 和耗时。
  可借：**重建不是一次生成，是一个带证据的搜索过程**；不可借：它仍然以“图”为骨架。
- **MemHarness** `[论文]` [arXiv 2607.28272](https://arxiv.org/abs/2607.28272)
  把旧经验原样塞回上下文会造成**负迁移**：旧经验越“正确”，在错误情境下干扰越大。
  它让策略模型按当前状态批判并重建取回的经验，用 GRPO 端到端学出来；ALFWorld/WebShop 上
  明显优过静态记忆基线，OOD 更稳。
  可借：**重建的目标是服务当前决策，不是还原过去**；这也是“保真度”要分层的理由。
- **EverMemOS** `[论文]` [ACL 2026](https://aclanthology.org/2026.acl-long.2125/)
  三阶段生命周期：MemCell（情景轨迹 + 原子事实 + 时限前瞻）→ MemScene（主题巩固 + 用户画像）→
  **Reconstructive Recollection**（以“必要且充分”为目标，主动组装当前问题所需的 grounded context）。
  在 LoCoMo/LongMemEval/PersonaMem-v2 上 SOTA。
  可借：**原子→场景→重建**这条生命周期，和 palimpsest 的“事件→归档→回忆”结构同构。
- **AnchorMem** `[论文]` [arXiv 2604.17377](https://arxiv.org/abs/2604.17377)（ACL 2026 Findings）
  从交互历史抽原子事实做**检索锚点**，但**原始上下文作为不可变背景保留**；检索时用锚点定位，
  重建时用关联的原始文本块和事件。动机是普鲁斯特效应：一个锚点触发整体回忆。
  **这是和 palimpsest “材料只读”最合拍的一篇**：锚指路，原文还魂。
- **TriMem** `[论文]` [arXiv 2605.19952](https://arxiv.org/abs/2605.19952)（NeurIPS 2026 poster）
  同时维护三种粒度：带来源标识的原始对话段（保真）、原子事实（高效检索）、合成画像（深度推理）；
  用 TextGrad 迭代优化抽取/画像提示，不更新参数。
  **反证：只留原子不够，原文层要留着。**
- **E-mem** `[论文]` [arXiv 2601.21714](https://arxiv.org/abs/2601.21714)（ICML 2026）
  明确批评“破坏性去上下文”：把连续对话压成预定义嵌入/图，会切断深度推理需要的叙事完整性。
  它保留未压缩的上下文，由多个助手智能体各自维护，主控做全局规划，检索时在局部推理后再聚合。
  LoCoMo F1 >54%，比 GAM 高 7.75%，token 降 70% 以上。
  可借：**“打碎”的代价是真实存在的，不是实现问题。**

### 2.3 反馈再巩固

- **REALM** `[论文]` [arXiv 2609.16053](https://arxiv.org/abs/2609.16053)
  检索不是终点，而是记忆演化的驱动力。长期记忆组织成异构认知图，用自适应组合的图搜索原子取证据，
  再根据检索反馈**持续再巩固**。LoCoMo 75.97、LongMemEval 65.11，分别比最强基线高 7.17/1.31；
  消融显示再巩固会把相关单元逐步重组成更连贯的局部结构。
  可借：**共激活可以长结构**；不可借：它会改写记忆本身，和 palimpsest 的“材料只读”冲突。
- **CA3Mem** `[论文]` [AAAI 2026](https://ojs.aaai.org/index.php/AAAI/article/view/38300)
  海马启发：记忆图 + **生成式记忆重组**（从图中合成新方案）+ 扩散激活检索。
  OSWorld 23.85%、WebArena 63.2%；困难 Workflow 子类比 GPT-4o 高 10.3 个百分点。
  可借：激活和重组可以并用；**注意 10.3 是子集，不是整体**。
  不可借：生成式重组在陪伴场景里等于编故事，只能做成显式动作。

### 2.4 参数化（第二阶段）

- **Doc2Atom** `[论文]` [arXiv 2606.12400](https://arxiv.org/abs/2606.12400)
  文档分解成语义类型化原子，每个原子编译成独立 micro-LoRA + 溯源键；推理时轻量路由器
  只组装相关原子成查询专属适配器，注入冻结基座。六个 QA 基准超过 Doc-to-LoRA，内存更低。
  这是“把记忆放进模型”最具体的现成路径。
- **MemGen** `[论文]` [arXiv 2509.24704](https://arxiv.org/abs/2509.24704)（ICLR 2026）
  memory trigger 监控推理状态决定何时调记忆，memory weaver 以当前状态为刺激生成一段潜 token
  序列作为机器原生记忆，主干模型冻结。八个基准上比 ExpeL/AWM 高 38.22%，比 GRPO 高 13.44%。
  **注意：38.22 是对 ExpeL/AWM，不是对 GRPO**（两段材料都写错了）。

### 2.5 概念/预印本

- **REM** `[论文/预印本]` [Zenodo 17220514](https://zenodo.org/records/17220514)
  每个 episode 编码成一个紧凑神经网络，从语义键确定性重建原文。§5 单独复核。

## 4 和 palimpsest 的对照

### 4.1 已经在做的

- **`recollect` 就是生成式重建。** [`write.py`](../../memory_v2/read/write.py) 把材料交给编写模型；
  [`write-memory.txt`](../../memory_v2/prompts/write-memory.txt) 明确要求“这是回忆，不是原文；可以概括、合并；
  只写材料里有的”。只有这段回忆进上下文。
- **`recall` 是激活。** 线索 → 种子 → 沿边和内容扩散 → 竞争 → 选一件（`read/activate.py`）。
- **材料只读。** note 只增不改，场次记录不重写，没有“说法层”。

所以“记忆不是被取回，是被重写”这件事，palimpsest 已经做了；文献里的口号不是新东西。

### 4.2 真正缺的

1. **一次只能重建一件事。** [`recollect`](../../memory_v2/api.py) 只接受一个 event，
   把它的 notes 拼起来交给编写模型。跨事件的“上回说到一半”“去年今日”在结构上做不出来。
2. **线索没有拆。** `recall` 拿一组关键词直接激活；复合线索靠一次向量匹配容易漏。
3. **反馈只到 `access + 0.1`。** 取用不会改变结构；REALM 那一派的核心是“检索本身是演化驱动力”。

### 4.3 一条数据观察

仓库里能看到的 `loop` 记忆样本（`.local/memlive`）只有 9 件：note 中位 102 字、中位 2 个分句，
5/9 有两个以上分句。样本很小，不足以定论，但提示：**note 已经接近“半原子”**。
真正的问题可能不是“note 太大”，而是“一次只取一件”。先量再建原子层，比直接开工省很多。

（两场 38/32 轮的真实数据不在这个 checkout 能看到的 graph 里；要做对照实验得先把它们找回来或重跑。）

## 5 REM 复核

### 5.1 它声称什么

摘要原话：每个 episode 编码成一个紧凑神经网络，能从**语义键**确定性重建原始内容；支持文本、源码、
二进制；原型演示线性扩展、CPU 高效、字节级精确。

正文里有两处关键限定，经常被摘要盖过：

- §5.1：语义检索只用于**选 cell**；重建时必须喂回**训练时那个精确的键**，不是查询向量。
- §7.5：对键的精确匹配极度敏感；当前实现没有容错机制。

也就是说，论文自己已经承认：**语义负责选，精确键负责重建**。摘要的“from a semantic key”是压缩过的说法。

### 5.2 怎么核

- 仓库：[MigelSmirnov/ReMemory](https://github.com/MigelSmirnov/ReMemory)，commit
  `3fe65d01b62b17314a9bd9e281fc7bac750f6f68`（2025-09-28）。
- 环境：Python 3.13.0，torch 2.10.0+cu126，CPU。
- 直接用作者预训练的 7 个 cell（`memory_cells/vec_0001..0007`），不改模型、不重训；
  用每个 cell 自己的 `context_vector.json` 重建，和 `data/memory_stories_with_keywords.json` 的原文逐字比。
- 另训三个新 cell：同一段中文，分别用**随机向量、全零向量、全一向量**做键，看是否都能精确重建。
- 另测 codec 的往返：不同字节长度的字符串，`decode(encode(s)) == s` 是否成立。

复现命令见文末附录。

### 5.3 结果

**A. 预训练 cell 的重建**

| cell | tokens | 原始字节 | 参数 | epochs | final loss | token 级精确 | **文本级精确** | 模型大小 | 膨胀倍数 |
|---|---|---|---|---|---|---|---|---|---|
| vec_0001 | 781 | 1,172 | 1,018,699 | 251 | 8.32e-6 | ✅ 1.0000 | ❌ | 4.08 MB | 3,479× |
| vec_0002 | 759 | 1,139 | 980,595 | 256 | 5.98e-6 | ✅ 1.0000 | ❌ | 3.93 MB | 3,446× |
| vec_0003 | 719 | 1,079 | 913,175 | 259 | 9.33e-6 | ✅ 1.0000 | ❌ | 3.66 MB | 3,388× |
| vec_0004 | 597 | 896 | 722,367 | 258 | 7.81e-6 | ✅ 1.0000 | ❌ | 2.89 MB | 3,228× |
| vec_0005 | 607 | 910 | 737,167 | 257 | 5.60e-6 | ✅ 1.0000 | ✅ | 2.95 MB | 3,243× |
| vec_0006 | 507 | 761 | 595,917 | 257 | 7.50e-6 | ✅ 1.0000 | ❌ | 2.39 MB | 3,136× |
| vec_0007 | 2,150 | 3,225 | 4,820,551 | 258 | 8.67e-6 | ✅ 1.0000 | ✅ | 19.29 MB | 5,980× |

token 级全对；**文本级只有 2/7 对**。差的那 5 个不是模型错，是 codec 丢了一个字符（见 D）。

**B. 键扰动**（vec_0006，相对 L2 噪声）

| ε | token 准确率 | 字符准确率 |
|---|---|---|
| 0 / 1e-4 / 1e-3 | 1.000 | 0.998（codec 丢字） |
| 0.01 | 0.304 | 0.005 |
| 0.05 | 0.008 | 0.005 |
| 0.1 | 0.367 | 0.005 |
| 1.0 | 0.000 | 0.005 |

和论文自报的“ε=0.01 约 0.2、ε≥0.05 为 0”量级一致。但这不是“零知识”，是**单点过拟合**：
训练只有一个 (k,t) 对，函数在 k 附近陡峭，离开就崩。

**C. 无语义键也能精确重建**

同一段 510 字节中文，分别用三种键训练新 cell：

| 键 | epochs | 训练时间 | 参数 | token 准确率 | 文本相等 |
|---|---|---|---|---|---|
| 随机单位向量 | 256 | 2.85 s | 394,196 | 1.0000 | ✅ |
| 全零向量 | 279 | 0.58 s | 394,196 | 1.0000 | ✅ |
| 全一向量 | 258 | 0.49 s | 394,196 | 1.0000 | ✅ |

**结论：键的语义内容对重建没有任何作用。** 键只是一个索引/种子；每个 cell 学的是“这个键 → 这段 token”。
全零键也能精确重建，说明“从语义重建”这个说法不成立；“语义”只发生在选 cell 那一步。

**D. codec 不是无损的**

`encode_text_to_token_ids` 先把文本变 Base64，`rstrip("=")`，再两两合并成 12-bit token。问题是
它用 `range(0, len-1, 2)` 丢掉了长度为奇数时最后一个 Base64 字符；对应 `len(bytes) % 3 == 2` 的输入，
解码后最后一个字节/字符消失。

| 输入 | 字节数 | 往返结果 |
|---|---|---|
| `"a"` | 1 | ✅ `"a"` |
| `"ab"` | 2 | ❌ `"a"` |
| `"abc"` / `"abcd"` | 3 / 4 | ✅ |
| `"abcde"` | 5 | ❌ `"abcd"` |
| `"abcdefg"` | 7 | ✅ |
| `"abcdefgh"` | 8 | ❌ `"abcdefg"` |
| 中文 3 字节的倍数 | 3k | ✅ |

约 1/3 的字节长度会中招；作者自己的 7 个 cell 里有 5 个中招。**“byte-exact recall”作为实现声明不成立**，
至少在这个 commit 上不成立。论文的 “exact = 1” 很可能只测了 token 序列相等，没有测解码后的文本。

**E. 论文与代码不一致**

- 论文 §3.1 说“single hidden layer”；代码 `MiniNetRegression` 是
  `Linear → ReLU → Linear → ReLU → Linear`，**两个隐藏层**。
- 论文自报的参数数（507 token 的 0.596M、2150 token 的 4.821M）和**代码的两层结构**对得上
  （我们复算 595,917 / 4,820,551）。也就是说数字来自代码，文字描述写错了。
- 这不算致命，但说明“作者自报”的正文也需要对着代码读。

**F. “zero-knowledge-like”不成立**

- 键就明文存在每个 cell 的 `context_vector.json` 里，和模型放在一起；`model.pt` 也没有加密。
  拿到 cell 目录的人不需要“破解”任何东西。
- 论文 §4.3.1 自己声明不是密码学意义上的 zero-knowledge；但“没有精确键就完全无法重建”在
  威胁模型上不成立，因为键没有离开数据目录。
- 单点过拟合导致的键敏感性，是**没有泛化**，不是**保密**。

### 5.4 判读

REM 的真实形态是：

> **一个语义最近邻索引（选 cell） + 每个 episode 一个过拟合 MLP（把固定键映射到固定 token 序列）。**

它做到的事：

- 固定键下 token 级精确重建（✅）；
- 线性训练/推理时间（✅，但常数很大）；
- cell 之间隔离（✅）；
- 换键就失败（✅，但这是过拟合的必然结果）。

它没做到、也不打算做的事：

- 从**新的**语义线索重建（❌；必须用训练键）；
- 字节级无损（❌；codec 对 1/3 输入丢最后字节）；
- 紧凑存储（❌；3,000–6,000 倍膨胀）；
- 泛化、跨 episode 推理（论文 §7.4 自己承认）；
- 保密（❌；键明文）。

**对 palimpsest 的结论：概念可借，实现不可借。** “记忆是函数不是存储”这个视角可以用来讨论第二阶段；
但“每段记忆训一个小网络”在成本上直接出局——按它自己的比例，一场 38 轮对话（几万字）会变成
几百 MB 到几 GB 的模型文件，而且不能跨事件回忆。更不能把 note 换成这种网络：note 是她的手迹，
网络是查表。

---

## 6 真正值得借的三条

1. **锚点/原文分离**（AnchorMem）。原子只做检索锚，note/原文永远是生成材料。
   这条同时满足“检索更细”和“材料不腐化”。
2. **管理/表达分离**（ROAM）。内部用原子去重、判冲突；对外表达时融合回连贯的一段。
   不要拿原子当输出单位。
3. **反馈只动结构**（REALM 的保守版）。共激活攒够了才长一条 `相关` 边，材料一个字不改。
   这和 palimpsest 现有的“重放证据攒到 4.0 才建边”“原文不删、只剪连接”是同一套哲学。

另外两条警示：

- **MemHarness 的负迁移**：原样回放旧经验会害了当前决策；重建要服务“现在”，不是还原“过去”。
- **E-mem 的去上下文**：把连续经历压成预定义结构，会切断叙事完整性；“打碎”的代价是真代价。

## 7 如果要做：四步，从最便宜的开始

### 第 0 步：原子化问题，不动记忆（半天）

把 `recall` 的线索拆成 1–3 个子查询，各自激活后取并集，再走原来的竞争。
复合线索的漏召回会立刻改善，存储一个字不用改。这是 atomir 的读侧做法，也是 MRAgent 的
“边推理边探索”的最小版本。

- 改哪：`loop/memory_bridge.py::_recall`（或 `read/activate.py` 外面包一层）。
- 失败模式：子查询拆错会把噪声带进来；用原来的赢家规则兜底。
- 回滚：开关关掉即回旧路径。

### 第 1 步：影子原子层（派生，不是权威）

新增 `memory_v2/store/atoms.py`，从 note 派生 1–5 条原子，带类型（事实/立场/未完成/关系/细节）
和溯源 `(event_id, note_hash, model)`；note 改名或改写就整体失效、可重建，像 `content-index.json`
一样是缓存。**只用于种子和过滤，不交给编写模型。**

- 改哪：`store/` 新模块；`read/activate.py` 的种子阶段可用原子做二级过滤。
- 失败模式：原子化丢语气；用“原子不进材料”挡住。
- 回滚：删缓存文件即恢复；note 不动。

### 第 2 步：跨事件重建（真正的升级）

`recollect` 支持多事件（或 `with` 参数）。召回给出“主事件 + 相关事件 + 命中原子”，
编写模型拿到的是**提纲**而不是原文堆：时间线、谁在场、当时怎么想、后来怎么变、哪件还没完。
输出附一份**不进上下文**的溯源表：每个事实性分句对应哪个 event id。

- 改哪：`loop/memory_bridge.py::_recollect`、`memory_v2/read/write.py`、`prompts/write-memory.txt`。
- 失败模式：跨事件编造；用溯源表 + 负样本测试挡。
- 回滚：默认单事件，多事件是显式参数。

**保真契约（三层，不同标准）：**

| 层 | 标准 |
|---|---|
| 事实层（日期、数字、谁说的、做了什么） | 必须可溯源到 note/原文；不许跨事件拼接出新事实 |
| 关系层（谁和谁、什么未完成） | 允许跨事件归纳，但必须能指出依据的事件 id |
| 语气层（当时多难受、现在怎么想） | 允许演化；这是“温度”，不追求保真 |

### 第 3 步：共激活边

记录“哪些事件被一起组装过、后来被用上了”。同一组合反复出现到阈值（沿用重放那套证据思路），
自动长一条 `相关` 边，`source=co-recall`，按同样的规则衰减和剪枝。**不新建说法层，不改 note。**

- 改哪：`consolidate/replay.py` 或新的 `co_activation.py`；graph 边加 source。
- 失败模式：自己强化自己；用阈值 + 衰减 + 只允许结构边挡。
- 回滚：删 `source=co-recall` 的边即可。

## 8 验证设计

用已有两场实聊（38 轮、32 轮）和 10/10 的跨会话题做对照。

- **三组条件**：A 现状；B 加原子索引、仍单事件重建；C 原子索引 + 跨事件组装。
- **题分三类**：10 道跨事件（“上次说到一半的那件事，后来呢”）、10 道单事件、10 道**根本没发生过的**。
- **量什么**：事实正确率；溯源诚实度（该说“这段是查到的”时说不说）；人读“像不像她”1–5；
  token 与延迟；负样本上的编造率。
- **判据**：
  - B ≈ A → 瓶颈不在粒度，直接跳 C 或停；
  - C 跨事件变好但负样本编造上升 → 先加溯源门禁；
  - C 在人读上赢不了 A → 这个方向对当前场景不值得复杂化。

按项目自己的标准：效果由人读判定，量具只报警，不追 LoCoMo 的分。

## 9 未决

1. **什么算一个原子？** 命题，还是“一口气能说完、拆开就变味”的最小单位？
   我倾向后者：命题会把对话压成事实，恰好压掉要的东西。
2. **哪些记忆不许打碎？** 判据不是长度，是“拆开后意义是否改变”：一次争吵、一个沉默、
   一个玩笑、一次告别，整体才是意义。
3. **保真契约怎么分层？** 见 §7 第 2 步；事实/关系/语气三层混在一起，就没法判断一次重建是“演化”还是“编造”。
4. **什么时候触发跨事件重建？** 默认不触发；只在复合/时间线索、候选分差小、新旧冲突、
   或模型显式要求时。
5. **原子由谁写？** 我建议“派生、标明、可重建”，不要让原子冒充她的 note；note 永远是权威副本。
