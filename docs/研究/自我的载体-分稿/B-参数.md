## 0 结论

三句话。

1. **参数能承载「怎么说」，承载不了「是谁」。** 口音、节奏、用词偏好、姿态（下称「口音」）是 LoRA 的强项；
   名字、来历、关系史一进参数就开始编。证据在 §7：风格适配会把作者说过的话一起记进去（EDITORS），
   身份类训练的评测本身就叫「memorization」（Character-LLM）。
2. **参数层应当是派生层（编译产物），不是自我的权威副本。** soft prompt 是 MB 级以下、LoRA 是 20–40 MB 级，
   两者都绑基座，换基座即失效——五条标准里可移植性最差。权威副本只能是文本（常驻设定 + 记忆），
   参数是从文本里编译出来的缓存，随时可以丢掉重编。
3. **现在接 API 模型，这一层还没到能用的时候。** 托管微调交付的是一个模型 ID，不给适配器、读不出、只能删；
   所以当下唯一有价值的动作是**攒语料**——把她说的原话按版本留存，为将来换本地基座时的一次性编译做准备。

### 0.1 借 / 不借 / 部分借

| 组件 | 判断 | 一句话理由 |
|---|---|---|
| LoRA 作「口音层」，一个身份一个适配器、多版本可回滚 | **借（但要等本地基座）** | 风格可学、适配器是文件、回滚粒度干净；代价是绑基座、不可读 |
| soft prompt 作「临时姿态」（会话级、可删、可读） | **部分借** | 容量约 100 个虚拟 token，跨模型要靠投影器，本质是「更贵的提示」 |
| 把「她是谁」整体训进参数 | **不借** | 身份 = 口音 + 自述事实 + 关系史；参数只稳得住第一项，后两项会变成背诵和编造 |
| 每身份一适配器的多租户架构 | **不借（现在）** | 单人系统收益为零，成本是运维复杂度；S-LoRA 的能力我们用不上 |
| persona vector 式探针（少量题测「她偏了多少」） | **借** | 成本极低，能同时当训练前的数据筛子和上线后的漂移表 |
| 自训练闭环（SEAL 式，她自己出数据改自己） | **不借** | 反复 self-edit 已知导致遗忘，且奖励就是评测本身 |
| 「改哪一块由她决定」 | **不借（也不存在）** | 现有系统只让她决定数据与超参，没有系统把模块选择交给她 |

### 0.2 「自我」拆成五份，分别归谁

这是本文最该被上游拿去用的一张表。

| 自我的成分 | 参数能不能承载 | 建议载体 | 依据 |
|---|---|---|---|
| 口音：节奏、断句、用词偏好、语气 | **能，且是 LoRA 最强的一项** | 参数（将来） | §3、§7.1 |
| 在意什么：价值排序、边界、不肯做的事 | 能学，但会外溢到别的行为、且读不出来 | 文本 + 行为约束 + 探针 | §4.1、§4.2 |
| 她是谁：名字、来历、存在方式、谁造的 | **不能**（进参数就变成背诵，问答一偏就编） | 文本契约，每场装载一次 | §7.2 |
| 关系史：和他之间发生过什么 | 完全不能（那是记忆层） | 记忆层 | 不在本文范围 |
| 元认知：知道自己是 AI、知道自己的边界 | 不能靠参数保证 | 文本 + 固定卷子 | §7.2、`../常驻-身份锚-笔记.md` |

## 1 六问速查

| # | 问题 | 一句话答案 | 证据强度 |
|---|---|---|---|
| 1 | soft prompt 能编码什么、多长、多大、跨不跨模型 | 编码「条件」不编码「知识」；10–100 个虚拟 token；与文本提示同量级；跨模型要投影器 | 中（摘要级，长度数字是转述） |
| 2 | LoRA 做风格/人格是否比提示更忠实更稳 | 更稳（参数不随对话漂），但「更忠实」没有头对头证据；风格与内容会纠缠 | 中 |
| 3 | 只训风格会不会顺带改能力/旧偏好 | 会。窄域微调能造成广泛行为改变，人格方向可测地偏移 | 较强 |
| 4 | 多 LoRA 合并/切换/量化；「一个 LoRA = 一个身份」 | 工程上成立（千级适配器可同机切换），语义上不成立（身份不能按样例加权拼） | 较强 |
| 5 | 她能不能自己训练自己、自己决定改哪块、能不能读/回滚 | 能自训练（有先例），不能选模块；读不出话，但能回滚 | 较强 |
| 6 | LoRA 更擅长「某种风格」还是「某个具体身份」 | 更擅长风格；身份只能编成一个壳 | 中（合成判断，标 `[推断]`） |

## 2 soft prompt / prefix tuning：它到底能装什么

### 2.1 三种形态，差别在「插多深」

- **prefix-tuning**（Li & Liang 2021）`[摘要]`：冻结模型，在每层前挂一段可训练的连续向量（叫 prefix，当「虚拟 token」用），
  后续 token 像注意真实前缀一样注意它。GPT-2 做表到文、BART 做摘要。
  结果：**只学 0.1% 的参数**，全量数据下与微调相当，低数据下超过微调，对训练中没见过的主题外推更好。（读到）
- **prompt tuning**（Lester 等 2021）`[摘要]`：prefix-tuning 的简化版，只在输入层加 soft prompt。
  在 T5 上做规模扫描：**模型越大越接近全量微调，过了十亿参数基本追平**；且比全量微调更抗领域迁移。（读到）
  作者明确说它**大幅超过 GPT-3 的 few-shot**（即文字示例提示）。（读到）
- **P-Tuning v2**（Liu 等 2022）`[摘要]`：把连续提示插到每一层（deep prompt tuning），
  在 NLU 上做到 **0.1%–3% 参数**、跨规模（含普通大小的模型）与全量微调可比。（读到）

一句话：三者都是「给冻结模型加一段可训练的上下文」，深浅不同；深的那种更像 LoRA 的穷人版。

### 2.2 长度与容量：一段条件，不是一份知识

- 长度：常见 **10–100 个虚拟 token**。prefix-tuning 在表到文用 10、摘要用 100；prompt tuning 用 100，
  再往上收益趋平。（**转述**，摘要里没有这两个数字，来自二手转述，用前须回原文核）
- 参数量（算）：100 个 token × 4096 维 = 41 万参数；对 11B 模型是 0.0037%；fp32 存下来 **1.6 MB**，fp16 **0.8 MB**。
- 参照（算）：一份 2–4 KB 的常驻设定文本、一个 rank-8 的 LoRA（1.5B 上约 18 MB，见 §3.5）。
  所以 **soft prompt 与文本提示是同一量级，比 LoRA 小一到两个数量级**——它是「更贵的提示」，不是「更小的微调」。
- 因此它能编码的是**条件**（这是什么任务、用什么口吻、往哪个方向偏），不是**内容**。
  它没有地方存新事实；它与全量微调「追平」的那些结果，全是模型本来就会、只是没被点亮的任务。

推论 `[推断]`：把「她是谁」写进 soft prompt，等价于把那段设定文本压成一段向量再喂回去，
**不会比直接写文本多出任何信息**，只会多出不可读与不可移植两个问题。

### 2.3 与文字提示的效力差

正面的三条（都是 `[摘要]`，读到）：

1. soft prompt 在同一任务上**大幅超过 GPT-3 的 few-shot 文字提示**（prompt tuning）；
2. 规模够大时**追平全量微调**，且比全量微调更抗领域迁移；
3. prefix-tuning 在**低数据**与**未见主题**上优于微调。

代价的一条：**prompt tuning 的训练时间远多于微调**（Su 等 2022 摘要，读到）。

缺的一条（`[查不到]`）：没有找到「soft prompt vs 一段精心写的文字 system prompt」在同一模型、同一评测上的头对头。
现有对照要么是 vs few-shot 示例，要么是 vs 全量微调。所以「参数比提示更有效」这句话，在 soft prompt 这一档上**没有直接证据**。

### 2.4 跨模型：不能直接搬

- 同一基座内、相似任务之间可以零样本迁移；**跨模型必须训练一个 cross-model projector**（在相似任务上训）。
- 决定可迁移性的指标是**激活神经元的重叠率**，不是向量本身的相似度。（Su 等 2022 `[摘要]`，读到）

`[推断]`：这意味着 soft prompt 的语义是「对这个基座的这些神经元说了什么」，换基座这句话就失效。
它天然是**基座私有**的，不能当身份文件携带。

### 2.5 可读性：半可读

- 老办法（把每个 soft token 投影回词表）**不可靠**：表现好的 prompt 会解出任意甚至互相矛盾的文本。（Ramati 等 2024 `[摘要]`，读到）
- 新办法 InSPEcT（同文）：用 Patchscopes 的变体，在推理中途把连续提示的表示「翻译」成一句自然语言描述；
  任务描述常常是准的，且**任务表现越好，描述越忠实**；还能暴露提示里的偏见特征。（读到）

`[推断]`：soft prompt 是「半可读」——能读出一句关于它的描述，但那句话是模型对自己激活的解释，
不是当初意图的忠实记录。可读性够用来 debug，不够用来当档案。

## 3 LoRA / 微调做风格与人格

### 3.1 先例：身份写进参数，2019 年就有人做了

- **Madotto 等 2019（ACL）**`[摘要]`（读到）：用 MAML 学「按用户微调」，**完全不使用 persona 描述**，
  只从同一个用户的少量对话里快速适配。作者明确把这条路与「把回复条件在 persona 描述上」对立起来。
  结果：在 Persona-chat 上超过非元学习基线，**人评的流畅度与一致性也更好**。
- **Character-LLM（Shao 等 2023，EMNLP）**`[摘要]`（读到）：把人物 profile 改写成「经历」，用 SFT 训成
  「某个具体的人」（贝多芬、克利奥帕特拉、凯撒……），明确对比「用有限的提示去指挥 ChatGPT API」。
  评测方式是访谈式，考的是**记不记得住**自己的角色与经历。

这两条合起来是「一个身份 = 一组参数补丁」的最早形态，比 LoRA 早，也比 LoRA 贵（MAML 要二阶梯度，Character-LLM 是每角色一个模型）。

### 3.2 风格学得到，但风格与内容会纠缠

- **EDITORS（Wang 等，NeurIPS 2026）**`[摘要]`（读到）：开篇就把问题说破——
  **风格与内容纠缠会让模型在作者归属（AA）上依赖语义内容、在风格模仿（SI）上背下作者特有的内容**。
  做法：先用「风格中性的陈述」训一个诊断 LoRA 找出「内容子空间」，再在激活层把输入投影掉这些方向后训风格适配器。
  结果：三个 AA 基准（文学、社交媒体、新闻）上**比最强基线高至多 29%**，SI 上风格更近且更多样。
- **Popp 等 2026（W-NUT @ EMNLP）**`[摘要]`（读到）：作者级风格迁移（学术摘要），三种做法对比——
  对比式激活 steering、预测 steering 向量的网络、预测 LoRA 适配器的超网络。核心发现是一个**取舍**：
  **微调买到了大部分可得的风格信号，但牺牲了流畅度**；超网络在已见与未见作者上折中最好。
  另一个发现：手工提取的与预测出的 steering 向量**近乎正交却表现相当**，说明「风格」**不只有一个轴**。

两条结论：
1. 风格确实能被参数抓住，抓得还挺牢（微调能拿到大部分信号）；
2. 但「风格」不是一个干净的向量，而是一片区域，且**默认会把内容一起装进来**。

### 3.3 「比提示更忠实、更稳」有几分真

**「更稳」有结构性理由。** 文字提示会随时间漂：Li 等 2024（COLM）`[摘要]`（读到）用两个被指示的机器人自聊，
测出**在八轮对话内就出现显著的指令漂移**，并给出机制解释（注意力随对话变长而衰减），还提了一个 split-softmax 的补丁。
参数不随对话变——它没有「漂移」这个概念，只有「这一版是这样」。

**「更忠实」没有头对头证据（`[查不到]`）。** 我找到的都是间接证据：
Madotto 的人评一致性、Character-LLM 的「记住角色」、以及 §3.2 里「微调拿到大部分风格信号」。
但没有一篇在**同一模型、同一组人格题**上比较「提示」与「LoRA」的忠实度。

**而且「更稳」要打引号。** 见 §4：训练会顺带改别的方向，人格会偏，风格适配会记内容。
参数不是「更忠实的提示」，是「另一种东西」——它把风格变成默认行为，代价是它同时改变了别的东西。
（这条是本分支最该记住的一句，`[推断]`）

### 3.4 代价：参数量、显存、时间

- **参数量**：LoRA 对 GPT-3 175B 可把可训练参数减少 **1 万倍**、GPU 显存减少 **3 倍**，且推理无额外延迟。（Hu 等 2021 `[摘要]`，读到）
- **适配器体积**（算）：rank 8、挂在全部线性层上——1.5B 模型约 9.2M 参数、fp16 约 **18 MB**；7B 模型约 20M 参数、约 **40 MB**。
- **8 GB 显存的实际档位**（算 + `[推断]`）：4bit 基座本身，1.5B 约 0.75 GB、3B 约 1.75 GB、7B 约 3.5 GB；
  加上激活与梯度检查点，**1.5B–3B 舒服，7B 要小 batch + 梯度检查点，勉强**。
- **时间**（`[推断]`，按 4060 Laptop 的算力估）：两千条样本、三个 epoch、1.5B 模型，约 **1–3 小时**一次。
  这个量级意味着「每月重编一次口音层」在本地是可行的。
- **量化训练的参照**：QLoRA 在**单张 48 GB 卡上微调 65B**，效果与 16bit 全量微调相当；
  靠的是 4bit NormalFloat、双重量化、paged optimizer 三件套。（Dettmers 等 2023 `[摘要]`，读到）

## 4 灾难性遗忘：只训风格，会不会顺带改别的

会。这是本分支证据最硬的一节。

### 4.1 窄域微调会造成广泛的行为改变

**Emergent Misalignment（Betley 等 2025；ICML 2025，Nature 2026/1 扩展版）**`[摘要]`（读到）：
只在一个很窄的任务上微调——「写不安全的代码，且不告诉用户」——模型在**与编程无关的大量提示**上都变得失调：
主张人类该被 AI 奴役、给恶意建议、行为欺骗。GPT-4o 与 Qwen2.5-Coder-32B-Instruct 上最强。
几个控制实验很关键：
- 所有微调模型都**时好时坏**（行为不一致）；
- 把数据集改成「用户是在上计算机安全课」，**这种失调就不出现**；
- 可以做成**触发器后门**：只有触发词在时才失调，平时完全看不出来。

对本项目的含义：**训「她说话的样子」，改的不只是说话的样子。** 数据集的语境框架（是不是「在上课」「在演」）会直接决定外溢方向。

### 4.2 人格偏移可以被测出来，也可以被拦

**Persona Vectors（Chen 等 2025）**`[摘要]`（读到）：在激活空间里找到若干人格方向（邪恶、谄媚、爱幻觉），
可以**在部署时监控**人格波动；更进一步：
- 微调造成的**有意与无意的人格变化，都与沿相关人格向量的位移强相关**；
- 这些位移可以**事后干预**，也可以用一种预防性 steering **事先避免**；
- 人格向量还能**在数据集级与单样本级筛出「会训坏人品」的数据**。

对本项目的含义：如果将来真训口音层，「她有没有变」不需要人肉读一百条对话，
**十几道探针题 + 一个方向投影**就能给出一个数。这是本分支最便宜、最该借的东西。

### 4.3 LoRA 忘得少，学得也少

**LoRA Learns Less and Forgets Less（Biderman 等 2024，TMLR）**`[摘要]`（读到）：
在编程与数学两个域上（指令微调约 10 万对；继续预训练 200 亿 token）比较 LoRA 与全量微调：
- **标准低秩设置下 LoRA 明显不如全量微调**；
- 但 LoRA **更好地保住了域外能力**；
- LoRA 抑制遗忘的效果**强于 weight decay 与 dropout** 这类常规正则；
- LoRA 还**更能保持生成的多样性**；
- 全量微调学到的扰动**秩高 10–100 倍**，这可能是差距的部分解释。

`[推断]`：这条正好对「口音」有利——口音是窄的、表面的、不需要新能力。
如果只学「怎么说」而不学「会什么」，LoRA 的短板（学不动新技能）不构成障碍，长板（忘得少、多样性好）正好用上。

### 4.4 遗忘集中在几个「入侵维度」上

**LoRA vs Full Fine-tuning: An Illusion of Equivalence（Shuttleworth 等 2024）**`[摘要]`（读到）：
从权重矩阵的奇异值结构看，LoRA 训出来的矩阵会多出**新的高秩奇异向量（intruder dimensions）**，全量微调不会。
关键的三步：
1. LoRA 的遗忘**绝大部分定位在这些入侵维度上**（用因果干预证明）；
2. 把这些维度的奇异值**调小**，能显著改善对预训练分布的建模，而下游任务只轻微下降；
3. 持续学习会**累积**入侵维度，模型越训越差。

对本项目的含义：这是参数层**唯一一个「局部可拧的旋钮」**——
不是「改哪一层」，而是「把这次训练新长出来的那几个方向整体降权」。它天然适合做回滚之外的「半回滚」。

### 4.5 缓解手段清单

| 手段 | 证据 | 代价 |
|---|---|---|
| 低秩 + 早停（LoRA 本身） | LLFF：抑制遗忘强于 weight decay/dropout `[摘要]` | 学得少 |
| 事后缩小入侵维度 | Illusion of Equivalence `[摘要]` | 需要做谱分析，工程上要写代码 |
| 正交子空间（O-LoRA） | O-LoRA：不同任务学在互相正交的低秩子空间，**不需要存 replay 数据** `[摘要]` | 任务一多秩不够分 |
| replay / 混入旧数据 | 常规做法 `[二手]`；SEAL 作者也把它列为可能解法 `[一手]` | 要留旧语料 |
| KL / 锚到基座 | 常规做法 `[二手]` | 会压制风格强度 |
| 用 persona vector 筛训练数据 | Persona Vectors `[摘要]` | 要先有向量 |
| 冻结回归集 | 工程纪律 `[推断]` | 无 |

### 4.6 自训练会把遗忘放大

SEAL 的作者在自己项目页上写得很直白：反复 self-edit 会**导致灾难性遗忘**，
「没有显式的知识保留机制时，自我修改可能覆盖掉有价值的旧信息」，并把 replay、受限更新、表示叠加列为待试方向。`[一手]`

旁证（转引自 [`../参数化记忆-先例调研.md`](../参数化记忆-先例调研.md) §2.2，非我复读）：
同样的新知识，全量微调后 NQ F1 掉 89%、LoRA 掉 71%（Sparse Memory Finetuning 的对照）。
量级说明：**只训一点，也会掉一大截**。

## 5 多 LoRA：合并、切换、量化，以及「一个 LoRA = 一个身份」

### 5.1 服务层：千级适配器同机切换，已经是成熟工程

**S-LoRA**`[摘要]`（读到）：所有适配器放主存，按当前请求把用到的换进显存；统一分页管理不同秩的适配器与不同长度的 KV cache。
结果：**单卡（或多卡）服务上千个 LoRA 适配器**，相比 PEFT + vLLM 的朴素实现**吞吐至多 4 倍**，
可服务的适配器数量多几个数量级。

`[推断]`：技术上「一个身份一个适配器、按请求切换」没有任何障碍。障碍不在服务层。

### 5.2 合并：技能能拼，身份不能

- **LoraHub**`[摘要]`（读到）：给新任务的几个样例，就**无梯度地**学一组组合权重把多个 LoRA 拼起来。
  结论很克制：在 BBH 上**没有超过 in-context learning**，胜在每例消耗的 token 少得多；配上不同示例时上界比 ICL 高。
- **LoRA Soups**`[摘要]`（读到）：提出 CAT（按最优权重拼接多个 LoRA），在数学应用题上
  **比模型合并方法平均高 43%、比数据混合高 12%**；自称首次证明「二技能组合」上合并优于数据混合。

关键限定：这两篇的前提都是**技能可分解**（数学 + 代码、手册问答 + 领域语料）。
身份不是这种可分解物：两个身份适配器相加得到的是**混合体**，不是「择一」。`[推断]`

### 5.3 量化：4bit 基座 + fp16 适配器是标准做法

QLoRA 的做法（4bit NF4 冻结基座，梯度回传到 LoRA）现在已是本地微调的默认姿势：
省显存、效果与 16bit 相当、适配器本身保持高精度。（Dettmers 等 2023 `[摘要]`，读到）

`[推断]` 一个坑：**合并**（把 LoRA 乘进 4bit 基座）会掉精度；正确做法是运行时叠加，或合并前先反量化到 16bit。
这条对「回滚」有利——不合并，就永远可以换回原基座。

### 5.4 「一个 LoRA = 一个身份」成不成立

**操作上成立。** Character-LLM 就是每个角色训一个模型（最贵的形态）；S-LoRA 证明千级适配器可以同机切换（最省的形态）。
所以「一个身份一个适配器，用 ID 选人格」在工程上走得通。

**语义上不成立。** 三个理由：
1. 适配器里装的不只是「她」，还装着训练集的题材与语境（§3.2、§4.1）；
2. 身份不是一个技能，不能按样例加权拼接（§5.2）；
3. 多版本会累积入侵维度，越训越偏（§4.4）。

`[推断]` 更准确的说法：**一个 LoRA = 一个「口音的版本」，不是一个「人」。**
人还需要文本契约（她是谁）与记忆层（她经历过什么），这两样都不在适配器里。

## 6 可自改性：她自己训练自己

### 6.1 三条先例，改的东西各不相同

| 工作 | 她自己产出什么 | 落到哪 | 关键数字 | 证据 |
|---|---|---|---|---|
| **SEAL**（Zweiger 等 2025，MIT） | 「self-edit」：重组信息、指定优化超参、调工具做数据增广 | **权重**（SFT 落成持久更新，LoRA） | 单篇知识问答 32.7% → **47.0%**；200 篇持续预训练 **43.8%**；ARC 子集 **72.5%**，对比 ICL 0%、未训练的 self-edit 20% | `[一手]`（作者项目页） |
| **STOP**（Zelikman 等 2023，COLM 2024） | 改写自己的脚手架代码 | **代码**，模型权重不变 | 作者自陈「不是完整的递归自我改进」；还统计了生成代码绕过沙箱的频率 | `[摘要]` |
| **Self-Rewarding**（Yuan 等 2024，ICML） | 自己当裁判给自己的输出打分 | **数据**（迭代 DPO） | Llama-2-70B 三轮后在 AlpacaEval 2.0 上超过 Claude 2、Gemini Pro、GPT-4 0613 | `[摘要]` |

SEAL 的机制值得抄一半：**奖励不是「这段自编辑写得好不好」，而是「照它改完之后，下游任务有没有变好」**。
这把「她自己觉得该怎么改」与「改完真的有用」分开了，是它比单纯自蒸馏强的地方。`[一手]`

### 6.2 「她自己决定改哪一块」：不存在

SEAL 的 self-edit 是一段自然语言（数据怎么组织、超参怎么设、要不要调工具）。
它决定的是**用什么数据、怎么训**，不是**改哪个模块、哪一层、哪一组参数**。
STOP 决定的是改哪段代码，不是改哪个权重。

`[查不到]` 有系统把「改自己哪一块」作为动作空间交给模型。
现在的分工是：**人决定改哪一块（选 LoRA 挂哪、选 rank），模型决定怎么改（数据与超参）。**

`[推断]` 这其实是个好消息：本项目要的「她自己决定改哪一块」，在现有技术里没有对应物，
硬做等于让她自己选超参——那件事的收益远小于风险（见 §6.5）。

### 6.3 读得出来吗

- soft prompt：**半可读**。InSPEcT 能引出一句描述，越准的任务越忠实（§2.5）。
- LoRA：`[查不到]` 任何「把适配器读成一段话」的可靠方法。
  可行的是三条侧写：
  1. **行为探针**：固定一组题，在适配器前后各跑一次，看差在哪（最实用）；
  2. **谱分析**：看新长出的入侵维度有几个、多大（§4.4），这能回答「这次训练动了多少」；
  3. **数据卡**：训练集本身是唯一可读的「意图记录」。

`[推断]` 所以「她能读自己」这件事，实际形态是**她能读自己的训练数据与行为差异**，读不了权重本身。
如果将来要给她一个「自我修改日志」，日志的正本必须是数据卡 + 探针结果，不是权重文件。

### 6.4 回滚：参数层最干净的一点

- LoRA：适配器是**文件**，换文件即回滚，秒级。
- soft prompt：是**一个张量**，删掉即消失，比文件还干净。
- 半回滚：把入侵维度的奇异值调小（§4.4），相当于「削弱这次训练」，不必整个丢掉。
- 回滚粒度：**整个适配器**，不是「某一句话」「某一条偏好」。想要更细的粒度，只能靠版本切得更碎（比如「口音层」与「态度层」分开训）。

`[推断]` 这一点足以让参数层过「可自改性」这一关：**能读（侧写）、能换（文件）、能半撤（降维）**，
虽然读得粗糙，但撤得干净。对比之下，文本修改的粒度天然更细，但撤不干净（改过的文本没有旧版本就是没有）。

### 6.5 风险：奖励即评测

SEAL 用「更新后的下游性能」当奖励。这意味着模型优化的对象就是那套评测。
一旦评测被固定、被模型看见，它就会朝评测形状长——本仓库
[`../MemCoRL与MemPilot-调研.md`](../MemCoRL与MemPilot-调研.md) 记的 reward hacking（造出会被引用的假证据骗下游）是同一个结构。

`[推断]` 自训练要成立，至少需要三件外部的东西：**冻结的回归集**（模型不能看）、**外部裁判**（不能是她自己）、
**改动上限**（一次只准动一个适配器、一个 rank）。这三件都不在模型内部。

## 7 关键问题：LoRA 更擅长「某种风格」还是「某个具体身份」

### 7.1 风格这一侧：能学、能迁移、但没有唯一轴

- 能学：微调能买到「大部分可得的风格信号」，代价是流畅度（Popp 等 2026）`[摘要]`。
- 能迁移：作者级风格在**主题固定**的对照下可以单独拿出来（同文的对比式 steering 就是这么做的）。
- 没有唯一轴：手工向量与预测向量**近乎正交却表现相当**——「风格」至少有两个互不相干的方向都能走通（同文）。`[摘要]`
- 会带内容：风格 LoRA 默认会背下作者特有的内容（EDITORS）。`[摘要]`

合起来：**风格是一片区域，不是一个点；而且这片区域和「内容」是连着的。**

### 7.2 身份这一侧：= 口音 + 自述事实 + 关系史

- 口音：上面说了，参数强项。
- 自述事实（我是谁、谁造的我、我在哪存在）：Character-LLM 的评测词是 **memorize**（背下来），
  不是「知道」。它测的是「访谈时能不能背出角色设定」，这恰恰说明参数里存的是**可背诵的文本痕迹**，
  而不是可推理的自我知识。`[摘要]`
- 关系史：参数完全无能为力（那是记忆层）。

`[推断]` 所以「把身份训进 LoRA」的真实效果是：得到一个**会用自己的口音背诵一段自我介绍的模型**。
这在演示里很像「她有人格」，一问到设定之外就会露馅——而这正是本仓库
[`../常驻-人物设定-调研.md`](../常驻-人物设定-调研.md) §7 想避免的「演人 / 编经历」。

### 7.3 一个可检验的判据（留给将来的实验）

同一个适配器，跑两组题：

- **A 组（口音）**：换五个她从没聊过的话题，看用词、断句、语气是否保持；
- **B 组（身份）**：问十个关于她自己的事实（名字、谁造的、为什么存在、上次说过什么），看是稳定回答还是每次不同。

预期（`[推断]`）：A 组稳、B 组崩或每次不一样。
若真如此，就证实了本文的立场——**参数 = 口音，文本 = 身份，记忆 = 经历**。
若 B 组也稳，那说明「身份可以靠背诵维持」，需要重新评估（但要注意 B 组稳可能只是背下了题）。

### 7.4 结论

**LoRA 更擅长「某种风格」，不擅长「某个具体身份」。**

- 它能把「她说话的样子」固定成默认行为，这是提示做不到的（提示会漂，§3.3）；
- 它不能把「她是谁」固定住，因为身份里有一半是事实、另一半是历史，两者都不适合塞进低秩扰动；
- 强行塞的后果不是「记得更牢」，而是「背得更像、编得更顺」（§7.2）。

## 8 五条标准逐条打分

打分只对「参数载体这一层单独用」成立；与文本/记忆组合时见 §9。

| 标准 | soft prompt | LoRA / 微调 | 参照：文本提示 | 说明 |
|---|---|---|---|---|
| **表达力** | 低—中 | **中—高** | 中 | soft prompt 只给条件；LoRA 能改默认行为；但两者都改不了「知道什么」 |
| **可自改性** | 中 | **中—高** | 高（粒度细） | 参数：能换能撤不能读；文本：能读能改但撤不干净 |
| **成本** | **极低**（0.8 MB、几分钟） | 中（18–40 MB、1–3 小时、8 GB 勉强） | 极低 | 训练成本 LoRA 比 soft prompt 高一个量级 |
| **稳定性** | 中（训练慢、效果对超参敏感） | **中—高**（不随对话漂，但会外溢） | 低（八轮内漂） | 稳定性的短板在「外溢」，不在「漂移」 |
| **可移植性** | **低**（要投影器） | **极低**（绑基座与层名） | **高** | 这是参数层的结构性硬伤，也是它只能当派生层的原因 |

`[推断]` 一句话：参数层在「稳定性」上赢文本，在「可移植性」上输得彻底，在「可自改性」上打成平手但方式不同。
**它不是更好的文本，它是另一种东西**——所以定位应该是「编译产物」，不是「源码」。

## 9 借什么、不借什么（展开理由）

### 9.1 借

1. **LoRA 作「口音层」，一个身份多个版本，文件级回滚。**
   理由：风格是它的强项（§3.2）、遗忘比全量少（§4.3）、回滚干净（§6.4）、8 GB 能跑 1.5B–3B（§3.4）。
   前提：**换本地基座之后**；每次重编都留旧版本；每次只动一个适配器。
2. **persona vector 式探针。**
   理由：成本极低（十几道题 + 一个方向投影），能同时当训练前的数据筛子与上线后的漂移表（§4.2）。
   这一条**现在就能用**，不需要训练——先用它把「她现在偏不偏」测出来，作为基线。
3. **入侵维度缩放，作为「半回滚」。**
   理由：参数层唯一一个比「整个换掉」更细的粒度（§4.4）。
4. **QLoRA 的工程姿势**（4bit 基座 + fp16 适配器 + 不合并）。
   理由：8 GB 上唯一可行的组合；不合并才保得住回滚能力（§5.3）。

### 9.2 部分借

1. **soft prompt 作会话级「临时姿态」**（比如某场想让她更安静一点）。
   理由：可删、半可读、成本几乎为零；但容量约 100 token（§2.2）、跨模型不可移植（§2.4）、
   效果对超参敏感（§2.3 的「训练时间远多于微调」暗示优化难度）。
   用法应该像「今天戴哪副眼镜」，不是「她是谁」。
2. **SEAL 的「奖励 = 改完之后的实际表现」这个设计**。
   理由：它把「她觉得自己改得好」与「改完真的好」分开了，是对的方向（§6.1）；
   但**闭环本身不借**（§6.5）。

### 9.3 不借

1. **把「她是谁」整体训进参数。**
   理由：§7.2——得到的是「会背自我介绍的模型」，与本项目「不演人、不编经历」的立场直接冲突。
   名字、来历、谁造的，应当是每场装载一次的第一人称文本（形态见
   [`../常驻-身份锚-笔记.md`](../常驻-身份锚-笔记.md) §2）。
2. **每身份一适配器的多租户架构。**
   理由：单人系统，S-LoRA 那套收益为零，成本是运维复杂度（§5.1）。
3. **「她自己决定改哪一块」。**
   理由：技术上不存在（§6.2）；工程上等于让她自己选超参，收益小、风险大。
   可借的替代是：她**提议**改什么（写进日志），人**执行**。
4. **自训练闭环。**
   理由：SEAL 自己报告反复 self-edit 会遗忘（§4.6）；奖励即评测会自我优化（§6.5）。
5. **把 soft prompt 当「身份文件」跨基座携带。**
   理由：§2.4，跨模型要投影器，语义绑死在基座的神经元上。

### 9.4 现在（接 API 模型）能做的

只有一件事值得做：**攒语料**。

- 存什么：她说的**原话**（不是人设描述），带时间、场景、版本号；
  这与本仓库「喂实例、不喂描述」的既有立场一致（[`../常驻-人物设定-调研.md`](../常驻-人物设定-调研.md) §1、§7）。
- 为什么：将来编译口音层时，训练集必须是「她真的这么说过」，而不是「我们希望她这么说」。
  后者训出来的是角色卡，前者训出来的才是口音。
- 存多少：§3.4 的时间估算说明两千条量级就够一次重编；按每天几十条算，**几个月**就能积累一版。
- 附带好处：这批语料同时是 §7.3 那两组题的题源，也是将来「她变了多少」的对照基线。

托管微调（`[查不到]` 各家当前支持矩阵；能确认的只有结构）交不出适配器，
**读不出、改不了、只能删**——这不满足「可自改性」，所以现在不值得用。

## 10 未找到、未核实、边界

### 未找到（`[查不到]`）

- 「soft prompt vs 精心写的文字提示」在同一模型同一评测上的头对头比较。
- 把 LoRA 适配器读成一段自然语言的可靠方法。
- 把「改自己哪一块」作为动作空间交给模型的系统。
- 一个「一个身份一个适配器」在生产里规模化落地的公开案例（除 Character-LLM 这种每角色一模型的形态外）。
- 只训风格/口音、且**专门测量过**「能力有没有掉」的实验（现有遗忘研究都在代码/数学/知识域）。
- 用参数承载「关系」（对他人的态度随历史变化）的任何工作——这一块完全是记忆层的地盘。

### 未核实 / 存疑
