## ② "读法随经历变"的先例

**结论：有先例，按同构程度分三档。**

### 第一档：检索函数本身从经历中学习（★最接近你要的东西）

- **HAGE: Harnessing Agentic Memory via RL-Driven Weighted Graph Evolution** `[论文]` — [ar5iv 全文](https://ar5iv.labs.arxiv.org/html/2605.09942)、[代码 (MVP)](https://github.com/FredJiang0324/HAGE_MVPReview)
  记忆是**带可训练边特征向量的多重关系图**。每条边 `e_ij ∈ R^4`（temporal / semantic / causal / entity 四个维度）。给定 query，LLM 分类出关系意图，`QueryRouter`（MLP）**动态调制边特征的对应维度**，得到结构权重 `w_ij(q) = softplus(MLP([q; ẽ_ij]))`；最终转移分 `S(n_j|n_i,q) = λ·cos(v_j,q) + (1-λ)·w_ij(q)`，再 softmax 成遍历策略。
  **关键点**：边特征与 router 用 **REINFORCE（下游任务奖励）联合优化**，作者明确称之为 "co-evolutionary dynamic"——"Features on successful trajectories are reinforced, while those on unsuccessful paths are suppressed"。为防止特征漂移过远，加了 **anchor 正则** `L_anchor = λ‖e_ij − e_ij^(0)‖²`，并用**非对称学习率** `η_edge < η_router`。
  这是目前找到的**唯一**把"读旧记忆的度量/权重由经历学出来"的完整框架。注意它是训练期学的（离线），不是在线边聊边学。

- **AURORA: Neuro-Symbolic Continual Indexing for Evolving RAG Systems** `[论文]` — [ACL 2026 Findings](https://aclanthology.org/2026.findings-acl.495/)
  "**decouples discrete index structure from continuous metric representations**, enabling efficient adaptation of neural components while preserving index topology"。即：**索引拓扑冻结，度量表示持续学习**（当成 few-shot continual learning 问题）。另有轻量 **Bayesian routing policy** 做 uncertainty 估计，在"自适应神经索引"和"静态 fallback"之间动态路由以平衡 stability/plasticity（这就是工程上"既要学、又别学坏"的现成答案）。数字：新主题 Recall@10 +26.9%，适配 28 ms vs 全量重训 5.1 s。

- **Navigation-Informed Embeddings (NIE): Dense-Retriever Adaptation from Agent Search Traces** `[论文]` — [arXiv 2608.15956](https://arxiv.org/abs/2608.15956)
  用 agent 自己的**检索轨迹**（query / 路径文档 / 停止文档）**直接微调 dense retriever**（BGE encoder），无需新标注、无需合成 query、无需 LLM 判分。`NIE-Stop` 把"停下来的那篇"当软正例；`NIE-Path` 把前序路径文档当 hard comparison 并施加几何衰减的顺序约束。Recall@20 从 72.2 → 78.0，长路径 46.7 → 55.4；打乱顺序的对照组掉 3.2 分（说明信号确实来自顺序结构）。
  ⚠️ 这条同时是**"检索历史反哺"的正面先例**——与你第 4 条纪律直接冲突，见 ④ 的讨论。

### 第二档：改变图结构 / 元数据 / 重嵌入（部分同构）

- **A-Mem 的 memory evolution** `[源码]` — [memory_system.py](https://github.com/agiresearch/A-mem/blob/main/agentic_memory/memory_system.py)
  最直接。新 note 进来 → 找 5 近邻 → LLM 输出 `{"actions": ["strengthen","update_neighbor"], "new_context_neighborhood": [...], "new_tags_neighborhood": [...]}` → **旧 note 的 `context` 和 `tags` 被覆写**，`evolution_history` 记录下来。
  ⚠️ 但必须精确说：ChromaDB 的 document 是 `note.content`，**embedding 只由 content 计算**，所以改 context/tags **不改变向量检索排序**；它改变的是**被检索到之后注入 prompt 的文本**、以及 tags/links 的可用性。所以它是"读法的表层变化"，不是度量变化。
- **mem0 的 `linked_memory_ids` + entity 降权** `[源码]` — 新记忆给旧记忆挂链接；检索时用 `1/(1+0.001(n-1)²)` 压低"关联爆炸"的 hub。属**结构/权重变化**。
- **Graphiti 双时态失效** `[二手]` — 旧事实被 invalidate 而非改写，"what was true at any point in time" 使**同一条旧记忆在不同时点被读成不同有效性**。这是时间维度的读法变化。
- **AIRI 的 dreaming/subconscious agent 设计** `[二手]` — 原话：处理每条新记忆并"**modifying various scores of past memories based on recent experiences**"；作者自评"from a re-indexing perspective, dreaming agents and subconscious agents are like rebuilding indexes"。**未实现**，但方向和你的 ★ 完全一致，可作为设计引用。
- **MemOS 的 `mem_organize` / reorganize 任务** `[二手]` — 调度器里有重组/合并任务类型；具体打分实现未读。

### 第三档：只是"记录增删改"（不算读法变化）

- **mem0 v3 的 ADD-only 抽取** `[源码]` — `ADDITIVE_EXTRACTION_PROMPT` 明说是 "Your sole operation is ADD"。（注意：`DEFAULT_UPDATE_MEMORY_PROMPT` 的 ADD/UPDATE/DELETE/NONE 四操作仍留在 `mem0/configs/prompts.py` 里，属可配置的自定义 prompt 路径。）纯追加 = 旧记忆读法不变。
- **Open-LLM-VTuber BasicMemoryAgent / Letta** — 全量或委外，无读法变化。
- **SillyTavern Memory / World Info** — stateless，显式无变化。

### 相关综述（用于定位，非机制）

- **From Storage to Experience: A Survey on the Evolution of LLM Agent Memory Mechanisms** `[论文]` — [ACL 2026 Findings](https://aclanthology.org/2026.findings-acl.2069/)（pp. 41622–41652）。三阶段框架 **Storage（轨迹保存）→ Reflection（轨迹精炼）→ Experience（轨迹抽象）**，并点出 Experience 阶段的两大机制：**proactive exploration** 与 **cross-trajectory abstraction**。可直接用作你设计文档的坐标系。
- "Agent Memory Research in 2026: A Data-Driven Survey and Extended Taxonomy" `[二手/论文 PDF]` — [Zenodo](https://zenodo.org/records/20780690)

### ★ 明确"未找到"

- **没有找到**任何**公开可用的工程系统**（AI VTuber / 陪伴类 / 开源 memory 库）实现了"在线地用经历改变**已存记忆的相似度度量**"。最接近的是 HAGE（训练期、图边权重）和 AURORA（索引拓扑冻结 + 度量持续学习），二者都不是"边聊边改度量"的陪伴场景实现。
- 搜索词：`learned metric for memory retrieval agent`、`memory evolution graph neural network agent`、`continual learning retriever dense retrieval`、`test-time adaptation retrieval`、`memory reconsolidation computational model`、`self-organizing memory agent`、`记忆 强化 检索 度量学习 智能体`、`记忆演化 图`。
- 边界判断：**"度量学习适配用户"在推荐系统里是成熟常规做法；在 LLM 陪伴记忆系统里，目前只有"元数据改写 / 链接 / 边权 / 失效"这类表结构层面的先例，没有"改读取器本体"的公开工程先例。**

### 论文 / 学习型做法

- **Proactive Agent: Shifting LLM Agents from Reactive Responses to Active Assistance** `[论文]`（ICLR 2025）— [ar5iv](https://ar5iv.labs.arxiv.org/html/2410.12361)、[ICLR 页](https://proceedings.iclr.cc/paper_files/paper/2025/hash/75c37811e830bf029584b1c6fac17726-Abstract-Conference.html)、[代码 thunlp/ProactiveAgent](https://github.com/thunlp/ProactiveAgent)
  目标函数就是"**最大化用户接受率** `max_θ E[R_t]`"，其中 `R_t` 由人类标注的 accept/reject 给出（2 类判断，含"reject all"= 用户此刻不需要帮助）。用 1,760 条人工标注训了一个**reward model 模拟人类判断**（F1 91.8%），再用它造 **ProactiveBench（6,790 events）** 微调 agent。
  **最重要的负面结论（直接回答"怎么防止定时问候变骚扰"）**：所有未微调模型（含 GPT-4o / Claude-3.5-Sonnet）**在 false-alarm 场景表现极差**（GPT-4o-mini false-alarm 64.73%，即一大半主动开口是多余的），它们"tend to accept arbitrary help, even if it is very abstract or meaningless"。指标明确用 **False-Alarm ↓** 与 **Missed-Need** 并列，而不是只看"帮到了没有"。
- **When Should the Agent Speak? A Survey of Intervention Timing for Always-On AI Assistants** `[论文]`（TMLR 投稿）— [论文页](https://tmlr.infinite-conf.org/paper_pages/b0yKEdAXEr.html)、[OpenReview](https://openreview.net/forum?id=b0yKEdAXEr)、[awesome-proactive-agents](https://github.com/tao-hpu/awesome-proactive-agents)
  把整个领域收敛到**一条判定规则**："intervene **iff** the expected benefit of acting exceeds the expected cost of interrupting"，并分五层组织：signals / decision / action / memory / evaluation。核心论断：1999–2017 的 interruptibility 文献把"打断代价"形式化得很好但没有 actor；2024–2026 的 proactive-agent 浪潮有 actor 但**只在碎片里重新发现代价项**（false-alarm pricing、cognitive load、social violation、compute），无人统一。作者主张 **evaluation 是卡点**：移动健康领域靠在决策点上随机化+有验证的近端指标来在线学时机，开放世界助手没有对应 outcome，因此 RL 目标缺一个公认 reward。→ 对工程的含义：**"打断代价"必须显式进目标函数，不能靠 prompt 里写"别太频繁"。**
- **ProactBench: Beyond What The User Asked For** `[论文]` — [PDF](https://export.arxiv.org/pdf/2605.09228)（PDF 未能解析，仅凭检索到的片段：多 agent 设定）。**标记为未核实**。
- 中文综述（主动对话系统：方法、评估与挑战）`[论文 PDF]` — [中国图象图形学报](http://www.cjig.cn/rc-pub/front/front-article/download/169440906/lowqualitypdf/…)。仅检索到，未读正文，**标记未核实**。

### 产品层的"频率预算"清单（非技术实现，但可作设计检查表）`[二手]`

- [AI陪伴为什么不能一直主动找你：主动消息也需要"频率预算"](https://www.tuikebi.com/archives/6687) 给出 12 条：每日总上限（低/中/高三档）、提醒类与关系类**优先级不同**、同类消息**去重**、考虑距上次互动时长、**不回复就自动降频**（"不能用更强情绪去逼用户回来"）、静默时段最高优先级、触发理由要足够强（"你说今天要面试"是强理由，"三小时没打开 App"不是）、**临时事件会过期**、不同关系模式不同预算、可按类别关闭、**打开率不是唯一指标**（看关通知/卸载/投诉/长期留存）、目标是"像有理由的出现"。

## ④ 防回音室 / 防复利污染的先例

你的两条原则分别对照：

### P1「检索历史不得反哺权重 / 检索函数」

- **有先例，但主要来自推荐系统：**
  - **Breaking Feedback Loops in Recommender Systems with Causal Inference（CAFL）** `[论文]` — [ACM TORS](https://dl.acm.org/doi/10.1145/3728372)、[arXiv 2207.01616 全文](https://ar5iv.labs.arxiv.org/html/2207.01616)。用**反事实/倾向性加权**修正闭环偏差，理论结论明确指向"为避免反馈环，每一步的推荐应按 …"（对已暴露项的过度自信做修正）。这是"检索/推荐历史不反哺"最成熟的数学化先例。
- **LLM 记忆侧的现状：**
  - **mem0**：我读了 `score_and_rank`，打分 = semantic + BM25 + entity_boost，**没有任何来自历史检索结果的项**；也没有更新 embedding 模型或度量的代码路径。→ **事实上的 P1 合规**（不是刻意设计，是不存在该机制）。
  - **SillyTavern World Info**：官方文档明说 stateless 评估，结果只取决于当前上下文。→ P1 合规（显式）。
  - **SillyTavern Vector Storage**：检索分数只来自 embedding 距离；检索到的 chunk 被插入上下文，**但它插入的是 user 消息、并且不会作为新条目被重新向量化**（向量化的输入只有 chat 消息 / 附件 / Data Bank 文件）。→ 需注意：**它插入的文本会进入后续 chat 消息流，下一次向量化时会被当作 chat 消息收录**——这是一条真实的"检索结果 → 索引"的回流通道，虽然需要经过一轮对话。这是我能给出的最具体的一个反例/风险点。
  - **Generative Agents**：`metadata["access"] = now` 写回，间接影响下次 recency 排序 → **弱反哺，但被承认且被限制**（只动时间戳，不动 poignancy、不动 embedding）。
- **反向证据（必须并列写出）**：**NIE** `[论文]` [arXiv 2608.15956](https://arxiv.org/abs/2608.15956) **明确主张用检索轨迹去微调 retriever**，并在独立 benchmark 上拿到提升。→ 结论不是"不能反哺"，而是"**反哺必须是被审计的、离线的、有对照实验的**（NIE 做了打乱顺序的 control，掉 3.2 分）"，而不是在线悄悄累积。
- **P1 的"未找到"**：没有找到任何公开文档/论文**明确以"禁止检索历史反哺"为设计原则**并给出形式化保证的 LLM 记忆系统。检索词：`retrieval feedback loop contamination RAG`、`self-consuming loop model collapse`、`echo chamber recommender feedback loop`、`dirty RAG`、`RAG self-reinforcement`。

### P2「外部材料只改强度、不改内容」

- **有，且是很干净的先例：**
  - **MemoryBank** `[源码]` — [forget_memory.py](https://github.com/zhongwanjun/MemoryBank-SiliconFriend/blob/main/memory_bank/memory_retrieval/forget_memory.py)。`update_memory_when_searched()` 对命中的记忆只做两件事：`memory_strength += 1`、`last_recall_date = cur_date`。**内容字段完全不碰**。强度通过 `exp(-t/(5S))` 影响后续留存/排序。这是"只改强度不改内容"的直接工程实现。
  - **mem0 v3 ADD-only** `[源码]` — [prompts.py `ADDITIVE_EXTRACTION_PROMPT`](https://github.com/mem0ai/mem0/blob/main/mem0/configs/prompts.py)：新信息一律 ADD，对旧记忆只加 `linked_memory_ids` 链接。**旧记忆的 content 不可被新对话覆写**（这是他们 v3 相对 v2 四操作模式的架构选择；相关讨论见 [issue #4956 "ADD-only extraction in v3 may surface stale/contradictory facts for time-sensitive attributes"](https://github.com/mem0ai/mem0/issues/4956)）。⚠️ 代价：陈旧/矛盾事实不会被清理——**你要求的"不改内容"必然换来"矛盾长期共存"**，这是需要你决策的取舍。
  - **Graphiti** `[二手]` — [README](https://github.com/getzep/graphiti/blob/main/README.md)：矛盾时"invalidated — **not deleted**"，双时间轴保留"what was true at any point in time"。这是"改写"的第三种答案：**不改内容、不删内容，只改其有效期**。对你的池+余弦读取器，这对应"给记忆加 valid_from/valid_to，过期条目不进候选但可被时间查询取回"。
- **另有明确的"污染"文献可引用：**
  - **Retrieval Collapses When AI Pollutes the Web** `[论文]`（ACM Web Conference 2026）— [ar5iv 全文](https://ar5iv.labs.arxiv.org/html/2602.16136)、[ACM](https://dl.acm.org/doi/10.1145/3774904.3792955)。讲 AI 生成内容污染语料后检索如何崩塌——正是"复利污染"的外部证据。
  - **When and How Human Curation Backfires: Preference Alignment under Multi-Model Self-Consuming Loop** `[论文]`（ICML 2026）— [poster 页](https://icml.cc/virtual/2026/poster/65872)
  - **Stabilizing Self-Consuming Diffusion Models with Latent Space Filtering** `[论文]` — [AAAI](https://ojs.aaai.org/index.php/AAAI/article/view/39067)（自消耗循环的稳定化手段：在潜在空间做过滤，可类比"检索结果进池前先过滤"）
  - **A survey on causal inference for recommendation** `[论文]` — [The Innovation](https://www.cell.com/the-innovation/fulltext/S2666-6758(24)00028-6)（把 IPS 估计器扩展到打破反馈环）
  - **P2 的"未找到"**：**没有找到**以"ingested 外部材料只允许改强度"为原则的**规范/标准或论文形式化的不变量**。这个提法在公开文献里没有名字。最接近的命名是：Graphiti 的 *fact invalidation*、MemoryBank 的 *memory strength*、mem0 的 *additive extraction*。搜索词：`external material only change strength not content memory`、`memory salience update without content rewrite`、`append-only memory agent`。

### A. 可直接抄的**算法**（不引依赖，纯 Python/数学）

| 来源 | 可复用的东西 | 许可 |

| [mem0 `mem0/utils/scoring.py`](https://github.com/mem0ai/mem0/blob/main/mem0/utils/scoring.py) | ① **BM25 的 sigmoid 归一化**：`1/(1+exp(-steepness*(raw-midpoint)))`，midpoint/steepness 按 query 词数自适应（≤3→(5.0,0.7) … >15→(12.0,0.5)）② **加性混合 + 自适应分母**：`combined = min((semantic+bm25+entity)/max_possible, 1.0)`，阈值只卡 semantic ③ **hub 抑制**：`1.0/(1.0+0.001*(n-1)^2)`。全是纯 math，零依赖。 | Apache-2.0 |
| [MemoryBank `forgetting_curve`](https://github.com/zhongwanjun/MemoryBank-SiliconFriend/blob/main/memory_bank/memory_retrieval/forget_memory.py) | `exp(-t/(5*S))` 留存概率 + 命中即 `S += 1`。**这正好就是你要的"外部/使用只改强度不改内容"**，可直接移植为池里每个条目的 `strength` 字段。 | 见仓库 |

| [A-Mem `process_memory`](https://github.com/agiresearch/A-mem/blob/main/agentic_memory/memory_system.py) | **evolution 的 prompt 结构与 JSON schema**（`should_evolve` / `actions` / `suggested_connections` / `new_context_neighborhood` / `new_tags_neighborhood`），是现成的"新经历改写旧记忆读法"接口定义。 | 见仓库 |

| 组件 | 依赖 | 说明 |
|---|---|---|
