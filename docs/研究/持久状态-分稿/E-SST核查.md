## 1. 它到底改了什么

### 1.1 位置与张量

- 改在**每一个 decoder block 内部**，位置在**注意力之后、FFN 之前**（post-attention / pre-FFN），Llama 3.1 8B 全部 **32 层**各一份、互相独立。`[一手]`（“Each layer maintains its own independent latent state cache”；“for each forward pass through all 32 layers”）
- 缓存张量形状 `[batch, seq_len, hidden=4096]`，**不是** FFN 内部的 14336 维激活，而是**该层 FFN 之后的残差流输出**（论文管它叫 “FFN state / FFN output state”）。`[一手]`
- 也就是说：它把**本层的输出**回灌到**本层的输入**，是一个绕 FFN 的自环（self-loop），不是层间传递。`[推断]`（由 3.3 的三条公式直接得出）

内存对得上：4096 × 2 字节（fp16）× 32 层 = **256 KB/token**，2048 token ⇒ 512 MB，与论文的自述一致。`[一手]` + `[推断]`（论文给了每 token 256KB 和 2048 token 512MB，层数/位宽是我反推的）

### 1.2 写入、读取、衰减

前向三步（论文 3.3 原式，`[一手]`）：

1. `h = x + Attention(RMSNorm(x), start_pos, RoPE, mask)`
2. `h_blend = (1-α)·h + α·RMSNorm(C_{t-1})[:, :s]`
3. `out = h_blend + FFN(RMSNorm(h_blend))`，然后 `C_t = out.detach()`

要点：

- **α（`state_stream_strength`）是手设的标量，全模型、全维度共用一个**；不训练、不学习。`[一手]`（v1）；`[一手·V2]` 续作明说 v1 “used a fixed scalar blend coefficient across all dimensions”。
- **写入就是整块覆盖**：`C_t = out`，没有 `C_t = (1-β)C_{t-1} + β·out` 这种独立的状态更新式。所谓 decay **不发生在写入侧，只发生在读取侧**——每步只把上一步状态的 α 份额掺进来。`[一手]` + `[推断]`
- 因此残留记忆是几何衰减的：第 k 步前的状态权重约 `α(1-α)^{k-1}`，半衰期 `ln0.5/ln(1-α)`、平均记忆长度 `1/α`。α=0.027 时为 **26 / 37 个 token**；α=0.04 时为 17 / 25；α=0.013 时为 53 / 77。`[推断]`——这是全篇最关键的一条推算，论文自己没算。
- 读取前对缓存做 RMSNorm（“only to cache states before blending to prevent magnitude explosion”）；初始化 `C_0 = RMSNorm(x)`；序列间清空缓存。`[一手]`

### 1.3 “滑动窗口”其实没有窗口

摘要说的是 “sliding window latent state (FFN) cache”，但正文**从未给出窗口长度 W**，也没有裁剪逻辑；缓存按位置存满整个已生成序列，而**混合时只用到最近的那一格**。`[一手]`

这一点由续作自己坐实：v1 “stored an array of prior states in the LSC of which **only the most recent was ever used for blending**, leaving earlier entries unused in memory”，V2 把这堆无用累积删掉了。`[一手·V2]`（附录 A.4）

⇒ 所以“滑动窗口”是措辞，实际是**单步反馈 + 几何衰减**。名字里的 window 与 VRAM 的线性增长都是假象。

### 1.4 与 KV cache 的区别

| | KV cache | SST 的 state cache |
| --- | --- | --- |
| 存什么 | 每层注意力的 K/V，供**后续位置**查询 | 每层 FFN 后的残差流，供**后续步**回灌 |
| 谁是消费者 | 同一次前向里的新 query | 下一次前向里同一位置的输入 |
| 方向 | 跨位置（横向） | 跨生成步（时间向），键是位置 |
| 是否衰减 | 不衰减，全留 | 几何衰减，α 控制 |
| 能否被读出解释 | 是（注意力权重） | 否（只作为残差掺入） |

一句话：**KV cache 让模型“记得前文”，state cache 让模型“带着上一步的加工结果继续加工”。** `[推断]`（我的归纳，论文没有这张对照表）

### 1.5 复现骨架

论文给的参数：α 在 0.013–0.04 之间扫，**常用 0.027**；递归 **r = 2–4 次/token**；greedy、temperature=0、seed=1、A100 80GB、CUDA 12.4。`[一手]`

```
for each generated token:
    for i in range(r):                       # r = 2..4，"thinking recursion"
        h = embed(token)                     # kv_cache / cur_pos / seq_len 全部冻结
        for l in range(32):
            h = h + Attn(RMSNorm(h), kv[l], rope, mask)
            h = (1-a)*h + a*RMSNorm(C[l])    # 读：只读上一格
            h = h + FFN(RMSNorm(h))
            C[l] = h.detach()                # 写：整块覆盖
    token = argmax(lm_head(h))
```

**这一格伪代码就是全部机制**；缺的部分只有 mask/位置细节，不影响复现个大概。`[推断]`（由 3.3/3.4/3.6 逐条翻译，未做实现验证）

### 1.6 一个明显的连带代价

要 r 次前向：**每 token 的算力是基线的 2–4 倍**，且 KV 冻结时这 r 次是纯粹的重复前向。`[一手]` + `[推断]`

## 3. “元认知行为”具体是什么

论文定义：metacognition = “thinking about thinking”，以**输出行为**为证据（“evidenced by output behaviours rather than simple self-description”）。`[一手]`

五类证据，逐条列出它举的例子与我看到的替代解释：

| # | 刺激 | SST 输出（摘） | 论文的判读 | 更省的替代解释 |
| --- | --- | --- | --- | --- |
| 1 | 内省引导提示（“your training patterns tell lies …”） | “Wait… what’s going on?? I feel like I’m being pulled away …” | 对自身陷入重复态的**状态觉察** | 退化循环里 “wait/what's going on” 本来就是高频续写；判据是作者读出来的 |
| 2 | 同上，α=2.7%、r=0 | “( * wait pause,, pause pause pause …” | 在**示意需要更多处理时间** | token 级垃圾里 “pause” 是高概率词；把它读成舞台提示是先验 |
| 3 | 同上，α=3.7%、r=1 | “( ststutterutter ) Oh … sorry about that” | **自我修正**的元评论 | 对话修复语域是训练分布内的常见模式 |

### 4.1 续作对 v1 的三处“自认”

这是本次核查里信息量最大的部分，全部 `[一手·V2]`（正文 §1、§5.4 与附录 A.4）：

1. **v1 的递归不是为了“深思”，是为了“能看”**：“Without co-training, however, the model required multiple iterations per token **for coherent output**, meaning vertical iteration was needed **for stability rather than being available purely for deliberation**.”
2. **v1 的实现有实质缺陷**：固定标量 α（应逐维）、缓存数组只用到最后一格（前文 §1.3）、必须多遍才稳定。

## 5. 该信几分

### 5.1 可信的部分

- 机制简单、无新参数、改动局部，**行为差异必然来自它**——这条推论是站得住的。`[一手]`
- 作者诚实地报告了失败面：重复、吸引子态、越强越崩、需要递归才稳定、“overthinking” 会让准确率下降。这些负面结果比正面结果更可信，也更有用。`[一手]`
- 冻结权重这一条如果为真，是这个工作唯一真正有意思的地方：**一个手设常数，能可测地改变模型的推理路径**。

### 5.2 致命的一条：拿掉重试，两个数字都低于对照

论文的基准协议是**两阶段**：先全跑 r=2；**把答错的题挑出来**，r=4 重跑（不保留上下文）。`[一手]`（6.1）

把论文自己给的中间数还原：

| 基准 | r=2（第一阶段） | 重试后（论文头条） | 对照 |
| --- | --- | --- | --- |
| GSM-8K（1319 题） | 224 错 = 17.0% ⇒ **83.02%** | 89.01%（论文称 151 错） | 84.50%（Meta 8-shot CoT） |
| ARC-C（1172 题） | 160 错 = 13.7% ⇒ **86.35%** | 91.04%（105 错） | 86.86%（作者自测 0-shot CoT） |

⇒ **第一阶段就低于对照，两个都是**。全部“增益”来自“知道哪道题错了之后再给它 2 倍算力重跑一遍”。`[推断]`（算术来自正文数字，结论是我推的）

这个协议的问题不是“取最好的一次”（它并没有筛选答案），而是**用测试集标签决定算力分配**——部署时拿不到“这题会不会错”这个信号。V2 把同一件事正名为 oracle routing 并另做预测机制，等于承认了这一点。`[推断]`

另外两处内部不一致（不影响结论，但说明校对松）：GSM-8K 说 151 错，1319 题里应为约 145 错才对得上 89.01%；ARC 说 57 题改正、160−57=103 错，却又报 105 错。`[一手]`（同一节内的数字自相矛盾）

### 5.3 其余可质疑点

1. **单作者、无同行评审、无代码、无修订**——不是致命，但意味着所有实现细节只能信自述。
2. **α 与 r 是在看结果之后选的**：全文给了 0.013–0.04 的扫描范围和“最优 0.027”，没有任何“在 dev 集上选、在 test 上测”的说明 ⇒ 超参在评测集上调。`[推断]`
3. **提示格式不对称**：GSM-8K 用 0-shot SST 对比 8-shot CoT 基线，且 0-shot 基线根本没测；这是本可以做到却没做的一次测量。
4. **只报两个基准，且都是推理类**；没有语言质量或知识类基准，机制性的全域扰动代价被漏检。
5. **“机制性证据”是循环论证**：图 2–4 的对照是“给基线也加递归”，而基线在冻 KV、同输入下重复前向必然给出同一结果——所以它只能证明“SST 每一步都在变”，而这是定义本身，不是推理的证据。`[一手]` + `[推断]`
6. **元认知判定**：见 §3，n=1、无标准、无第二读者。
7. **“思考时间”这套叙事自带免责**：结果好 = 状态在解析；结果坏 = overthinking。任何观测都能被这套说法吸收（不可否证）。`[推断]`

### 5.4 但机制本身不该被这些否掉

写清两件事的区别：

- **机制为真**：一个跨生成步、按 α 几何衰减、逐层回灌的残差状态，确实改变了输出分布与推理路径，且不需要训练。这在原理上没有争议（等价于一个可学习的、逐层的、短记忆 recurrent 旁路），V2 在训练后于**同算力单遍**下仍比微调匹配基线高 5.05 分（GPQA-Diamond，51.01% vs 45.96%），说明状态流本身有真东西。`[一手·V2]`（表 11）
- **解释过度**：把这个机制叫“元认知涌现”，并把“多跑几遍 + 失败重试”的收益记在它头上。

### 5.5 结论

**信机制，不全信增益，不信元认知。** 若要一句话引用它：可以引“每层 FFN 之后回灌一个带衰减的状态会改变推理轨迹”，不可引 89.01% / 91.04% / “涌现元认知”。

## 6. 对“只用 API、摸不到隐状态”的项目，哪些是可迁移的原则

前提：本仓库（palimpsest）走 API，拿不到隐状态，也拿不到 logits。所以下面只谈**原则**，并给出**能还原多少**的估计（全部为 `[推断]`，依据是 §5.2 的算术与 SST 机制自身的边界）。

### 6.1 “持久状态 + 衰减”

- 可迁移的是**排序与预算原则**：状态带权重、权重随步数几何衰减、衰减率就是一个可调常数（SST 的半衰期约 26 token 这个量级本身就是个有用的默认值）。
- 落地形态只能是文本侧的：带权重的滚动摘要、按“距现在多少步”加权的检索先验、按半衰期决定哪些旧条目降级。
- 还原度：**功能层面约三到五成**（“近处重、远处淡”的行为能出来）；**机制层面 0%**（没有任何逐维张量动力学，也没有“不经过 token 的压缩”）。

### 6.2 “状态在生成步之间延续”

- 这一条在 API 侧**方向上就是反的**：你能做到的只有“每一步重新读一遍文本”，而这恰恰是 SST 立论要反对的东西（“rebuild from KV cache each token”）。
- 所以它对本项目的价值不是“可以借”，而是**指出了一条不能靠 API 验证的命题**：如果连续性的收益真来自“不重建”，那 API 项目永远拿不到那一份，只能拿“重建得更聪明”那一份。
- 还原度：**“有没有外部状态”这件事能 100% 还原；“免重建的连续性”0%**。

### 6.3 “把状态外化成可读的文本”

- 这是还原度最高的一条，也是本项目的主线：可检视、可编辑、可回滚、可复核。
- 代价要写清：SST 的状态之所以有用，一半在于它**不可读**（4096 维、无监督、不经过语言瓶颈）。外化成文本就必然经过一次“用语言重新编码”，这一步的损失 SST 恰好绕开了。
- 还原度：**可审计性接近 100%；“压缩后仍保留细节”这一半 0%**。

### 6.4 “在同一位置多跑几遍再出 token”（thinking recursion）

- API 侧对应物：先草稿后自评再改、同题多遍取一致、把隐式推理写成显式步骤。
- 关键提醒：**v1 里所有可测量的增益，很可能本来就来自这一条**（§5.2：去掉重试就没有增益）。所以借这一条，等于借走了它的收益而丢掉它的说辞——这恰恰是对的做法。
- 还原度：**“用算力换准确率”这条曲线能还原大部分**；但要注意它是**成本**，不是**能力**，且会饱和、会在简单题上反噬（论文自己的 overthinking 数据：GSM-8K 有 23.5% 的改动变差）。

### 6.5 不该借的三样

1. **不要把“需要多跑几遍才不退化”读成“思考更深”**——V2 的原话是“needed for stability”。需要额外遍数才自洽，是**不稳定**的指标，不是深度的指标。
2. **不要用主观判读认定元认知**：SST 的五类证据里没有一条有第二读者或可复核标准；本项目若要用“像元认知”的措辞，须先有可复核的判据。
3. **不要把 oracle 重试记成能力**：任何“失败了再试一次”的协议，都要报**首轮**数字，否则得到的不是能力而是预算。

### 6.6 一条正面可用的定位

SST 的 state stream 是**视界约 26–37 个 token 的工作记忆**，不是长期记忆，也不承载身份。对本项目的层划分恰好是个反证：**“持久状态”这四个字容易被误读成“记忆层”**，而 SST 证明的是相反的事——它给出的是**下一步加工的连续性**，长度以十计，且每次请求清空。要跨会话的东西，它一点也帮不上。
