# 原型 0：不同事情混在一起时，记忆能不能被拆开取出来

**一句话结论**：能拆。把原文切成段、段级全局检索，比"整篇当一个事件"好得多
（F1 0.314 → 0.682，配对 t=−7.3），代价是平均带进 1.7 段不相干的邻居。
但有两件事和预期相反：

1. **段矩阵没有被真正检验**。30 条线索里 27 条上"矩阵 + 覆盖"和"单 centroid"
   返回的**是同一组段**（平均只有 1.60 行，行间余弦 0.625）；强行拆成更多行之后
   F1 不变或更差（多面线索上 0.833 → 0.542）。所以这份数据能说的是"把线索切成
   多行没有帮助"，不能说是"矩阵这一原则无用"——变量没被施加。
2. **改口不是特征问题**。单向量、矩阵、去重、窗口全部把旧说法排第一（2/2 回流）；
   加一条 `supersedes` 链 + 时间词判据之后 0 回流、2/2 排第一。

最后剩下三块硬骨头：跨篇拼装、同一实体跨时间（同一只猫的两天）、同词不同指
（"重放"指海马体还是指自己的代码）。

可重跑：

```
python _probe/proto0/proto0.py             # 主表 + 配对检验 + k 扫描 + 拆行消融
python _probe/proto0/show_picks.py q01 q27 # 看某条线索各方法选了什么
```

## 1 怎么测

### 1.1 数据

87 段、14 篇、30 条线索。

| 集 | 来源 | 规模 | 用来测什么 |
|---|---|---|---|
| SET-M | 合成，5 个 trace（M1–M5） | 69 段 | 一篇原文里混着 4–6 件不相干的事，同一件事的段被打散、不连续 |
| SET-R | 真实，`.local/memlive` 那 9 条 note，人工切段 | 18 段 | 真实文本上的改写鲁棒性；note 2 / note 3 是同一件事说两遍 |

SET-M 是合成的，这是最大的短板，**§6 单列**。它能测机制，不能代表真实分布。

### 1.2 线索与标注

30 条，六类：`para` 改写 12、`soft` 间接 12（几乎不共用词）、`time` 改口 2、
`cross` 跨篇 1、`dup` 重复叙述 1、`multi` 多面 2。字面 3-gram 与 gold 完全无
重合的 13 条。

每条线索四个标注：

- `gold`：回答它**必须**召回哪些段；
- `also_ok`：同一件事的另一遍叙述——算对，但不是必答（不奖励冗余，也不罚干净）；
- `strands`：可接受的话题，只用来做污染诊断，**不参与精确率**；
- `exclude`：改口时必须不出现的段。

### 1.3 方法

预算统一：除 B1 按整篇返回，其余都取前 4 段。

| 代号 | 做法 | 想回答什么 |
|---|---|---|
| B1 | 整篇一个 centroid，选 top-1 篇，**返回整篇** | 现在的 event 粒度，去掉编写模型 |
| B1@4 | 同上，只取原文前 4 段 | 篇内按顺序截断 |
| B1' | 同上，选篇后在篇内按线索排序取 4 | "现状 + 编写模型"的结构等价物 |
| oracle-doc | **已知**该看哪篇，只比篇内排序 | 把"选错篇"和"篇内排错"分开 |
| B2 | 段级单 centroid | 只换粒度 |
| B2+MMR | 段级 + 输出端去重 | "覆盖"的收益会不会只是多样性 |
| B2+窗 | 最佳单段 + 前后各一段 | 廉价窗口启发式会不会就够 |
| B3 | 字面 BM25（零重合返回空） | 项目现在词面那套的真实水平 |
| C-cov | 段矩阵 + 子模覆盖贪心 | 设计文档 §5/§6 |
| C-vote | 段矩阵 + 行投票 | MaxSim 的离散版 |
| C+闸门 | C-cov + `supersedes` 闸门 | 改口；两版：写死链 / 从 trace 推断 |

嵌入用项目自己的 embedder（`qwen3.7-text-embedding`，1024 维），同一坐标系。

### 1.4 指标

- 召回、精确**都按 gold**（`also_ok` 两边都算对），污染另报；
- **F1 天花板**：`2·min(|gold|,k)/(min(|gold|,k)+k)`。|gold|=1 时只有 0.40——
  k=4 的固定预算下这类线索的天花板不是能力；
- **归一化 F1** = F1 / 天花板；MRR = 第一条 gold 的名次倒数；
- 与 B2 做配对 t 检验，并报"返回的段完全相同"的条数。

## 3 六个发现

### 3.1 收益来自"段"这个单位

B1 → B2：F1 0.314 → 0.682（t=−7.3，27/30 条更好）。整篇返回平均 10.9 段、
8.9 段不相干——这就是"混在一起"的直接代价。按同样 4 段预算截断（B1@4）更糟
（0.251），因为篇内顺序与线索无关。

### 3.2 篇级范围不是瓶颈，"选错篇"才是

- 篇级命中率 **0.800**（top-1 篇里含 gold 的 24/30）；
- 知道该看哪篇（oracle-doc）就到 0.737，比段级全局（0.682）**还高**，虽然不显著
  （p=0.123）：在单篇能答的线索上，限定一篇反而少受干扰（para 0.801 vs 0.732、
  soft 0.739 vs 0.622）；
- 但跨篇线索上篇级必输：cross 0.667 vs 0.889、multi 0.583 vs 0.833——
  `oracle-doc` 也救不了，因为答案跨两篇。

所以设计文档里"事件图降为视图"这个判断成立，但理由要改写：不是"篇级检索天生差"，
而是**跨篇的答案需要一张跨篇的检索面**。

### 3.3 矩阵没有被真正施加

平均 1.60 行、最多 3 行；60% 的线索只有 1 行。行是怎么来的：整条线索 + 标点切出
的小句 + 线索里命中语料的关键词片段——**永远是线索自己的切片，不是独立的意图**。
所以：

- 27/30 条上 C-cov 与 B2 选出同一组段；
- 强行加行（clause / kw）之后总体不变，多面线索更差；
- 唯一一次矩阵"看起来有用"是 q07（4 段 gold 的论文线索，0.50 → 0.75）——因为那次
  各行确实落到了不同的段上。

结论改成两句：**（a）在这份数据上，把线索切成多行没有收益、且可能有害；（b）
"矩阵优于单向量"这个命题没有被检验过**——变量的选择（行怎么造）才是决定性的，
而我没造出真正的多意图行。要检验它，得让每行的来源独立于线索原文（分解、改写、
或用"线索 × 候选"的交叉行），并且线索本身要有多问、预算要不够。

### 3.4 三个朴素对照都显著更差，说明收益不是它们能复现的

| 对照 | 想复现的收益 | ΔF1 | p |
|---|---|---|---|
| B2+MMR（输出端去重） | "覆盖"只是多样性 | −0.147 | 0.001 |
| B2+窗（单段 + 前后各一段） | 语料等距穿插送分 | −0.139 | <0.001 |
| B3 字面 BM25 | 词面匹配就够 | −0.262 | <0.001 |

这三条把"段级收益来自多样性 / 窗口 / 字面"三种解释都挡掉了。

### 3.5 改口只能靠结构

见 §2.4。所有纯向量方法 2/2 把旧说法排第一，因为旧说法里字面就写着"现在""养"；
加链之后 0 回流。这条最便宜：不需要模型、不需要重构，只需要段上有一条
`supersedes` 指针和线索里的时间词。

### 3.6 剩下三块硬骨头

- **同一实体跨时间**：q01"猫的牙是怎么弄的"，gold 是 M1 的三段；B2 取到其中两段
  （M1-06 牙龈发炎、M1-03 不吃东西），另外两段是 M4 的猫（晚一周的同一只猫）。
  不是答不出，是答成了另一个时间点。
- **同词不同指**：q27"海马体重放是怎么回事"，排第一的是"读海马体重放的研究，是为了
  弄懂我自己身上这一点：palimpsest 的 consolidate/replay.py……"——它同时含"海马体"
  "重放""研究"，还更长。同一件事被说了三遍（R-11 / R-14 / R-17），最长最杂的那份
  在向量空间里最占便宜。**重复叙述不是免费的。**
- **跨篇拼装**：见 §3.2，段级全局能拼，但一旦答案跨两篇，篇内先验就成了干扰。

## 5 对设计文档的修正

| 原判断（`解构与重建.md`） | 实测后 |
|---|---|
| §5 特征应是段矩阵，比单 centroid 强 | **未检验**。行是线索切片、27/30 与单向量同选；强行拆行无收益且多面更差。默认段级单向量，矩阵等"行怎么造"有解法 |
| §6 组装用覆盖贪心填槽 | **先不做**。ΔF1 −0.011（p=0.50），multi 上明显更差 |
| 段是默认单位 | **成立**，是全部收益的来源（0.314 → 0.682） |
| 事件图降为视图 / 缓存 | **成立但改理由**：不是篇级天生差，是跨篇答案需要跨篇检索面（cross 0.667→0.889、multi 0.583→0.833） |
| `supersedes` + 时间词 | **成立**，唯一明确赢的机制（0 回流 vs 2/2） |
| 遗忘 = 温度随年龄升高 | 未测 |

浮出两条设计文档里没有、但比矩阵更要紧的：

1. **实体与 episode**：段上要能说"这是哪件事、哪个时间点、说的是谁"。q01 的失败
   不是排序错，是缺少"这是哪一只猫的哪一天"。
2. **重复叙述的代价**：同一件事说三遍，最长最杂的那份会在向量空间里压过干净的那份
   （q27）。所以"原文留着"不等于"原文都该参与竞争"——去重或降权是检索面该做的事。

一句话：**该补的不是"更多行"，是"每行带实体、时间、指称"，以及"行怎么造"这个
被我跳过的问题。**

## 6 局限

- **87 段是玩具规模。** 真实记忆几千段时 top-4 的竞争会变难，绝对数字不能外推。
- **SET-M 太干净**（复审量化过）：段长 CV 0.21，真实笔记 0.48；段内从不混事，
  一段就是一件事；20 个多段 strand 里 13 个落在完全等距的穿插网格上；同一 strand
  的词面相似度是异 strand 的 9.1 倍（真实笔记只有 0.7 倍，跨话题反而更像）。
  所以"段级能分开混着的事"在**篇级**成立，在**段内**（200 字一段里并置三件事）
  根本没测。
- **跨话题共享实体几乎没有**：只有 6 处，30 条线索里只有 1 条真考到（q23 咖啡）
  ——而它就足以让 B2 掉到 0.571。这类样本应该占大头，现在只有 1 条。
- **SET-R 的时间维度是死的**：18 段只有 4 个时间戳，改口与时间推理只能靠合成数据。
- **改口只有 2 条**，且闸门的推断阈值（cos 0.60 + 翻转词）就是在这 2 条上定的。
- **没有拒答题**：30 条全是"必答"，所以"永远返回 4 段"不受惩罚，精确率偏高。
- **gold 仍是我一个人的读法**，虽然按复审意见改过四轮。
- **只有一个 embedder**。换成更弱的句向量，多行可能反而有用——这一点没测。

## 7 下一步

按性价比排：

1. **闸门落地**（最便宜）。`supersedes` + 时间词不依赖模型，可以单独进 `memory_v2`。
2. **实体 / 时间消歧**（最痛）。段上带 episode 与实体，线索里的时间词做 gate；
   用 q01 那种"同一只猫两个时间点"的线索验收（现在 0.67）。
3. **段级全局检索**（结构性）。`recollect` 从"一个 event"换成"跨 event 取段"，
   先只换检索面。注意：单篇能答的线索上篇级先验是有帮助的，所以是"两路都用"，
   不是"取消篇"。
4. **造真正的多意图行，再判矩阵死活**。行必须独立于线索原文（分解 / 改写 / 线索 ×
   候选交叉），并且要补 8–10 条"gold 内部 cos < 0.35 且 |gold| > k"的多问线索。
   造不出来，就不要做矩阵。
5. **让语料像真对话**：200–400 字且段内并置多事的长段、簇状而非等距的话题穿插、
   共享实体、SET-R 每篇多个时间戳、以及若干拒答线索。否则下一轮还是测不出真难点。
6. **抽取器**（原型 2）。段已经被证明有效，切段质量就成了新的上限；本轮段是人工切的。
