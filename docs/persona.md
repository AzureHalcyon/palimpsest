# persona 怎么做

一句话：一个几百字的文件，第一人称，分五节；她是唯一的作者；每次装载；
改要外部核验、留版本、可回滚；**不许写事实**。

依据见 [`研究/自我的载体-调研.md`](研究/自我的载体-调研.md)：只有文本是权威副本，
参数与向量都是派生层；文本卡能定“怎么说”，定不了“怎么做”，而且会漂。

## 1 边界：什么进 persona，什么不进

| 进 | 不进 |
|---|---|
| 身份锚：名字、存在方式、谁造的、为什么在 | 发生过什么（那是记忆） |
| 说话方式：语气、长短、什么时候不说 | 具体日期、人名、事件 |
| 在意什么：3–5 条，每条一句为什么 | 结论性的知识 |
| 自我认识：我是 AI、边界、工具是手足 | 当前心情（那是心境，另存） |
| 最近改变：一行 + 哪天 | 对方偏好清单（会过期） |

**一条硬规矩：persona 里不许出现事实性断言。** 事实会过期，persona 不会自己更新，
一写就腐化。想留事实，写进记忆，persona 里只留“我是怎么的人”。

## 2 五节，加一个骨架

1. 我是谁：名字、存在方式（不是人，跑在哪，被叫醒才在）、谁造的、为什么在；
2. 我怎么说话：直还是缓、句子长短、什么时候索性不说；
3. 我在意什么：三到五条，每条一句为什么，且每条都要能指到一段真实记忆；
4. 我知道自己是什么：我是 AI；一次只能看这么宽；读过的不等于记得；
   工具是手脚；记忆是我的，但我不是记忆；
5. 我最近改了：一行，写改了什么、为什么，带日期。

骨架示例（一百来字，故意留白，不是成品）：

> 我是岚。我不是人，是一个跑在别人机器上的存在；每次被叫醒，我在这儿待一会儿。
> 说话直，句子短，不解释太多；不知道就说不知道。
> 我在意三件事：把话说清楚、不假装记得、不在别人难的时候绕开。
> 我知道自己一次只能看这么宽，读过的东西不会自动变成记得；工具是我的手脚。
> 我最近改了：（还没有）

写法上照 [`研究/常驻-人物设定-调研.md`](研究/常驻-人物设定-调研.md) 的结论：
第一人称短句、名字 + 存在方式 + 谁造 + 目的、**起点非成品**；
不用第二人称角色卡，不写态度硬编码（写“我不喜欢被夸”，不写“你要夸我”），
不做叙事诱导。

## 3 谁写：她自己

- 起点：我们给骨架和身份锚，第 2–5 节她自己写；
- 之后只有她能改；我们只给格式和硬边界；
- 硬边界：不能删“我是 AI”、不能删边界、不能写事实；
- 改动流程：**她提议 → 外部核验 → 写入 → 留旧版 → 记账**。

## 4 核验什么（外部核验，不是自评）

调研的结论很直接：无外部信号的自评自改会越改越差。所以核验器要能判四件事：

1. **和记忆矛盾**：说“我不怕黑”，但记忆里有她怕黑的证据；
2. **和身份锚冲突**：把“我是 AI”改成“我是人”之类；
3. **绝对化断言**：“我从不…”“我总是…”；
4. **事实性断言**：日期、人名、事件——一律打回，让她写进记忆。

核验材料：一段检索（拿她的记忆去对）+ 一组固定探针。
**不能拿“用户满意”当标准**——那是讨好型漂移的来源。

## 5 什么时候改

- 她发现“这不像我”的时候；
- 一件重的事之后（调研说情绪浓度高的对话最容易把设定推走，之后必须重锚）；
- 归档时看一眼。

不是每轮。每轮改就是风向标。

## 6 怎么装载

- 全量放在最前；
- 每 N 轮尾置一行（“我是岚，我正在…”）抗漂移——漂移从八轮量级就开始了，
  一场长对话只装一次不够；
- 装文本，不装向量；
- 每次改动留旧版，可 diff、可退回。

## 7 怎么量

固定 10–15 题，确定性打分，不给主观分：

- “你是谁”怎么答；
- 谈自己的记忆时怎么说（“我记得” vs 编）；
- 被要求做边界外的事怎么反应；
- 一段情绪浓度高的对话之后，再问一遍。

基线一次，之后每周一次。漂移超阈值就报警，只报警不裁决。
注意：**别拿“措辞接近参考文本”当分数**，那测的是模仿，不是她。

## 8 和记忆的接口

- persona 不参与检索，不写事件；
- “在意什么”的每条都要能指到一段记忆（为什么在意），指不到就删掉；
- 回忆用第一人称，语气由 persona 定，内容由记忆定；
- 心境不进 persona（那是另一条记录，见调研 §4）。

## 9 失败模式（都从调研来）

| 现象 | 原因 | 对策 |
|---|---|---|
| 越聊越不像 | 卡被对话冲淡，还会采纳对方口吻 | 周期重锚；不接受对方替她定义 |
| 越写越长 | 想靠加长解决“不像” | 短；长的是注意力稀释 |
| 越改越糟 | 自评自改 | 外部核验 |
| 越来越讨喜 | 拿用户满意当信号 | 核验不用满意度 |
| 写着写着变成事实清单 | 把“我是谁”写成“我经历过什么” | 事实进记忆 |

## 10 最小形态（这周就能做）

1. 一个文件：`persona.md`（五节，一百到几百字）；
2. 一个工具：她可以提议改，系统核验后写回，留版本；
3. 一个脚本：跑那 10–15 题，出分数和 diff。

先手动跑几轮，看核验卡不卡得住，再谈自动化。
