# 代码规范

> 管 `memory_v2/`。旧代码不回溯改。

## 位置与复用

- 新链路只在 `memory_v2/` 里写，不混进 `memory/`；
- 底座直接 import（模型调用、凭证、提示词文件），逻辑自己写；
- 不复制旧代码再改：看懂了重写。

## 分层

```
core/         配置、模型客户端、词项
store/        状态记录、事件图、回灌
read/         检索、展开、编写
consolidate/  重放与成边
chat/         工具与一轮对话
cli.py        命令入口
```

依赖只往下走：`chat -> read / consolidate -> store -> core`；同层之间不互相 import。
提示词是数据，放 `prompts/`，由 `core/prompts.py` 读。

## 命名

- 名字说明它是什么，不用 `a`、`b`、`tmp`、`data2`；
- 一个概念只用一个词：叫了“事件”就别再叫“节点”；
- 函数用动词开头（`parse_event_call`、`next_session_id`）；布尔用 `is_` / `has_`。

## 注释

- 代码能说清的不写；
- 只写“为什么”和“不能这么做”：约束、坑、代价；
- 修复留痕放 [`决策记录`](../docs/决策记录.md)。

## 死代码

- 没有调用方的，要么删掉，要么在定义上方写一行保留理由（谁会用、什么时候）；
  不许既不删也不说明；
- 拿不准就先留着加注释，别为了让文件“干净”删掉还要用的东西。

## 外观

- 不用 emoji，代码和界面都一样；
- 空行分组，一行一件事。

## 错误与落盘

- 能恢复的错误报给调用方，不静默吞掉；
- 落盘先写临时文件再 `os.replace`；追加写要 `flush` 和 `fsync`；
- 不为“别打断”假装成功。

## 测试

- 新功能带一个离线自检（假模型 / 假数据），不依赖网络；
- 自测只回答“这条链路还通不通”：不追条数和覆盖率，效果由人读判定；
- 临时目录用 `testsupport.tempdir()`（建在 `data/` 下），不用 `tempfile.mkdtemp`；
- 入口登记到 `check_all.py` 的 `ENTRIES`，本地和 CI 跑同一条命令；
- 交出去之前自己先跑一遍；
- 提交前要问。
